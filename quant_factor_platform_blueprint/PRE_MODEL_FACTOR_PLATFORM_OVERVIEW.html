4. 性能设计：快，但不再造第二个执行平台

Batch

因子块

按 date chunk × asset × factor block 处理，避免 10k 因子逐个 Python groupby。

Reuse

中间量复用

rank、valid mask、daily IC、quantile assignment、exposure matrix 在同次 request 内只算一次。

Parity

Reference / Fast

Pandas/NumPy/SciPy 做可审计参考；NumPy/Numba/Polars 做 production fast path。

刻意不做： 第一版不建立跨任务持久化 Artifact DAG、第二套 factor cache、distributed scheduler。只有实测证明重复计算是主要瓶颈时再升级。

5. Claude Code：多 Agent 并行，但先冻结接口

最危险的不是 Agent 少，而是 20 个 Agent 同时改 shared API。正确方式是“并行审计 → Contract Freeze → worktree 隔离开发 → 独立红队”。

Wave 0 · 只读审计

4 个 legacy miner + boundary/license/corpus/red-team 同时扫描服务器。

Wave 1 · Freeze

Lead Architect + Chief Integrator 冻结 schema、public API、file ownership。

Wave 2–4 · 开发

QE / FP / FO / FA 同时推进；Developer Agent 使用 worktree isolation。

独立 Audit

Math、Leakage、Performance、Boundary、Simplification、Extraction、License、Corpus Regression。

Agent Teams

若环境启用，可用在架构研究/跨库协调；否则主会话 + project subagents + worktrees 即可。不要依赖不存在的 project team config。

7. 本次明确不做什么

禁止重复建设

  • PIT / calendar / universe / snapshot
  • Data lake / COS/S3/DuckDB wrapper
  • Factor DSL / compiler / materialization
  • 通用 cache / DAG / Kafka 平台

禁止研究捷径

  • corr > 0.9 就删除
  • 一个万能 score
  • 全样本 fit preprocess
  • 每因子跑全部高级统计
  • 10 万因子全 pair O(K²)
  • 把“代码运行通过”当“研究验收通过”
