# 有界批量精确召回：实现合同

## 模块与入口

公开入口仍为 `incremental_assign`。`incremental_batch_recall.py` 负责有界批量准入、
查询准备和分块调度；`incremental_recall.py` 的 `scan_exact_member_winners` 负责
同一成员块在多个查询之间复用。原单查询扫描和小矩阵 LRU 路径保留。

新路径只用于没有可用 batch ANN、查询数至少为 2、成员矩阵估计超过缓存预算且
至少存在一个成员指纹的簇。预算不够或查询维度不一致时，使用原单查询路径。
ANN 查询失败仍采用原有逐查询精确回退，不额外预扫描所有 ANN 成员。

## 计算口径与同分规则

对有限、非零 embedding x，先以最大绝对值 a 缩放，再作 L2 归一化：

\[ u(x) = \frac{x/a}{\sqrt{\sum_j (x_j/a)^2}},\qquad a=\max_j |x_j|. \]

相似度为 \(s(q,m)=\sum_j u(q)_j u(m)_j\)。沿用逐成员行的 Float64
`einsum(..., optimize=False)`，不改成批量 GEMM；超出有限数值包络的结果拒绝。
成员按原顺序扫描，只有新分数严格大于当前分数才替换 winner：不加容差，精确
同分保留首个成员。全部成员块都校验，不因已找到高分 winner 而提前停止。

分数低于 `min_measure_floor` 标记 `MEASURED_LOW`，否则标记 `APPROXIMATE`。
这不是 QE 认证证据，不会由余弦相似度升级成 `CERTIFIED`。

## 工作区与复用范围

成员块最多 256 行，默认预留 4 MiB、按三份 Float64 数值数组估算。单行维度
超过此估算时仍按一行处理，这是原单查询合同的例外，不代表总 RSS 被限制。
查询每块最多 256 行，不构造 Q×M 相似度矩阵。

额外查询准备和 winner 状态的估算为
\(Q(3\cdot8D+128C)\) 字节，Q 为查询数、D 为维度、C 为有可用指纹的超大簇数。
默认准入上限为 32 MiB。归一化查询矩阵在主循环复用；同一成员块在一个查询块内
只转换、归一化一次。超过 256 个查询时按查询块处理，成员准备次数可为每个查询块
一次，而不是承诺整个任意大小请求只准备一次。以上不包括输入对象、审计输出和
任意第三方分配，不是总进程 RSS 保证。
