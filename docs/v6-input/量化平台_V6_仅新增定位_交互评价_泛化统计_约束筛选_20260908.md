## 1. 最重要的结论

下一阶段更重要的是确认“指标计算的对象”和“证据的统计单位”，而不是继续增加字母等级。当前新定位的风险可形成下面的错误链：风险面板均值被当因子中性、真正互补被当重复、缺失筛样本被当新增信息、复制因子让CI变窄，再由MMR缺分回退或不完整状态推进做选择。

这不证明整条生产链已经发生这些行为；它说明这些函数若用于准入/优化，其输入与证据范围必须收口。

## 3. 逐项修复要求

### X01 · 风格暴露与纯度没有真正使用待评估因子

**优先级：** P0  
**证据性质：** D/S：函数行为及指标含义冲突  
**源码：** [S01](https://github.com/18047533889/quant_projects/blob/2bac7209c00e302728b810513c91f5475ec6954f/quant_evaluator/metrics/exposure_evidence.py)  
**函数/边界：** `compute_style_exposure_evidence / compute_size_exposure / compute_purity_ratio / compute_exposure_evidence`

**与V5的差异。** V5要求风险评价与因子身份相绑定；本轮新增的是具体计算对象错误，不重复分派中性化或空门槛整改。

**已见行为。** ExposurePanel定义为证券级(T,N,K)风险解释变量。风格函数对该面板直接求均值；purity以各风格均值平方与面板方差计算。综合入口虽接收factor_values，但这些风格/纯度字段不使用它。同一个风险面板会给完全不同的待评因子同样结果。

**具体反例。** 风险size变量均值0、方差>0；令待评因子x=size。当前size_exposure=0、purity_ratio=1；但x实际上完全由size解释。P01验证此反例。

**怎么改：**
1. 区分SecurityExposurePanel、FactorLoadingSeries、PortfolioExposureSeries，优先扩展现有类型；不能把风险解释变量当已计算的因子暴露。
2. 信号暴露至少输入因子值、风险面板、当时有效mask、权重和时间/证券坐标；调用已有回归/相关内核输出逐日期×因子×风格的结果。
3. 组合暴露使用真实目标/持仓权重与风险面板，例如w^T Z；信号回归系数不能冒充组合风险。
4. 风格解释度可明确为含截距、同样本/同权重回归的R²；剩余方差比只在总方差>0且模型适用时定义。高维拟合、正则方法及负样本外R²必须另作解释，不盲目截成完美纯度。
5. 如仍保留风险面板均值/方差，改名为context统计，不进入某个因子的纯度/中性化通过证据。

**真实仓库验收：**
1. x=Z_size应显示高size解释度；与size正交的x结果应不同。
2. 仅换待评因子而保持风险面板不变，证据应跟随因子变化。
3. 把风险变量平移或换单位，规范化暴露/解释度应遵循已声明的不变性；常数因子不返回完美纯度。
4. 从公开评价到FA风险标签检查字段来源，防止正确新函数无人调用。

**历史制品处理。** 仅失效依赖错误风格/纯度定义的评价、标签和准入；若生产中根本未消费这些字段，保留范围证明，不宣称全库受影响。

**依赖。** 无额外单项依赖；遵循已有主合同。

### X02 · 替代性检测可能把明显互补的因子认作可替代

**优先级：** P0  
**证据性质：** D：判断分支与所声明关系相反  
**源码：** [S02](https://github.com/18047533889/quant_projects/blob/2bac7209c00e302728b810513c91f5475ec6954f/quant_evaluator/metrics/interactions/substitution.py)；[S03](https://github.com/18047533889/quant_projects/blob/2bac7209c00e302728b810513c91f5475ec6954f/quant_evaluator/metrics/interactions/complementarity.py)  
**函数/边界：** `detect_substitutable_factors / compute_substitution_effect`

**与V5的差异。** V5已区分冗余和增量。本轮新增对现有替代检测函数的具体反例。

**已见行为。** 替代评分为|IC组合|/max(|IC_A|,|IC_B|)，达到默认0.9便入可替代列表。没有接近1的上界，也没有执行docstring所称的高相关检查。组合改善越大，越容易被判为可替代。

**具体反例。** A与B正交，y=A+B，两个单独IC均约0.7071，组合IC约1，ratio≈1.4142，仍通过“替代”门。P02。

**怎么改：**
1. 用有类型关系证据分别表示近重复、可替换、互补、权衡、未知；相似性与效用差不得折成同一个单向ratio。
2. 复用QE共同样本配对比较：对冻结方向、冻结基准及组合配方计算净效用或IC差值；替代要满足用途相关的等价/非劣与可替代性条件。
3. 互补不是要求IC相加后超加性；相关系数不是可直接相加的收益贡献。组合权重、标准化和符号全部属于配方。
4. 批量检测只接候选pair清单和预算，避免在所有F上无条件双重循环；不再复制第三份IC和标准化数学。

**真实仓库验收：**
1. 正交互补反例不得被当作无增量近重复删除。
2. A与A同样本近等价；A与-A按冻结方向处理，不能用日后绝对值翻转掩盖关系。
3. 弱信号分母接近0时不输出巨大替代分数。
4. 关系字段消费端只按被授权用途决策。

**历史制品处理。** 重算使用该判据产生的替代/去重决定。相同数学定义的原始因子值无须重新落值。

**依赖。** 无额外单项依赖；遵循已有主合同。

### X03 · 边际贡献把样本变化误计成新因子信息

**优先级：** P0  
**证据性质：** D/S：比较口径不一致  
**源码：** [S02](https://github.com/18047533889/quant_projects/blob/2bac7209c00e302728b810513c91f5475ec6954f/quant_evaluator/metrics/interactions/substitution.py)；[S03](https://github.com/18047533889/quant_projects/blob/2bac7209c00e302728b810513c91f5475ec6954f/quant_evaluator/metrics/interactions/complementarity.py)；[S06](https://github.com/18047533889/quant_projects/blob/2bac7209c00e302728b810513c91f5475ec6954f/quant_evaluator/metrics/interactions/conditional.py)  
**函数/边界：** `compute_marginal_contribution / compute_substitution_effect / compute_complementarity_score`

**与V5的差异。** V5有共同样本原则；本轮给出违反该原则的实际函数位置和可重复反例。

**已见行为。** 基准IC在baseline有效样本计算，加入候选后的IC在更小joint样本计算，两者直接相减；两因子互补函数也可能将各自样本的IC与交集上的组合IC比较。条件IC还先用标签是否finite影响分组，标签validity又稍后处理，分组样本与实际计数不一致。

**具体反例。** 64只证券的基准全样本IC≈0，前32只IC=1。候选只在前32只存在且值恒定；联合IC=1，于是旧边际贡献≈1，但共同32只样本的实际增量=0。候选可用性可能有分组信息，应单独评价，不能冒充连续因子值的新增预测。P03。

**怎么改：**
1. 在同一pair/factor-set comparison中先生成共同样本身份；基准、候选和组合都在该样本重新计算。
2. 同时保留native deployment范围结果，明确coverage/value/missing-indicator三类贡献；不能只看交集而忽略真实覆盖损失。
3. 条件分组若声明为决策时可见分组，只用当时conditioning值与有效性形成；事后标签联合过滤只影响评估与n_joint，不能重新定义交易群体。
4. 按T×F×Q输出实际评价有效数，而不是用T×Q分组总人数代替每个被测因子的有效样本。

**真实仓库验收：**
1. 恒定on-support候选的共同样本增量=0，同时输出覆盖差异。
2. 把无效标签的物理存储从有限值改NaN，不得不经说明地改变其他合法样本的分组/结果。
3. 候选覆盖一致时，成对结果与各自原结果一致。

**历史制品处理。** 只重算受影响comparison及依赖它的替代/互补准入；真实可用性信号可另建明确recipe验证，不应一概删除。

**依赖。** X02

### X04 · 加入无关缺失因子，会让原本有效的相关性消失

**优先级：** P0  
**证据性质：** D：不相关候选破坏pairwise统计  
**源码：** [S04](https://github.com/18047533889/quant_projects/blob/2bac7209c00e302728b810513c91f5475ec6954f/quant_evaluator/metrics/interactions/pairwise.py)  
**函数/边界：** `compute_correlation_matrix(cross_sectional=True)`

**与V5的差异。** 不是V5已列GPU mask问题，而是CPU交互相关矩阵的全F预筛。

**已见行为。** 日期级预门槛使用np.all(isfinite(values_t),axis=1)，要求所有F列同时有效；后续虽按pairwise算相关，整个日期已可能被提前跳过。

**具体反例。** A、B在64只证券都有数据且相关≈1。追加一列全NaN的C，日期级有效数从64变0，A/B相关也不再计算。P04。

**怎么改：**
1. 删除跨所有候选F的门槛；每一对按其自己的joint mask、有效资产数和有效日期数计算。
2. 如某用途确需统一完整样本，显式设listwise policy与命名scope，不能挂在pairwise指标下面。
3. 批量计划固定pair身份、窗口和mask；F分片、候选顺序和加入无关列不得改变既有pair。

**真实仓库验收：**
1. 追加全缺失列、交换候选次序、分批合并，既有A/B结果和有效计数一致。
2. 常数相关定义为不适用或未定义，而不是对角线1即宣称有可用信息。
3. 不在十万规模构造T×F×F dense结果；走已有候选稀疏pair路径。

**历史制品处理。** 只失效被错误日期筛选影响的相似边/簇版本，不因修一条pair便全部重聚类。

**依赖。** 无额外单项依赖；遵循已有主合同。

### X05 · 泛化对比用np.resize把少量或空证据变成完整数组

**优先级：** P0  
**证据性质：** D：输入身份与值被静默改变  
**源码：** [S05](https://github.com/18047533889/quant_projects/blob/2bac7209c00e302728b810513c91f5475ec6954f/quant_evaluator/metrics/generalization_evidence.py)  
**函数/边界：** `compute_validation_retention_array / compute_generalization_deltas / build_train_validation_artifact`

**与V5的差异。** V5未具体定位这里的数组循环补值；不是重复分派一般轴对齐。

**已见行为。** 将两侧reshape(-1)，取最长长度，再np.resize到同长。短数组会循环复制；空数值数组会产生零。形状合法后，错配可能无法从最终制品发现。

**具体反例。** train有三个因子，valid=[0.08,0.16]，结果被扩成[0.08,0.16,0.08]；空valid可成为[0,0,0]。第三个因子没有证据却被填出数值。P05。

**怎么改：**
1. 按factor_id、factor_version、metric_instance与split refs显式对齐。长度不一且没有合法映射时拒绝，不允许reshape抹掉轴。
2. 允许集合对齐时，输出每项缺失与未测量原因；不将None/空数组变成0。
3. 单因子标量与多因子向量采用不同显式合同。需要广播的context参数可以广播，评价结果不能广播。

**真实仓库验收：**
1. 3对2、空对非空、相同长度不同顺序、T×F误输入均有明确验证结果。
2. 同一因子的证据不得循环复制给另一个factor_id。

**历史制品处理。** 识别由这种补值产生的generalization artifact；已知明确映射的正常等长结果可保留。

**依赖。** 无额外单项依赖；遵循已有主合同。

### X06 · 泛化置信区间的样本单位错成了因子数量

**优先级：** P0  
**证据性质：** S：统计估计对象错误  
**源码：** [S05](https://github.com/18047533889/quant_projects/blob/2bac7209c00e302728b810513c91f5475ec6954f/quant_evaluator/metrics/generalization_evidence.py)  
**函数/边界：** `_confidence_band / build_train_validation_artifact`

**与V5的差异。** V5配对CI原则之外的新定位：该函数把每因子一个汇总值当成置信区间样本。

**已见行为。** 构造器输入明确为每因子一条summary，_confidence_band直接在这些值之间估计标准误并返回一个公共区间。它没有该因子的日度/fold序列，无法证明单因子时间泛化不确定性。

**具体反例。** 两因子summary计算CI约[-0.0286,1.8286]；把同样两行重复100次，不增加一天市场样本，CI变成约[0.8342,0.9658]。P06。

**怎么改：**
1. 单因子区间必须消费该因子的时间块、fold或同方案抽样分布及有效样本数；输出factor_id×comparison的区间。
2. 只有一个summary时输出CI_NOT_IDENTIFIED_FROM_SUMMARY，不制造时间置信度；也不因只有一个因子就否定已有日度证据。
3. 若要报告库级横截面描述，使用独立metric ID并说明样本单位/相关家族，不能给每个因子套同一区间。
4. 强制维护block draw IDs与n_time/n_fold/n_factor，防止shape正确而统计单位错误。

**真实仓库验收：**
1. 复制其他因子、添加无关候选不能缩窄当前因子的时间区间。
2. 增加独立时间证据才可按模型假设改变其精度；别名不增加样本量。
3. 库级描述区间与单因子准入证据类型不可互换。

**历史制品处理。** 重算/撤销错误CI对应的证据等级与准入，不必改已有正确点估计。

**依赖。** X05

### X07 · 验证均值为零时，保留率区间错误收缩成[0,0]

**优先级：** P1  
**证据性质：** D：delta-method代数在零分子处错误退化  
**源码：** [S05](https://github.com/18047533889/quant_projects/blob/2bac7209c00e302728b810513c91f5475ec6954f/quant_evaluator/metrics/generalization_evidence.py)  
**函数/边界：** `_confidence_band`

**与V5的差异。** 与X06不同：即使将来输入轴修对，这个公式本身仍有零分子边界错误。

**已见行为。** 公式先用SE_valid/max(|mean_valid|,epsilon)，最后乘|mean_valid/mean_train|。当mean_valid=0，最后一步使所有不确定性乘成0。

**具体反例。** train=[.1,.1,.1]，valid=[-.02,0,.02]；验证样本有方差，旧CI仍为[0,0]。示例只验证代数，不把三点正态近似称有效95%置信检验。P07。

**怎么改：**
1. 若保留delta method，直接用ratio梯度计算方差：Var(V)/mu_T² + mu_V² Var(T)/mu_T⁴ − 2 mu_V Cov(T,V)/mu_T³。不得通过乘零掩盖分子不确定性。
2. 均值、方差、协方差的估计依正确样本单位和时间依赖而定，不能假设两个时期必然独立。
3. 分母接近零时返回不稳定或使用预声明的替代推断；仍可报告绝对差与其区间，不临时放大epsilon造有限值。

**真实仓库验收：**
1. 零验证均值但非零方差时，区间不得零宽。
2. 验证均值从正、零到负连续变化，结果不因epsilon产生不合理断裂。
3. 分母零/接近零有独立状态，不能称完全确定。

**历史制品处理。** 在修复X06的同一统计PR处理此公式，但保留独立边界测试。

**依赖。** X06

3. 该函数作为partial association仍允许运行，不误伤合法诊断。

**历史制品处理。** 只有存在误消费才失效依赖准入；目前未证明所有生产入口会这样用。

## 4. 跨项实施方案：修根因，不建15个新模块

### 4.1 QE交互证据分三层

第一层是描述性关联：同日partial correlation、因子值相似、简单加权混合IC。这些可以计算，但不能自称OOS模型增量。

第二层是受控配对比较：冻结方向、基准、共同样本、处理配方、期限与有效性。输出差值、差值不确定性、覆盖改变和实际经济成本。

第三层是用途准入：FO调用模型/组合现有训练与执行域，QE消费其训练外预测或持仓轨迹，FA按用途政策判断新增、替换或删减。不得把第一层裸float直接升级成第三层通过。

**新增字段应优先补到现有artifact：** `sample_unit`、`n_time`、`n_assets`、`n_factors`、`estimation_scope`、`common_support_ref`、`orientation_ref`、`baseline_ref`、`fit_scope`、`comparison_method_version`。这些是语义要求，不是要求逐字段再发明一个新包。

### 4.2 FA的约束感知MMR

修复后的伪代码如下，类型名称仅示意；正式比较和相似证据仍来自QE，选择算法保留在FA：

```python
# Prevalidate quality, pair-evidence policy, hard constraints and K.
selected = []
max_redundancy = {candidate.id: 0.0 for candidate in candidates}
while len(selected) < K:
    feasible = [c for c in remaining if constraints.can_add(c, selected)]
    if not feasible:
        break
    chosen = choose_by_declared_mmr(feasible, quality, max_redundancy)
    selected.append(chosen)
    constraints.commit(chosen)
    remaining.remove(chosen)
    # Batch refine only the pairs required by this new selected member.
    # UNKNOWN must not silently become zero.
    pair_evidence = qe_similarity_batch(remaining, chosen, comparison_spec)
    validate_pair_evidence(pair_evidence)
    update_max_redundancy(max_redundancy, pair_evidence)
```

首次selected为空时的0是“空集合不存在冗余惩罚”的数学初值，不是把未知pair当成0。当新增成员出现后，必须取得适用pair证据或按明确策略延期；不能在为省钱重写时把已正确的UNKNOWN保护删掉。

### 4.3 状态机让结果证明完成，而不是由调用者声称完成

一个StageOutcome至少需要引用实际发出的job/attempt、candidate recipe版本、当前stage和评价证据。接受结果的事务核对状态、去重outcome、更新预算与候选阶段；结果重复投递只回放同一结论。既有队列、outbox、trial账本已实现的直接复用，不能因X14新建第二套竞争工作流。

### 8.2 外部定义核对

- NumPy `resize`：新数组超出原长度时会重复原内容。这是数值数组重排函数，不是证据身份对齐工具。<https://numpy.org/doc/stable/reference/generated/numpy.resize.html>
- NumPy `lstsq`：返回最小二乘解、矩阵秩与奇异值，可用于已有数值权威中的rank-aware实现。<https://numpy.org/doc/stable/reference/generated/numpy.linalg.lstsq.html>
- scikit-learn Common pitfalls：训练与评价数据的用途要隔离，不能用测试信息fit并把同样本结果当泛化。本文X08没有因此禁止合法的事后partial correlation。<https://scikit-learn.org/stable/common_pitfalls.html>
- SciPy Pearson相关定义：常数输入相关未定义，且没有线性相关不代表统计独立。<https://docs.scipy.org/doc/scipy/reference/generated/scipy.stats.pearsonr.html>

外部文档支持定义，不为本项目任何IC阈值、收益、等级或可盈利性背书。
