## 团队版本使用原则

- 源码固定到一次发布回执中的总仓提交，或分别固定到对应镜像提交。各库原有 `0.1.0` 等版本号不等于完整源码版本，不能仅比较包版本号判断同步。
- Python 项目的 `pyproject.toml` 是依赖声明；requirements 入口用于安装，只有明确提供的精确约束/锁才限定版本。不要把带宽松下限的 requirements 当作锁。
- 核心安装入口与平台范围见 `docs/TEAM_INSTALL.md`。内部库从这次固定源码安装，不从公共索引盲取同名包。
- 不强行把核心栈、兼容回测栈、AlphaProbe/GPU 和前端混入同一环境；Python、NumPy、Numba、CUDA、Node 的适用范围分别说明。跨系统及生产 GPU 验收不由一次依赖解析自动证明。
- 历史 `requirements-production.lock` 中有解释器伪依赖、缺失版本或不匹配哈希说明，不应作为新的团队安装命令依据。
