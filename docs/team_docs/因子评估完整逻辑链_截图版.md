# 因子评估完整逻辑链（截图版）

下面这份不是正文需求文档，而是一份专门给你截图、发群、做开场解释用的逻辑链总览。

写法原则：

- 以中文解释为主，但保留必要英文字段，方便和实际对象、库表、消息、代码对齐。
- 按真实流程顺着往下看，一眼能明白全链路。
- 重点写“这个阶段做什么、产出什么、往哪里流、失败后怎么回流”。
- 和主需求文档的思路保持一致，但更适合截图展示。

## 一页总链路

```text
[0. 24小时多方法持续挖掘]
LLM / 强化学习 / 遗传规划 / 论文公开方法 / 开源仓库复现 / 人工研究 / 聚合器回流
持续产生候选因子
产出内容：
- 原始公式
- 公式结构
- 父因子关系
- 复杂度估计
- method_code / campaign_id / iteration_id / batch_id / parent_factor_ids
        |
        v
[1. 极速网关：静态拦截 + 查重]
先做最便宜、最快速的过滤，避免浪费后续算力
主要动作：
- 提交格式校验
- 公式结构解析
- 未来函数拦截
- 非法算子拦截
- 复杂度预算检查
- 重复因子检查(ast_hash / semantic_hash / 数值指纹)
处理结果：
- 合法且不重复 -> 进入正式计算队列
- 重复 / 非法 / 超预算 -> 直接进入负样本归档，不再消耗算力
        |
        v
[2. 因子登记与户籍创建]
给通过网关的候选分配正式因子编号
建立因子户籍、血缘关系、实验记录
形成正式 FactorAsset
从这一层开始，系统追踪的是“正式因子资产”，不是一段临时公式
        |
        v
[3. 因子计算引擎]
读取底层量价数据和基础数据
调用现有因子执行能力，计算原始因子暴露（已有）
首期现状：
- 先写入 factor_lake_staging（已有）
- 再通过 publish_from_staging 发布到 factor_lake（已有）
完整目标：
- 控制面、数据面、产物面进一步企业化
        |
        v
[4. 截面清洗与纯化]
把“原始因子值”处理成“可评估、可比较、可入库的纯净因子值”
主要动作：
- 缺失和脏值处理
- 去极值
- 标准化
- 行业中性化
- 市值中性化
- 风险因子正交化 / 残差化
输出：
- 原始暴露
- 标准化暴露
- 中性化暴露
- 残差暴露
        |
        v
[5. 全维度评估引擎]
基于纯净因子值并行计算多类指标
评估维度：
- 预测能力：IC、Rank IC、衰减速度、半衰期
- 结构质量：分组单调性、多空对称性、头尾分层
- 收益风险：多空收益、夏普、回撤、尾部风险
- 独立性：与库内已有因子的相关性、边际增益、风格簇归属
- 落地性：换手、冲击、容量、融券成本
- 鲁棒性：扰动稳定性、过拟合修正、不同市场环境稳定性
输出：
- 评估汇总
- 明细时序
- 分组回测
- 多空收益曲线
- 指标清单
说明：
- 现有 factor_evaluation 已有标准单因子评估主链（已有）
        |
        v
[6. 自动化贴标]
根据评估结果、来源信息、风格暴露、库内关系自动生成标签
标签分为五类：
- 来源标签
- 性能标签
- 风格标签
- 生命周期标签
- 动作标签
标签的作用不是展示，而是决定后续怎么路由、怎么检索、怎么复评
        |
        v
[7. 智能路由与入库决策]
不做简单“通过 / 不通过”，而是做多分支分流

  ├─ 分支 A：完整通过
  |   条件：
  |   - 预测力稳定
  |   - 结构质量好
  |   - 风险收益可接受
  |   - 和现有库不是严重重复
  |   去向：
  |   - 核心生产库
  |   - 卫星生产库
  |   - 特征原料库
  |
  ├─ 分支 B：高潜但有硬伤
  |   典型问题：
  |   - 换手过高
  |   - 衰减太快
  |   - 信号太抖
  |   去向：
  |   - 孵化库 / 加工车间
  |   处理动作：
  |   - 平滑
  |   - 降频
  |   - 裁剪
  |   处理后：
  |   - 回到“截面清洗与纯化”
  |   - 再次评估
  |
  ├─ 分支 C：严重同质化但可修
  |   典型问题：
  |   - 与现有风格簇太像
  |   - 与已有核心因子高度相关
  |   去向：
  |   - 孵化库 / 加工车间
  |   处理动作：
  |   - 残差化
  |   - 正交化
  |   - 去共线化
  |   处理后：
  |   - 回到“截面清洗与纯化”
  |   - 再次评估
  |
  └─ 分支 D：彻底否决
      典型问题：
      - 噪声脆弱
      - 容量极差
      - 疑似泄漏
      - 多维度表现都很差
      去向：
      - 负样本归档库
      作用：
      - 保存失败原因
      - 为后续反馈闭环提供反例知识

        |
        v
[8. 分层因子库]
不是所有因子都进一个总库，而是分层管理

- 第0层：原始降落区
  放候选提交体、预检查结果、查重结果

- 第1层：标准评估区
  放正式登记后的因子、物化结果、评估产物

- 第2层：孵化库 / 加工车间
  放高潜但需要修复的因子
  主要用于平滑、降频、残差化、正交化、去共线化后再评估

- 第3A层：核心生产库
  直接服务正式组合主线

- 第3B层：卫星生产库
  有增量价值，但稳定性或容量略弱于核心库

- 第3C层：特征原料库
  不一定适合单因子直接上生产
  但适合给聚合器、模型层、超级因子引擎使用

- 第4层：归档与负样本库
  放否决对象、重复对象、退役对象和失败样本
        |
        v
[9. 下游消费层]
下游主要有三条使用主线：

- 组合研究主线
  消费核心库和部分卫星库
  形成组合信号、持仓和组合回测

- 单资产信号主线
  形成单资产择时、目标仓位和单资产回测

- 特征供给主线
  消费特征原料库
  给聚合器、非线性模型、超级因子引擎使用
        |
        v
[10. 持续复评、监控与退役]
进入正式生产后也不是结束
还要持续监控：
- 预测力衰减
- 风格漂移
- 拥挤风险
- 容量变化
- 成本变化
可能发生：
- 进入观察名单
- 降级
- 退役
- 归档
        |
        v
[11. 闭环反馈与基因迭代]
把两类信息回传给上游挖掘系统：

- 失败因子的失败原因
  例如：高换手、严重重复、噪声脆弱、容量不足

- 成功因子的生产贡献
  例如：在组合中的边际贡献、归因结果、不同市场环境下的稳定性

这些反馈会变成下一轮挖掘的指导信号：
- 给 LLM：提示词和禁止模式
- 给强化学习：奖励函数修正
- 给遗传规划：变异和交叉偏好

最终重新回到：
[0. 24小时多方法持续挖掘]
```

## 字段解释与完整案例

### 字段解释

- `method_code`：候选因子的来源方法，例如 `llm`、`rl`、`gp`、`paper`。
- `campaign_id`：一轮大规模挖掘活动的大轮编号。
- `iteration_id`：同一大轮里的第几轮迭代。
- `batch_id`：一次具体运行批次，偏工程调度视角。
- `parent_factor_ids`：这个候选因子是从哪些父因子演化出来的。
- `factor_id`：正式登记后分配给这个因子的唯一编号。
- `FactorAsset`：正式因子资产对象。后续评估、贴标、路由、复评都围绕它展开。

### 完整案例

```text
method_code   = gp
campaign_id   = gp_us_pv_2026q2_round01
iteration_id  = iter_07
batch_id      = 20260502_night_03

解释:
- 这是一个来自 GP 的候选因子
- 它属于 2026 年 Q2 的第一轮美股量价 GP 大轮
- 它是这个大轮里的第 7 次迭代结果
- 它是在 2026-05-02 夜间第 3 个运行批次里产生的

流程:
1. GP 生成候选公式，并带上父因子关系和复杂度信息
2. 候选提交进入原始候选入口
3. 极速网关检查它是否合法、是否重复、是否超预算
4. 如果通过，就登记并生成 factor_id
5. 然后调用现有 factor_engine 计算原始因子暴露
6. 暴露先进入 staging，再发布到正式因子库
7. 再做截面清洗、标准化、中性化、残差化
8. 再跑全维度评估
9. 假设结果是：
   - Rank IC 很强
   - 但是换手率偏高
   - 和已有某类反转因子相关性也偏高
10. 那么它不会直接进入核心库，而会被贴上：
    - high_ic
    - high_turnover
    - needs_smoothing
    - needs_residualization
11. 然后它会进入 Tier 2 孵化库
12. 在孵化库里做：
    - 时间平滑
    - 降频
    - 残差化
13. 处理后回到“截面清洗与纯化”，再重新评估
14. 如果重评后通过，就可能进入核心库、卫星库或特征原料库
15. 如果最终还是不行，就进入 Tier 4 负样本归档库
16. 它失败的原因会回传给上游 GP，指导下一轮变异和搜索
```

## 简化版：适合发消息的超短逻辑链

```text
多方法持续挖因子
-> 极速网关拦截非法、重复、超预算候选
-> 正式登记因子资产
-> 计算原始因子暴露
-> 做截面清洗、中性化和风险纯化
-> 跑全维度评估
-> 自动贴标签
-> 智能路由到核心库 / 卫星库 / 特征库 / 孵化库 / 归档库
-> 下游组合、单资产和聚合器消费
-> 持续复评、降级、退役
-> 把失败原因和成功经验反馈给下一轮挖掘
```
