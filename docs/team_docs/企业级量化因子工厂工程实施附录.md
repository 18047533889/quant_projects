## 4. 状态机规则

### 4.1 主状态迁移

```text
landing
-> screening
-> materializing
-> evaluating
-> admitting
-> production_core / production_satellite / feature_store_ready / incubating / archived
```

### 4.2 异常状态迁移

```text
screening -> screening_rejected -> archived
production_core -> watchlist -> deprecated -> archived
incubating -> evaluating -> admitting
```

### 4.3 状态迁移约束

- 不能从 `landing` 直接跳到 `production_core`。
- 不能从 `screening_rejected` 直接回到 `evaluating`，必须重新提交候选或重开记录。
- `watchlist` 不是最终状态，必须进一步转到 `production_*`、`incubating` 或 `deprecated`。
- `archived` 为终态，仅允许重新生成新版本进入主线，不建议原对象反复复活。

## 5. 路由动作矩阵

| 条件 | 动作 | 目标 |
| --- | --- | --- |
| 非法表达式 / 未来函数 / 超时 | `hard_reject` | `tier4_archive` |
| 预测力弱且多项核心指标失效 | `hard_reject` | `tier4_archive` |
| 高潜但换手高 / 相关性高 | `incubate` | `tier2_incubator` |
| 单因子质量高、可直接服务组合 | `accept_core` | `tier3a_core` |
| 有增量价值但稳定性略弱 | `accept_satellite` | `tier3b_satellite` |
| 单因子一般但适合供模型聚合 | `accept_feature_store` | `tier3c_feature` |
| 生产中明显衰退但暂不退役 | `watchlist` | `watchlist` |

## 8. 错误码与处理建议

| 错误码 | 含义 | 建议动作 |
| --- | --- | --- |
| `CANDIDATE_SCHEMA_INVALID` | 候选提交体不合法 | 直接拒收 |
| `COMPLEXITY_EXCEEDED` | 复杂度超预算 | 直接退回或降级重试 |
| `DUPLICATE_FOUND` | 与库内对象重复 | 记录重复关系，不进入评估 |
| `FACTOR_NOT_REGISTERED` | 正式因子不存在 | 阻断后续评估和准入 |
| `PUBLISH_VALIDATION_FAILED` | staging 发布校验失败 | 保留 staging，禁止升格 |
| `EVALUATION_ARTIFACT_MISSING` | 评估产物不全 | 标记 run 失败 |
| `ADMISSION_POLICY_INVALID` | 准入策略缺字段 | 拒绝执行准入 |
| `ROUTE_TARGET_INVALID` | 路由目标非法 | 阻断状态迁移 |

## 9. 工程注意事项

- 所有对象都要带 `campaign_id`、`iteration_id` 和 `batch_id`，否则无法支撑多方法持续挖掘场景。
- 首期建议沿用现有目录和文件协议，不要先改存储再谈治理。
- 所有新的服务层对象都必须能映射回现有产物目录，否则排查会非常困难。
- 所有状态变更都要有审计记录，不允许只更新当前状态而不留历史轨迹。
- 路由和标签规则必须配置化，不写死在代码分支里。

## 10. 对下游基建组的直接提示

- 先把对象和状态机建对，再做 UI 或服务外壳。
- 先打通 `candidate -> factor -> evaluation -> admission -> route` 这条线，再扩展高级评估项。
- 先保证可回放和可审计，再做性能优化和服务拆分。
