[全局基建] 湖仓一体与微服务技术栈选型 (Enterprise Tech Stack)
架构宣言：系统严禁过度绑定单一语言！因子评估可能由 Python 编写，但下游微观脉冲执行引擎必须是 Rust/C++，路由与网关必须是 Go。各组件间强制采用高性能通信与读写分离存储。
计算引擎层 (Compute)
【离线批处理】: Python + Ray 分布式集群，执行长周期历史回测。
【高频流式/订单簿】: 强制采用 Rust/C++ 重写核心 factor_engine。
【通信契约】: 严禁 JSON 传大矩阵！必须通过 Apache Arrow Flight (零拷贝共享内存) 或 gRPC Stream 传输高频张量。
湖仓数据面 (Lakehouse)
【写密集/高频流】: Apache Hudi，提供读时合并 (MoR) 支撑订单簿更新。
【海量只读回测】: Apache Iceberg，强依赖写时复制 (CoW) 与隐藏分区，完美支持 PIT 拼接防穿越。

【消息总线】: Kafka，负责 factor.candidate.evaluated 等状态流转的全局异步广播。
【流式状态/特征缓存】: Redis / Aerospike，持久化 Rolling Window 最新状态，彻底消除离线与在线计算漂移 (Online-Offline Skew)。

【产物防篡改】: MinIO (对象存储)。所有 Artifacts (如 eval_reports.json) 落盘后强制锁定为 不可变只读 (Immutable) 并写入 SHA256 Checksum。
【血缘图谱】: Neo4j 支撑级联失效重算。
【任务编排】: Airflow / Prefect。
Order Book Imbalance (订单簿失衡度)
【应用轨道】: Track C3 (微观脉冲) / 高频扩展
【数学公式】: $\text{OBI}_t = \frac{\sum_{i=1}^k (V_{bid,i} - V_{ask,i})}{\sum_{i=1}^k (V_{bid,i} + V_{ask,i})}$
【工程约束】: 针对高频脉冲因子，必须计算信号发出瞬间的失衡度，以确认信号是否具备抢跑流动性耗尽的微观解释力。
Regime Shift Probabilities (状态转移概率)
【应用轨道】: Track G (宏观状态轨)
【数学公式】: $P(S_t = j | S_{t-1} = i)$，基于 HMM 等隐状态推断。
【工程约束】: 必须在时序评估中生成转移概率热力图，并测算因子在不同隐状态（如单边趋势、高波震荡）下的存活率。
Tail Dependence (尾部相依性)
【应用轨道】: 极值理论 / 压力测试
【数学公式】: $\lambda_U = \lim_{q \to 1} P(X > F_X^{-1}(q) | Y > F_Y^{-1}(q))$
【工程约束】: 评估策略时，必须测算资产因子与市场大盘崩盘期间的极值相关性，防范策略在极端黑天鹅下发生致命共振。
Value at Risk & Expected Shortfall (VaR & ES)
【应用轨道】: 全局风控 / 尾部测算
【数学公式】: $\text{ES}_\alpha = E[R | R \le -\text{VaR}_\alpha]$
【工程约束】: 必须测算并汇报 95% 和 99% 置信度下的 CVaR (条件风险价值)，防范黑天鹅事件导致的穿仓风险。
Roll's Spread (罗尔隐含价差)
【应用轨道】: Track C (微观轨) / 摩擦估算
【数学公式】: $S = 2 \sqrt{-\text{Cov}(\Delta P_t, \Delta P_{t-1})}$
【工程约束】: 在缺乏高频 Level-2 数据时，利用相邻两期价格的负自相关性推算隐性买卖价差，评估流动性枯竭时的真实交易成本。
Kyle's Lambda (市场深度流动性)
【应用轨道】: 冲击测算 / 高频做市
【数学公式】: $\Delta P_t = \lambda \cdot Q_t + \epsilon_t$
【工程约束】: 通过价格变动与净订单流回归计算 $\lambda$。高频策略入库前必须测算其订单在不同 $\lambda$ (市场深度) 下的冲击耐受度。

1.4 Agent 未来函数审计

【逻辑】: 部署多智能体 (Multi-Agent) 审计流水线。构造交互项回归 $Y_{t+1} = \beta_1 X_t + \beta_2 L_t + \beta_3(X_t \times L_t)$ 检验涉嫌泄露的前瞻变量 $L_t$。
【出参】: $\beta_3$ 异常显著则证明发生污染，直接阻断。

【出参】: 标记 cache_hit: true，微秒级返回历史评估报告 URI。
网关分流决策： Passed (进入计算主线) | Duplicate (返回缓存) | Rejected (打入 Tier 4 负样本库)

[3.5] 数据质量预检防线 (Data Quality Pre-flight) 【严苛质量把控】
核心目标：在消耗算力计算因子值之前，对底层依赖数据进行高标准健康度检查。避免“Garbage In, Garbage Out”。
基础健康度断言 (Sanity Assertions)
【逻辑】: 检验特征极值分布偏移 (Distribution Shift)、NaN/Infinity 爆炸率。确保序列长度满足回测窗口下限。
【机制】: 设定容忍阈值（如 NaN 比例 > 5% 则触发警告，> 15% 熔断）。
微观结构异象侦测 (Micro-Structure Anomalies)
【逻辑】: 针对高频数据，检测“负买卖价差”(Negative Spread)、“跳空闪崩”(Flash Crash) 等数据污染。
【防御】: 若发现底层时序大面积包含微观错误，系统自动挂起该因子计算，并向数据工程团队发送 DataQualityAlert。
↓ 根据路由指令，动态组装预处理管线与回测引擎上下文，这构成了多轨评估的“指挥塔”

【入参 (Input)】: 通过 Gateway 审查的合法候选对象及元数据。
【处理逻辑 (Process)】: 为其分配全系统唯一的正式 factor_id，绑定固定的库坐标（如 signal_structure / asset_class / frequency_bucket / domain_root）。状态推进为 landing -> screening -> materializing。
【出参/效果 (Output)】: 生成正式 FactorAsset 对象，从此刻起系统追踪正式资产，而非临时公式。
Neo4j 数据血缘图谱定义 (Graph Schema)
【节点 (Nodes)】: (DataFeed) -> (Operator) -> (Factor) -> (Model)。
【关系 (Edges)】: [DERIVED_FROM], [COMPUTED_BY], [CONSUMED_BY]。
【工程意义】: 当上游某个行情源 (如 Binance_Tick) 发生数据重刷时，通过 Neo4j 图谱一键触发所有依赖其的 Factor 和下游 Model 进行级联重算 (Cascading Recalculation)，保证全局数据一致性。

[5] 因子特征物化与核心计算引擎 (Factor Engine & Materialization) 【现有基建复用】
核心架构：系统已有强大算子层，严禁重复造轮子！当前 factor_engine 已支持字符串 DSL 到 AST 转换、多后端执行 (Pandas/Modin/Polars) 及 factor_lake_staging 物化。未来演进方向为引入 Rust/C++ 的 JIT/SIMD 极速底层。
3.1 AST 解析与 DAG 算子树优化 (已具备)
【入参】: 原始公式 ts_mean(close, 5) / ts_mean(close, 10)。
【逻辑】: 引擎将其解析为有向无环图 (DAG)，执行 公共子表达式消除 (CSE)。例如，ts_mean(close, 5) 如果在其它因子算过，直接复用内存指针。
【出参】: 极致压缩的物理执行计划。
3.2 向量化与 JIT 编译执行
【入参】: 优化后的 DAG 执行计划与底仓数据。
【逻辑】: 放弃逐行解释。通过 LLVM JIT 动态编译，或者调用 Rust 的 SIMD (单指令多数据流) 指令集，在 CPU 寄存器层面并发处理截面数组。
【出参】: 提升百倍的计算吞吐量。
3.3 严格双时态与 ASOF JOIN
【入参】: 交易流与 knowledge_ts (物理入库时间)。
【逻辑】: 严禁使用 trade_date 做普通 merge！强制使用 ASOF JOIN (按时间就近向下匹配)：WHERE knowledge_ts <= decision_ts。
【出参】: 彻底阻断基本面财报修订和高频事件抢跑的未来函数。
3.4 Staging 隔离与原子落盘
【入参】: 引擎计算出的多阶特征张量。
【逻辑】: 写入隔离沙盒 factor_lake_staging。待数据 Schema 校验、空值率审计全部通过后，才执行 Atomic Move (原子重命名) 进入正式生产湖。
【出参】: 保证线上读取永远不会读到“写了一半”的脏数据。
↓ 多轨评估完毕，产出海量指标，进入贴标画像与决策阶段
[6] 数学纯化流水线 (Mathematical Purification Pipeline)
核心原则：不同类型的因子具有截然不同的物理属性，严禁“一锅端”。必须满足严苛的风控红线，执行 MAD 稳健去极值与 WLS 加权正交化。
A. 稳健去极值 (Robust Winsorization)
【入参】: 包含极端黑天鹅的截面特征矩阵。
【红线拦截】: 严禁使用易受离群值扭曲的 3-Sigma 均值标准差法。
【强制处理】: 必须使用 MAD (Median Absolute Deviation)。公式：
$M = \text{median}(X)$, $\text{MAD} = \text{median}(|X_i - M|)$。
截断边界：$[M - 3.148 \cdot \text{MAD}, M + 3.148 \cdot \text{MAD}]$。
B. 高阶风险正交化 (WLS Orthogonalization)
【入参】: 暴露于市场 Beta 和行业风格的因子。
【红线拦截】: 严禁仅做简单的行业市值去均值。
【强制处理】: 针对结构化风险模型 (如 Barra)，必须采用 加权最小二乘法 (WLS) 回归：$f_{\text{raw}} = \beta \cdot \mathbf{X}_{\text{risk}} + \epsilon$。
权重使用市值的平方根。纯净因子即为残差 $\epsilon$。
C. 动态缺失值填补 (Dynamic Imputation)
【入参】: 包含停牌、无数据的非随机缺失 (MNAR) 序列。
【红线拦截】: 严禁使用全局均值或中位数粗暴填充。
【强制处理】:
- 截面缺失：采用截面内行业加权均值填补。
- 时序缺失：采用带指数衰减的向前填充 (Forward-fill with decay)，超过最大容忍延迟则丢弃。
D. 对称正交与流形保护 (Symmetric & Manifold)
【入参】: 深度学习输出的隐式高维张量 / 强共线性因子组。
【红线拦截】: 严禁破坏向量空间的几何拓扑结构。
【处理】:
- 组内正交：计算协方差 $C$，利用 Löwdin 对称正交 $F_{orth} = F \cdot C^{-1/2}$。
- 张量处理：在流形空间执行 $L_2$ 范数归一化，严禁列级 Z-score。
E. Crypto 永续专线 (Perpetual)
【入参】: 包含异常插针与资金费率的 7x24 盘口。
【处理 1：费率对齐】: 精确匹配 8 小时一次的 Funding Rate 扣减时间戳。
【处理 2：聚合降噪】: 针对跨交易所流动性，按成交量加权聚合 (Volume-Weighted Aggregation) 剔除单一所的 Spoofing 假单。
【出参】: 剥离虚假流动性噪音的链上特征。
F. 期货连续主力专线 (Futures)
【入参】: 换月时存在价差跳空的期货合约。
【处理 1：价差缝合】: 采用 Panama Canal Stitching (巴拿马平移) 累加展期跳空差额 $P_{adj} = P_{raw} + \sum \Delta_{roll}$。
【处理 2：持仓缩放】: 基于 Time-to-Maturity (TTM) 进行非线性缩放，降低临近交割日的噪音权重。
【出参】: 不受交割规则扭曲的无跳空期限特征。
防泄露红线：严禁全局统计泄露 (用全样本均值算Z-score)、严禁参数前视、严禁正交化泄露。一切统计量必须是 Rolling 的。
[6.5] 高频微观结构专属预处理 (High-Frequency Preprocessing)
核心原则：高频量价与 LOB (订单簿) 数据的预处理逻辑与低频基本面截然不同。系统开辟了独立的高频数据管道，执行微观状态对齐与高频滤波。
A. LOB 状态空间对齐 (Micro-State Alignment)
【入参】: 不规则的 Tick-level 逐笔订单簿切片。
【处理】: 采用事件驱动 (Event-driven) 重采样技术。确保在极微小的时间戳内，不同深度档位 (Bid/Ask) 的量价状态完全一致，消除时钟抖动引发的特征错位。
B. 高频去噪与滤波 (High-Freq Denoising)
【入参】: 充满白噪音的高频特征序列。
【处理】: 避免使用移动平均 (MA) 导致信号严重滞后。引入 Savitzky-Golay 滤波 或 卡尔曼滤波 (Kalman Filter) 提取潜在动力学趋势，保留微观价格跳跃 (Jumps)。
C. 非线性信号挤压 (Non-linear Squashing)
【入参】: 存在瞬间暴增或无限放大的高频脉冲强度。
【处理】: 信号传入下游前，强制经过 tanh 或自定义 Softplus 函数执行软截断 (Soft Clipping)，压制极端脉冲对后续强化学习权重的破坏。
D. 迟滞环降噪 (Hysteresis Loop)
【入参】: 频繁在阈值边缘跳动的触发规则信号。
【处理】: 设定双阈值边界 (如买入阈值 $T_{upper}$，平仓阈值 $T_{lower}$)。构建状态死区 (Deadzone)，强力阻断微观高频的“乒乓换手效应”。
[6.8] 另类数据与非结构化预处理 (Alternative & Unstructured Pipeline)
核心原则：为支持 NLP 文本与知识图谱等前沿数据源，系统开辟独立的非结构化特征工程基座，执行语义实体对齐与图谱补全。
A. 实体链接与消歧 (Entity Linking)
【入参】: 包含模糊别名的新闻、社交媒体文本流。
【处理】: 提取文本前，强制执行实体消歧，将 "果链"、"A厂" 等模糊词汇映射到统一的 Asset_ID，消除交叉污染。
B. 稠密向量提取 (Dense Embeddings)
【入参】: 清洗后的研报与新闻长文本。
【处理】: 经过 FinBERT 或专用金融 LLM 提取 768 维稠密特征向量。强制隔离未来词表。
C. 情感极性衰减 (Sentiment Decay)
【入参】: 离散且瞬间爆发的 NLP 情绪得分。
【处理】: 避免使用简单的算术平均。采用 成交量加权的指数衰减滑动平均 (Volume-weighted EMA)，捕捉突发热度的半衰期。
D. 图谱拓扑提取 (Graph Topology)
【入参】: 供应链网络、股权穿透网络。
【处理】: 使用 Node2Vec / GCN 提取节点特征。对孤立节点 (Isolated Nodes) 产生的空值使用图中心度 (Centrality) 动态补全。

A. 股票多因子与基本面量化 (Equity Multi-Factor)
1. 财报跳空与盈余漂移 (PEAD)
【评估轨】: 横截面基本面轨
【专属动作】: 收益核算必须从 T+1 开盘价 (Open_{t+1}) 算起。
【红线】: 财报往往在盘后发布。严禁将财报日当天的收盘价作为成本价，否则“隔夜跳空收益”实盘根本吃不到，引发严重穿越。
2. 分析师预期修正 (Analyst Revision)
【评估轨】: 横截面基本面轨
【专属动作】: 启动 僵尸预期剔除 (Stale Estimate Dropping)。
【红线】: 分析师数据存在“聚团更新”。若超过 90 天未更新的数据不被强行剔除，会严重污染一致预期的均值和标准差分母。
3. 财务造假识别 (Fraud Detection)
【评估轨】: 离散规则轨 (做空池)
【专属动作】: 提取 Beneish M-Score 等指标进行 一票否决 (Veto)。
【红线】: 这类因子通常不能产生稳定正收益，而是作为黑名单过滤器。必须测试其对现有多头组合“排雷”后的夏普增益。
4. 风格漂移剥离 (Style Drift)
【评估轨】: 横截面纯化轨
【专属动作】: 强制进行 市值与动量双重正交 (Size & Momentum Neutral)。
【红线】: 很多所谓的“低波动”或“高质量”因子，其收益完全来自于隐含的小盘股或动量暴露。若不剥离 Beta，纯净 Alpha 为零。
B. 高频量价与微观结构 (High-Frequency & Microstructure)
5. 订单簿失衡压迫 (LOB Imbalance)
【评估轨】: 时序微观脉冲轨
【专属动作】: 强制注入 排队位置耗时模型 (Queue Position Model)。
【红线】: 严禁“触价即成交”假设。若订单挂在 Tail 端且撤单率极高，整个信号周期内根本无法成交，必须算作 Missed Fill。
6. 大单资金流向 (Order Flow Toxicity)
【评估轨】: 时序/截面轨
【专属动作】: 必须注入 3 倍市场冲击弹性 (Market Impact Multiplier)。
【红线】: 资金流向极具“内生反身性”（大单自身推高了价格）。如果不加重滑点惩罚，回测必陷“买入即赚钱”的同向假象。
7. 极短期均值回归 (Micro-Reversion)
【评估轨】: 时序微观脉冲轨
【专属动作】: 引入 迟滞环 (Hysteresis Loop) 双阈值截断。
【红线】: 信号在临界点反复横跳。若不设置死区 (Deadzone)，将产生海量的“乒乓换手”，手续费瞬间击穿所有利润。
8. 暗池与大宗交易 (Dark Pool / Block)
【评估轨】: 微观结构轨
【专属动作】: 注入 延迟印证延迟 (Delayed Tape Printing) 调整。
【红线】: 暗池交易往往延迟 15 分钟甚至更久汇报。回测时绝对不能把“交易发生时间”当做“信号获取时间”。
C. 统计套利与特殊事件 (StatArb & Event Driven)
9. 统计配对套利 (Pairs Trading)
【评估轨】: 跨资产协整轨

【红线】: 严禁仅靠“相关性”做对冲。必须证明残差序列平稳。当价差发散超过最大容忍时间 (如 3 个半衰期) 时必须强制止损。
10. ETF 申赎与折溢价 (ETF Arbitrage)
【评估轨】: 公司行为套利轨
【专属动作】: 强制计算 篮子同步冲击成本 (Basket Impact)。

11. 内部人与高管交易 (Insider Trades)

【专属动作】: 剥离 10b5-1 预定计划 (Programmed Trades)。
【红线】: 多数高管卖出是税务或期权到期的被动操作。必须剔除例行公事的卖出，仅保留“非计划内的簇状抛售”作为做空信号。
12. 并购重组套利 (M&A Arbitrage)
【评估轨】: 事件驱动轨
【专属动作】: 注入 交易破裂概率折现 (Deal Break Probability)。
【红线】: 严禁将收购公告价直接视为无风险套利空间。必须结合反垄断审查、融资环境和宏观周期测算失败风险。

[8] 时序执行工程与摩擦成本数学模型 (Execution & Friction Modeling)
为什么这是生死线：横截面日频的摩擦主要是调仓滑点，而高频时序的生死线直接落在买卖价差 (Bid-Ask Spread)、手续费和延迟。不带执行语义的时序回测全是“纸上富贵”。
1. 平方根冲击成本模型 (Square-Root Impact)
【入参 (Input)】: 订单量 $Q$、市场总成交量 $V$、资产日波动率 $\sigma$。
【处理逻辑 (Process)】: 使用公式 $Impact = Y \cdot \sigma \cdot \sqrt{\frac{Q}{V}}$ 测算非线性成本；实时获取当期真实的 $V$ 动态调整滑点。
【出参/效果 (Output)】: 产出更真实的执行成本估算，防止在大单成交时低估滑点导致容量测算失效。
2. 分数阶差分记忆保留 (Fractional Diff)
【入参 (Input)】: 非平稳原始序列 $X_t$、差分阶数 $d \in (0, 1)$。
【处理逻辑 (Process)】: 执行 $(1 - B)^d X_t = \sum_{k=0}^{\infty} w_k X_{t-k}$；通过 ADF 检验寻找满足平稳性的最小 $d$ 值。
【出参/效果 (Output)】: 在满足平稳性的同时最大化保留序列的长程记忆 (Long-memory)，提升机器学习模型的预测力。
3. 成本感知的凸优化器 (Cost-Aware Convex Optimizer)
【入参 (Input)】: 预期收益向量 $\mu$、当前持仓 $w_{t-1}$、L1 惩罚项 $\lambda$。
【处理逻辑 (Process)】: 求解 $\max [\mu^T w_t - \lambda ||w_t - w_{t-1}||_1]$；引入 L1 范数触发“惰性调仓 (Lazy Trading)”机制。
【出参/效果 (Output)】: 自动过滤微弱噪音导致的过度调仓，确保每一笔交易的预期收益都能覆盖交易摩擦。

[9] 数据边界处理与双时态防穿越机制 (Point-in-Time & Anti-Leakage)
逻辑说明：本环节主要处理数据在内存、精度、时区和截面聚合时的极值边界，并针对历史回测中的常见数据穿越问题进行机制阻断，确保回测环境与实盘环境的严格物理一致性。
I. 数据与内存边界处理 (Hardware & Precision Limits)
1. 大容量内存调度 (OOM 防范)
【入参 (Input)】: 全市场高频历史数据 (Tick/1min)
【处理逻辑 (Process)】: 采用 时序分块 (Time Chunking) 与 标的分桶 (Asset Bucketing) 的双轴切分架构进行按需加载。
【出参/效果 (Output)】: 控制单次内存占用，支持超大规模回测计算。
2. 微小价差精度保障
【入参 (Input)】: 低价资产 (仙股/仙币) 价格数据
【处理逻辑 (Process)】: 升位计算，底层存储和高频中间态统一转换为 Float64 或 Decimal 类型。
【出参/效果 (Output)】: 防止计算微小价差或收益率时发生 Float32 精度下溢 (Underflow)。
3. 跨时区与异步交易对齐
【入参 (Input)】: 跨时区、不同开盘时间的多资产价格序列
【处理逻辑 (Process)】: 统一转换为 UTC 时间戳，采用 ASOF JOIN (按时间就近匹配) 进行截面拼接，休市资产使用前向填充 (ffill) 并设置最大容忍天数。
【出参/效果 (Output)】: 产出时间严格对齐、无前视信息的截面切片。
4. NaN 与 Inf 极值清洗
【入参 (Input)】: 包含除以零等运算产生的 Inf 或 NaN 的原始因子序列
【处理逻辑 (Process)】: 截面计算前，将 np.inf 统一转为 NaN，并开启聚合函数的 skipna=True 机制。
【出参/效果 (Output)】: 输出干净的截面序列，防止单一极值污染整体分布。
II. 回测穿越机制阻断与双时态架构 (Point-in-Time Architecture)
1. 强一致性 PIT 审计键 (knowledge_ts)
【入参 (Input)】: 所有依赖宏观/财报等低频数据的高频特征
【处理逻辑 (Process)】: 强制区分 Observation Time (业务发生时间) 与 Knowledge Time (系统获知时间)，采用 ASOF JOIN 按照 knowledge_ts 进行拼接。
【出参/效果 (Output)】: 彻底杜绝因财报修正或宏观数据重述导致的“未来函数 (Look-ahead Bias)”。
2. 退市资产结算机制
【入参 (Input)】: 全市场历史存活与退市标的数据
【处理逻辑 (Process)】: 完整保留退市标的历史。在退市日当天，按退市清算价或设定比例 (如破产归零) 强制结算持仓。
【出参/效果 (Output)】: 产出包含真实破产损耗的组合收益，消除生存偏差 (Survivorship Bias)。
3. 复权与未复权数据分离使用
【入参 (Input)】: 历史未复权盘口价与前/后复权价
【处理逻辑 (Process)】: 计算截面收益与排序时采用前/后复权；但计算滑点、手续费与订单簿撮合时，采用未复权真实盘口价。
【出参/效果 (Output)】: 输出真实的模拟成交结果，避免因除权除息导致的虚假价差。
4. 标签 (Label) 收益严格对齐
【入参 (Input)】: T 日收盘生成的因子特征
【处理逻辑 (Process)】: T 日特征对应的预测目标对齐至 T+1 到 T+2 或 T+1 开盘到收盘 的真实可得收益。
【出参/效果 (Output)】: 生成干净、时间严格错开的特征-标签对 (Feature-Label Pair)。

【入参】: 同一时点多标的特征矩阵。
【核心逻辑】: 强制执行行业/市值中性化；计算 Rank IC (Spearman) 而非 Pearson；执行分位数多空回测 (Top-Bottom)；采用 Jackknife 进行 HAC 稳健标准误检验。

【入参】: 仅几十个活跃合约或三维曲面。

[6.2] B 轨: 时序基座与摩擦成本协议 (Time-Series Protocol)

[6.3] C 轨: 离散事件与规则协议 (Discrete Event Protocol)
C1-A: 纯离散状态轨
【特征】: 双均线金叉等纯状态 (-1,0,1)。
【核心逻辑】: 严禁计算 IC。采用状态机回测。计算 系统质量指数 (SQN) = $\sqrt{N} \cdot \frac{E(R)}{Std(R)}$。

C1-B: 强度加权规则轨
【特征】: 触发信号带有确信度大小。

C2: 宏观/基本面事件轨

【核心逻辑】: 必须使用“实际公告日”。计算 Event CAR (累计异常收益)。
【出参】: 事件发生后 T+1 到 T+N 的漂移轨迹与吸收半衰期。
C4: 模式识别轨

[14] 多因子组合与高级凸优化 (Portfolio Construction & Convex Optimization)
阶段说明：单因子的评估结束后，系统需要将因子群转化为实际的最优目标仓位权重 (Target Weights)。此阶段必须考虑协方差矩阵、微观摩擦损耗以及风险约束。
成本感知的凸优化器 (Cost-Aware Convex Optimizer)
【核心痛点】: 传统 Markowitz 均值方差模型会产生极高换手率，导致实盘净夏普崩塌。
【L1 范数惩罚】: 在目标函数中引入 $\lambda ||w_t - w_{t-1}||_1$。强制优化器进行惰性调仓 (Lazy Trading)，只有当预期 Alpha 超过边际交易成本时才允许换手。
【非线性成本惩罚】: 引入平方根冲击成本惩罚项 $c \cdot |w_t - w_{t-1}|^{1.5}$，防止大资金下单打穿订单簿。
鲁棒组合优化变体 (Robust Optimization)
【风险平价 (Risk Parity)】: 针对低频宏观因子，放弃收益预测，使各资产对组合的总风险贡献相等，实现极高抗脆弱性。
【Black-Litterman 模型】: 将量化挖掘出的历史均衡权重，与特定的事件驱动“主观观点 (Views)”进行贝叶斯融合。
【重采样技术 (Resampled Efficiency)】: 对预期收益和协方差矩阵进行蒙特卡洛扰动，降低参数估计误差 (Estimation Error) 导致的角点解 (Corner Solutions)。

[14.6] 极限压力测试与黑天鹅回放 (Extreme Stress Testing & Black Swan)

附录 3：核心量化评估指标数学定义字典 (Math Dictionary)

为防范实现歧义，下游 C++/Rust/Python 引擎在开发评估指标时，必须严格遵守以下数学定义与前提假设。

Deflated Sharpe Ratio (DSR)
【应用轨道】: 全局显著性红线
【数学公式】: $\text{DSR} = Z\left( \frac{(\widehat{SR} - SR_0)\sqrt{T-1}}{\sqrt{1 - \gamma_3 \widehat{SR} + \frac{\gamma_4 - 1}{4}\widehat{SR}^2}} \right)$
【工程红线】: 严禁仅汇报普通夏普！必须根据全局历史测试次数 (Multiple Testing) 计算期望夏普 $SR_0$，并使用偏度 $\gamma_3$ 和峰度 $\gamma_4$ 校正非正态惩罚。
Break-even IC (盈亏平衡 IC)
【应用轨道】: Track A, Track B
【数学公式】: $\text{IC}_{\text{BE}} = \frac{\text{Turnover} \cdot \text{Cost}}{\text{Volatility} \cdot \sqrt{M}}$
【工程红线】: 对于高换手因子，必须将实测 IC 与 BE-IC 比对。若实测 IC 小于此阈值，意味着策略预测能力连交易摩擦都无法覆盖，必须立即打回。
Non-linear Market Impact (非线性冲击)
【应用轨道】: 容量评估 / Sim2Real
【数学公式】: $\text{Cost} = \gamma \cdot \sigma \cdot \left( \frac{Q}{V} \right)^{0.5}$
【工程红线】: 严禁使用固定滑点！当单笔订单量 $Q$ 超过该 K 线均线成交量 $V$ 的特定阈值时，必须采用平方根法则模拟几何级增加的滑点成本，计算理论 AUM 上限。
Event CAR (事件累积异常收益)
【应用轨道】: Track C (离散事件轨)
【数学公式】: $CAR(t_1, t_2) = \sum_{t=t_1}^{t_2} (R_{i,t} - \hat{R}_{i,t})$
【工程红线】: 严禁将 $R_{i,t}$ 直接相加。必须通过 CAPM 或 Fama-French 模型计算出预期收益 $\hat{R}_{i,t}$ 并扣除，仅保留事件触发带来的“异常”增量收益。

1. OOM 熔断与降级策略
【场景】: 全市场 1min 级因子物化导致内存溢出。
【机制】: 底层检测到 RAM Usage > 90% 时触发熔断，终止当前大批量操作。系统自动捕获并切换为 时序分块 (Time Chunking) 与 标的分桶 (Asset Bucketing) 双轴切分模式重试计算。
2. 静默拦截语义区分
【场景】: 因子夏普率太低被拒 vs. 底层 ClickHouse 宕机。
【机制】: 强制区分状态码！业务拒绝必须返回特定的 BIZ_REJECTED，调度器收到后直接完结任务并打入负样本库；而基础设施错误 (如 DB_TIMEOUT) 则进入指数退避 (Exponential Backoff) 的无限重试队列。
3. 级联失效重算 (Cascading)
【场景】: 上游行情源发现 Bug 并重刷历史数据。
【机制】: 运维触发 Trigger_Data_Update，系统查询 Neo4j 血缘图谱，找出所有依赖该 data_lineage_version 的因子和模型，自动使历史缓存失效 (Invalidate) 并生成重算 DAG 提交给 Airflow。
4. 产物 Checksum 防篡改校验
【场景】: 内部人员尝试篡改 Parquet/JSON 报告以粉饰夏普率。
【机制】: 下游加载任何 Artifact 时，必须重新计算 SHA256 并与中心数据库中的 Manifest 校验。若 Hash 不匹配，直接抛出 FATAL_SECURITY_BREACH 告警至安全中心。
