# 企业级量化因子工厂开发排期与任务拆解

面向工程总监、项目经理、平台工程组、数据工程组和因子评估组。

## 1. 排期原则

首期建设采用“基于现有仓库增量扩展”的策略，而不是从零重做一个新平台。这样可以尽快拿到可运行成果，并减少和现有代码的割裂。

排期原则：

- 先统一对象与状态，再做高级能力。
- 先打通主链路，再扩展高级指标。
- 先保证可回放、可审计，再追求全量服务化。
- 先让 `candidate -> evaluation -> admission -> route` 跑通，再做复杂运营能力。

## 2. 首期目标

首期目标不是一次性建完全部企业平台，而是建成一条稳定可扩展的主线：

```text
多方法候选提交
-> 预检查与去重
-> 因子登记
-> 物化与发布
-> 标准评估
-> 准入与路由
-> 入核心库 / 卫星库 / 特征原料库 / 医院 / 归档库
```

## 3. 团队分工建议

| 角色 | 建议人数 | 主要职责 |
| --- | --- | --- |
| 工程总监 / Tech Lead | 1 | 对象模型、状态机、接口边界、发布审批 |
| 后端工程师 | 2-3 | 控制面、查询 API、路由、审计、配置中心 |

| 项目经理 | 1 | 里程碑管理、跨团队协调、依赖追踪 |

## 4. Epic 拆分

### E1 统一对象模型与配置中心

目标：冻结 `candidate / factor / evaluation / admission / route` 的对象、枚举和配置。

产出：

- 统一 schema 文档
- 统一枚举
- 配置模板
- 错误码表

优先级：`P0`

### E2 候选提交与预检查

目标：承接 24h 多方法候选提交，形成统一入口。

产出：

- Candidate Submission Schema
- 预检查模块
- 重复发现模块
- `candidate_registry`

优先级：`P0`

### E3 因子登记、血缘与批次管理

目标：让 `campaign / iteration / batch` 进入正式控制面。

产出：

- `factor_registry` 增强
- `factor_lineage`
- `experiment_registry`
- 血缘查询接口

优先级：`P0`

### E4 因子物化与发布主线

目标：复用现有 factor lake 和 `data_access`，补齐 staging -> publish 主线和运行索引。

产出：

- 标准物化任务
- staging / publish 规范
- run manifest
- watermark / schema 校验增强

优先级：`P0`

### E5 标准评估主线 v1

目标：以现有 `factor_evaluation` 为基线，形成稳定批量评估主线。

产出：

- 评估模板管理
- 运行编排
- 评估产物索引
- summary 和 manifest 标准化

优先级：`P0`

### E6 标签、准入与自动路由

目标：把评估结果转换为结构化决策，而不是停留在报表层。

产出：

- 标签规则引擎
- 准入规则引擎
- 路由执行器
- `routing_history`

优先级：`P1`

### E7 因子医院与修复重评

目标：给高潜但存在硬伤的因子提供修复闭环。

产出：

- 平滑
- 正交化
- 降频
- 修复后重评流程

优先级：`P1`

### E8 调度、队列与监控

目标：支撑 24h 持续生产。

产出：

- DAG 编排
- 消息队列
- 重试机制
- Kill-Switch
- 告警和可观测性

优先级：`P1`

### E9 美股专属增强项

目标：补齐更贴近实盘和研究治理的评估维度。

产出：

- borrow fee 相关指标
- SSR / 特殊交易日影响
- 更完整的容量与摩擦评估

优先级：`P2`

### E10 特征供给与聚合器回流

目标：支持 `tier3c_feature` 和更高层模型。

产出：

- feature store ready 索引
- 特征供给视图
- 聚合器产物回流登记

优先级：`P2`

## 5. Phase 规划

### Phase 1. 主链打通

建议周期：`4-6 周`

目标：先打通可运行主线。

包含：

- E1 统一对象模型
- E2 候选提交与预检查
- E3 血缘与批次管理
- E4 物化与发布主线
- E5 标准评估主线 v1

验收标准：

- 上游多方法候选可按 `campaign / iteration / batch` 提交
- 候选可通过预检查后进入因子湖
- 评估产物可稳定生成
- 可查看某个大轮下所有因子及其评估结果

### Phase 2. 准入与路由

建议周期：`4-6 周`

目标：从“能评估”提升到“能自动治理”。

包含：

- E6 标签、准入与自动路由
- 部分 E7 医院闭环基础能力
- 部分 E8 审计和监控基础能力

验收标准：

- 某因子评估完成后可自动生成准入决策
- 可自动路由到 core / satellite / feature / incubator / archive
- 所有路由动作有审计轨迹

### Phase 3. 24h 稳态运行

建议周期：`3-5 周`

目标：支撑持续生产和批量运行。

包含：

- E8 调度、队列、重试、Kill-Switch
- E7 医院重评闭环增强

验收标准：

- 支持 24h 多方法持续提交
- 支持任务重试和失败隔离
- 支持暂停生产路由和恢复

### Phase 4. 高级评估与特征供给

建议周期：`4-6 周`

目标：做强评估厚度和下游供给能力。

包含：

- E9 美股专属增强项
- E10 feature store 和聚合回流

验收标准：

- `tier3c_feature` 有明确供给出口
- 聚合器输出可回流为新因子对象
- 高级摩擦与容量指标可以按模板扩展

## 6. Story 拆分建议

### E2-S1 候选提交接口

- 支持 `method / campaign / iteration / batch`
- 支持 schema 校验
- 支持幂等写入

### E2-S2 预检查与去重

- 支持 AST 深度检查
- 支持估算复杂度预算
- 支持重复发现结果记录

### E3-S1 因子登记与血缘

- 分配 `factor_id`
- 记录 `parent_factor_ids`
- 记录 `relation_type`

### E4-S1 staging -> publish 主线增强

- 统一 publish 入口
- 统一 run manifest
- 统一 schema / row count 校验

### E5-S1 评估模板管理

- 支持模板列表和版本
- 支持按模板发起评估
- 产出标准 MetricsPackage

### E6-S1 标签规则引擎 v1

- 根据 summary 生成标签
- 标签可回写 catalog
- 标签规则版本可追踪

### E6-S2 自动路由执行器 v1

- 根据 AdmissionDecision 执行状态迁移
- 生成 `routing_history`

## 7. 关键依赖关系

| 上游任务 | 下游任务 | 原因 |
| --- | --- | --- |
| E1 对象模型 | 全部后续 Epic | 字段和枚举不稳定会导致返工 |
| E2 候选提交流程 | E3 / E4 / E5 | 没有统一入口就无法统一治理 |
| E3 血缘与批次管理 | E5 / E6 / 运营查询 | 不记录 campaign/iteration 无法复盘 |
| E4 物化与发布 | E5 评估 | 没有稳定 factor lake 就无法批量评估 |
| E5 评估 | E6 路由 | 没有统一指标就无法贴标签和准入 |
| E6 路由 | E7 医院闭环 | 没有自动路由就无法进入修复流程 |
| E8 调度 | 全链路稳态运行 | 没有调度和重试无法支撑 24h 持续运行 |

## 8. 风险与缓释

| 风险 | 影响 | 缓释动作 |
| --- | --- | --- |
| 未冻结 `campaign / iteration / batch` | 大轮和迭代不可回溯 | Phase 1 先冻结对象字段 |
| 评估模板频繁变动 | 指标不可比 | 评估模板版本化 |
| 先设计过重服务化架构 | 首期无法落地 | 先按 V1 文件湖和 catalog 跑通 |
| 候选提交体不统一 | 无法收敛多方法来源 | 强制 Candidate Submission Schema |
| 路由规则写死 | 后续维护困难 | 标签和路由规则配置化 |
| 评估任务抢占资源 | 24h 稳态受影响 | 复杂度预算 + 队列分层 + Kill-Switch |

## 9. 验收清单

### Phase 1 验收

- 能按 `method / campaign / iteration / batch` 查询候选和正式因子
- 能从候选提交一路跑到评估产物
- 能查看单个大轮形成的因子库

### Phase 2 验收

- 能根据评估结果自动打标签和准入
- 能自动路由到不同 tier
- 能记录路由历史和状态变化

### Phase 3 验收

- 支持 24h 持续运行
- 支持任务失败重试
- 支持暂停和恢复

### Phase 4 验收

- 特征原料库可被下游检索和消费
- 聚合器回流路径可用
- 高级评估项可按模板接入

## 10. 结论

排期的核心不是把所有愿景一次性摊开，而是先围绕“持续产生候选、大轮形成因子库、统一评估并自动路由”这条主线逐段打通。只要这条主线建稳，后续扩展到更多市场、频率、方法和模型都只是增量工作。
