# `data_access` 团队使用规范

> **适用范围**：所有在 `(base) yluel@mafm2` 这台共享账号上跑量化代码的人。
>
> 读之前你需要知道的事：这台机器大家共用一个 Linux 账号，$HOME 也是共用的，
> 磁盘在 `/home/yluel/share/projects/` 下是大家共享的 ext4（不是 NFS）。
> 也就是说：**你 rm 一个目录，全团队都看不到了**。这个规范就是为防止这类事故写的。

---

## 1. 硬性规则（不遵守会踩到别人）

### 1.1 读写数据必须走 `data_access.get_store()`

**禁止**在业务代码里直接写 `pd.read_parquet / pq.read_table / duckdb.connect /
pd.DataFrame.to_parquet / pq.write_table`。例外**必须**出现在仓库根的
`.data_access_allowlist.yaml` 里（PR4 起）：

- `data_access/` 模块自己（它就是干这个的）
- `streaming/` 各 writer（tmp+rename / append-only 的原子协议，不适合 write_arrow）
- `raw_data_layer/raw_data_cleaning/` 的 per-file 清洗（和 data_access glob 聚合语义不匹配）

**新增豁免 = 提 PR，在 `.data_access_allowlist.yaml` 加一行 + 说明理由**；
评审人把关，尽量不开口子。PR6 会上静态检查，清单外直读会 CI fail。

**为什么**：直接读绕开了路径白名单、绕开了 DuckDB footer 缓存、绕开了谓词下推。
直接写绕开了审计日志、绕开了 namespace 隔离、绕开了 `published` 保护。
单人用没问题，十个人一起跑就会:

- 全进程各自开 DuckDB，内存翻十倍
- 每次读都重扫 parquet footer，慢 10x
- 路径改了所有代码都要改
- 因子出问题没法追是谁哪次写崩的

### 1.2 绝对不要往 `published` 数据集的目录里写东西

`config/datasets.yaml` 里 `access_mode: published` 的路径（比如 `massive_parquet/` 下
的清洗后行情、`factor_lake/factors/<已发布 id>/`）**只读**。

`store.write_arrow("factor_lake", ...)` 和 `store.upsert("factor_lake", ...)` 都会直接
raise `ValidationError("published, 不允许直写...")`，这是硬防线，别试图绕开。

要发布新产物 → **PR3 起用 `store.publish_from_staging(staging_name, published_name, ...)`**
（原子切换 + 旧版本归档到 `_archive/` + 并发锁 + 校验失败自动回滚）。
要做实验 → 写到 `namespaced` 路径（见 1.3）。

### 1.3 个人实验数据必须带 namespace

namespaced 路径模板形如：

```
${WORKSPACE}/users/${RUN_NAMESPACE}/backtests/.../*.parquet
```

`${RUN_NAMESPACE}` 的取值顺序（见 `namespace.py`）：

1. 环境变量 `QUANT_RUN_NAMESPACE`（**推荐**，一次 `export` 就够）
2. 兜底 `anon__<git-branch>__<pid>`

**推荐在你的 shell rc 里加一行**：

```bash
# ~/.bashrc 或 ~/.zshrc
export QUANT_RUN_NAMESPACE="shw"          # 换成你自己的花名/拼音，例如 shw
export QUANT_OPERATOR="shw@team"          # 可选，审计日志里会带
```

因为 `$HOME` 是共享的，**不要**依赖 `~/.quant_user_alias` 这种文件方式。
环境变量每个 shell 一份，天然隔离。

### 1.4 并发跑是正常操作，但别共用同一个 namespace

两个同事同时 export 了 `QUANT_RUN_NAMESPACE=aaa` 去跑写路径，会互相覆盖。
选 namespace 时用一个别人不会重的名字（花名 / 拼音 / `<name>-<任务代号>`）。

### 1.5 不要在代码里写死绝对路径

用 `datasets.yaml` 登记 + `${VAR:-default}` 展开。想看展开后的路径：

```python
from data_access import get_store
ds = get_store()._registry.get("us_stocks_sip_day_aggs")
print(ds.resolve_paths())
```

## 2. 选 API 的口诀

| 场景 | 用什么 |
|---|---|
| 画图、存 CSV、末端查看 | `read_frame()` |
| pipeline 中段要继续传给下一步 | `read_arrow()` |
| 因子引擎、要 `(ts, instrument)` MultiIndex Series | `load_columns()` |
| 单列读（老 API 兼容） | 走 `factor_engine` 的 `ParquetSource.load_column()` 即可，底层会复用 `load_columns` |
| 写个人回测结果 / 实验产物 | `write_arrow(namespaced 数据集, ..., mode="overwrite")` |
| 写待发布的因子（带分区） | `write_arrow(staging 数据集, ..., partition_by=["year"])` |
| 增量算完 merge 进已有目录（去重、保留旧键） | `upsert(staging 数据集, ..., upsert_on=[...])` |
| 发布 staging → published（原子切换 + 归档） | `publish_from_staging(staging_name, published_name, ...)` |
| 临时 ad-hoc 分析（GROUP BY / JOIN 等） | `sql("SELECT ...", read_datasets=[...], params=[...])` |

**一个重要反模式**：不要 `for col in cols: df = read_frame(ds, columns=[col])`。
每次调用都要重开 DuckDB 游标，虽然有 footer 缓存但仍有解码开销。
正确写法：一次传 `columns=[col1, col2, ...]`，DuckDB 内部并行读。

**写的反模式**：不要 `for chunk in chunks: write_arrow(ds, chunk, mode="append")` 当临时流式写。
如果数据够大需要分批，应该：先在内存拼成一个 `pa.Table`，或者直接带 `partition_by` 让 pyarrow
按分区写小文件。大量 append 会在目录下堆碎文件，后面读的人要吞下这个代价。

## 3. 排障 FAQ

### 「找不到数据集 'xxx'：未注册」

`datasets.yaml` 里没有 `xxx` 这个 key，或者你用的是不同的 YAML。
注意 `load_registry()` 默认找 `data_access/config/datasets.yaml`，
如果你 export 了 `QUANT_DATASETS_YAML` 会优先读你指定的那个。

### 「data_access.exceptions.DataError: 数据集 'xxx' 在给定条件下读出 0 行」

不是代码 bug，是你的 `time_range / instrument_filter` 把所有行都筛掉了。
先不加过滤条件读一次，看看文件里到底有什么。

### 「读同一批 parquet 第二次明显比第一次慢」

极少见，通常是 DuckDB 连接被 reset 了。检查：

- 是不是在测试代码里手动调了 `reset_store()` / `reset_shared_engine()`
- 是不是 fork 了子进程（子进程的 buffer pool 是空的）

### 「多线程跑突然报 DuckDB 错误」

我们用 `conn.cursor()` 每查询一个 cursor，线程安全的。如果仍然出错，
一般是写路径被并发走了（PR2 开始允许写）——同一个 `target_dir` 两个线程同时 `overwrite`
必然互相踩脚。把报错贴到 `#quant-platform`。

### 「我的 `write_arrow` 打了 warning 说 namespace 不是显式的」

你忘了 `export QUANT_RUN_NAMESPACE=shw`。写能成功，但路径用的是兜底 `anon__<branch>__<pid>`，
别人（和审计日志）都追不到是你写的。补上 export 重跑一遍。

### 「我想看自己今天写过哪些数据集」

```bash
jq 'select(.namespace=="shw" and .op=="write" and (.ts | startswith("2026-04-19")))' \
    ${QUANTSOCIETY_WORKSPACE_DATA_ROOT:-./workspace_data}/logs/data_access_audit.jsonl
```

审计日志是 append-only JSONL，失败的写也在里面（`ok: false` + `error` 字段）。
