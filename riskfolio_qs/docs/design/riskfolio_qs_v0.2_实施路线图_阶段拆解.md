# riskfolio_qs v0.2 实施路线图

## 1. 目标

v0.2 的目标不是直接写实现代码，而是先把“配置驱动的组合优化系统”按可落地顺序拆清楚，再逐步实现。

整体实施顺序如下：

1. 先定义优化目标与约束的完整规范。
2. 再明确需要的数据格式、数据源和适配器。
3. 再冻结合约模式下的默认参数。
4. 然后接通上游数据与适配器。
5. 最后实现优化器、约束扩展层与主入口执行链路。

---

## 2. 第一阶段：优化目标规范化

这一阶段只做定义，不做实现。

### 2.1 先定义最小可交付目标单元

需要先明确系统到底支持哪些目标函数和硬约束。建议从实际使用最频繁的最小集合开始：

1. 目标函数
1. mean_variance
2. min_variance
3. max_sharpe / risk_adjusted_return
4. index_enhancement / benchmark_tracking

2. 约束
1. 换手约束，区分软约束与硬约束。
2. 市值中性 / 市场中性 / 行业中性。
3. 最大个股仓位。
4. 交易成本控制。
5. 预算约束、净敞口约束、行业暴露区间约束。

### 2.2 规范化文档内容

这一份规范文档要写清楚：

1. 每个目标函数的数学含义。
2. 每个硬约束的业务含义与数学表达。
3. 哪些参数属于目标函数内部参数，哪些属于外部约束参数。
4. 哪些约束必须由内核扩展实现，不能只依赖现成 Riskfolio 接口。

### 2.3 合约模式的冻结参数

对指增、低波增强、行业中性、多空等实际场景，要冻结默认参数表。

合约模式要满足：

1. 用户只输入策略名，不手写底层参数。
2. 系统从注册表直接索引默认目标函数、约束、求解器参数。
3. 后续只允许做参数覆盖，不允许改变合约语义。

---

## 3. 第二阶段：数据规范与数据源

### 3.1 需要的数据类型

至少要定义这些输入数据：

1. alpha 信号文件。
2. 行情文件。
3. 风险因子文件。
4. 行业分类文件。
5. 基准持仓文件。
6. 上期持仓文件。
7. 可交易状态文件。

### 3.2 数据格式约束

每类数据都需要明确：

1. 主键字段。
2. 日期频率。
3. 资产编码规则。
4. 必填字段与可选字段。
5. 缺失值语义。

### 3.3 数据来源状态

这一阶段要同步梳理：

1. 哪些数据已经有稳定上游。
2. 哪些数据需要新找上游源。
3. 哪些数据只能先用 mock 或 sample 数据替代。

### 3.4 数据适配器任务

适配器要负责把上游原始数据统一成标准输入协议，至少要解决：

1. 路径解析。
2. 格式读取。
3. 字段映射。
4. 日期与资产对齐。
5. 缺失与异常校验。

---

## 4. 第三阶段：预置合约模式

### 4.1 预置模式定义

预置模式就是策略名直达参数模板，例如：

1. minvar_enhance_index。
2. topn_long_only_equal_weight。
3. topn_long_short_equal_weight。
4. classic_sharpe_absolute。

### 4.2 预置模式应包含的内容

1. 目标函数类型。
2. 风险模型类型。
3. 硬约束模板。
4. 默认求解器参数。
5. 默认数据前置要求。

### 4.3 预置模式的工程原则

1. 预置参数必须表格化、注册化。
2. 预置模式不能依赖人工拼源码。
3. 预置模式和目标函数模式底层必须收敛到同一套内部参数对象。

---

## 5. 第四阶段：内核约束扩展

这一阶段只针对“Riskfolio 原生接口不够用”的情况。

### 5.1 原则

1. 外层接口始终保持参数化。
2. 内核如果缺少硬约束，允许在 vendor/riskfolio 中扩展。
3. 扩展必须可追踪、可回归、可回滚。
4. 约束实现必须进入统一注册表，而不是散落在业务层。

### 5.2 需要关注的约束扩展

1. 市值中性 / 市场中性 / 行业中性。
2. 最大个股仓位。
3. 交易成本控制。
4. 指数增强中的跟踪类约束。
5. 更细粒度的组合暴露区间控制。

---

## 6. 第五阶段：主流程实现

### 6.1 执行链路

1. CLI 或 run.py 读取配置文件。
2. 解析输入路径或输入目录。
3. 加载并校验数据。
4. 根据合约模式或目标函数模式装配优化器。
5. 编译约束。
6. 调用内核求解。
7. 输出目标仓位到指定路径。

### 6.2 输出要求

1. 目标仓位宽表。
2. 调仓表。
3. 组合摘要表。
4. 审计元数据表。
5. 运行日志。

---

## 7. 推荐实施顺序

建议按以下顺序推进：

1. 优化目标规范文档。
2. 数据协议与字段字典。
3. 预置合约参数表。
4. 数据源清单与适配器。
5. 约束扩展层。
6. CLI / run.py 主入口。
7. 输出落盘与审计。

---

## 8. 阶段划分结论

这个实施路线图的核心是：

1. 先定目标和边界。
2. 再定数据与合约。
3. 再接上游与适配器。
4. 最后实现代码和内核扩展。

这样可以保证 v0.2 既能服务研究，也能服务生产。
