# 组合优化器实现方案 v0.1

本文档定义 `riskfolio_qs` 的组合优化器实现方案。

该方案承接以下已冻结文档：

1. [组合优化与回测接口协议_v0.1.md](组合优化与回测接口协议_v0.1.md)
2. [组合优化器方案_v0.1.md](组合优化器方案_v0.1.md)
3. [上游信号平滑与换手门控方案_v0.1.md](上游信号平滑与换手门控方案_v0.1.md)

目标是把“上游 alpha 信号 + 行业/风格标签 + 行情数据”转化为“可直接下游回测消费的目标持仓数据”。

---

## 1. 实现目标

1. 接收标准输入 bundle。
2. 先做信号换手检测，必要时执行 EMA 平滑。
3. 按 alpha 类型路由到对应 benchmark。
4. 在冻结硬约束模板下求解组合。
5. 输出标准化持仓、调仓、摘要、审计元数据。
6. 与 `vectorbt_qs` 直接对接。

---

## 2. 实现范围

### 2.1 v0.1 必做

1. 标准输入校验。
2. 信号平滑器。
3. 模型路由器。
4. benchmark 路由器。
5. 硬约束模板。
6. 输出适配器。
7. 回退机制。
8. 最小闭环测试。

### 2.2 v0.1 不做

1. TE 约束。
2. 流动性 / ADV 约束。
3. 指数锚定约束。
4. 行业中性 / 风格中性约束。
5. 复杂自定义求解器插件系统。

### 2.3 vendor 源码策略

v0.1 采用“源码 vendor + 外围适配”的方式实现组合优化器内核。

#### 2.3.1 设计原则

1. 将 Riskfolio-Lib 原始源码复制到 `riskfolio_qs/vendor/riskfolio`。
2. `vendor` 目录只承载上游源码和必要的最小补丁，不承载业务逻辑。
3. 业务逻辑统一放在 `core`、`adapters`、`smoothers`、`optimizers`、`constraints`、`runners`。
4. 对 vendor 的修改必须可追踪、可回滚、可与上游 diff 对比。
5. 后续升级上游版本时采用“同步上游 + 差异评审 + 局部补丁回迁”的方式。

#### 2.3.2 vendor 目录建议

```text
riskfolio_qs/
├── vendor/
│   └── riskfolio/
│       ├── src/
│       ├── external/
│       ├── README.md
│       └── LICENSE.md
```

#### 2.3.3 改造边界

1. 默认不改 vendor 内核的求解逻辑。
2. 只在必要时对 vendor 做最小补丁，例如导出接口、路径兼容、少量 bug fix。
3. 任何业务相关的 benchmark 路由、约束模板、门控策略都不得写入 vendor。
4. 如果需要做大改动，优先通过外围适配层解决，而不是直接修改 vendor。

#### 2.3.4 依赖方式

业务代码在运行时从本地 `vendor/riskfolio` 导入，而不是依赖外部已安装的 Riskfolio-Lib 包。

建议后续统一由 `riskfolio_qs` 自己控制 Python 导入顺序，保证 vendor 版本优先。

## 4. 核心数据流

### 4.1 输入

输入为标准输入 bundle，至少包含：

1. alpha 表。
2. 行情表。
3. 行业标签表。
4. 风格暴露表。
5. 基准持仓表（可选）。
6. 上期持仓表（可选）。
7. 可交易状态表（可选）。

### 4.2 处理流程

```text
标准输入 bundle
    ↓
Schema 校验
    ↓
SignalSmoother 检测 TopN 平均换手率
    ↓
若触发阈值 → EMA 平滑
    ↓
OptimizerRouter 按 alpha 类型路由
    ↓
BenchmarkRouter 选择 benchmark
    ↓
ConstraintBuilder 注入冻结硬约束
    ↓
Riskfolio 求解
    ↓
OutputAdapter 生成标准输出 bundle
    ↓
vectorbt_qs 回测
```

## 5. 模块实现方案

### 5.1 `core`

#### 5.1.1 `contracts.py`

定义标准输入 / 输出 bundle 的字段合同。

建议包含：

1. `InputBundle`
2. `OutputBundle`
3. `OptimizationContext`
4. `RunMetadata`

#### 5.1.2 `schema.py`

定义字段类型、索引要求、缺失值语义、对齐规则。

#### 5.1.3 `validator.py`

负责校验：

1. 日期是否单调递增。
2. 资产代码是否一致。
3. 是否存在 inf / 全 NaN。
4. 是否满足最小字段要求。
5. 各表是否可同日对齐。

---

### 5.2 `adapters`

#### 5.2.1 `input_adapter.py`

职责：把上游原始数据转成标准输入 bundle。

v0.1 先只定义接口，具体实现可以留空或用 MockAdapter 代替。

#### 5.2.2 `output_adapter.py`

职责：把优化器结果转成下游 `vectorbt_qs` 可消费的格式。

最少输出：

1. 目标持仓宽表。
2. 调仓表。
3. 组合摘要表。
4. 审计元数据表。

#### 5.2.3 `mock_adapter.py`

职责：生成假数据，跑通端到端闭环。

用于：

1. 没有真实上游数据时的联调。
2. 单元测试。
3. CI 验证。

---

### 5.3 `smoothers`

#### 5.3.1 `signal_smoother.py`

职责：

1. 计算 TopN 平均换手率。
2. 判断是否触发 EMA 平滑。
3. 输出平滑后的 alpha。

默认逻辑：

1. `topn_n = 50`
2. `turnover_window = 5`
3. `turnover_threshold = 0.30`
4. `ema_span = 5`
5. `mode = auto`

---

### 5.4 `optimizers`

#### 5.4.1 `optimizer_router.py`

职责：

1. 读取 alpha 类型配置。
2. 判断 `alpha_is_absolute_return`。
3. 选择对应 benchmark 路由。

#### 5.4.2 `benchmark_router.py`

职责：

1. 仅排序 / zscore 场景 benchmark 路由。
2. 真实尺度收益场景 benchmark 路由。
3. 返回统一的 benchmark 配置对象。

#### 5.4.3 `portfolio_optimizer.py`

职责：

1. 调用 Riskfolio-Lib。
2. 组装目标函数。
3. 组装风险模型。
4. 注入硬约束模板。
5. 返回权重结果。

#### 5.4.4 `risk_model_builder.py`

职责：

1. 历史协方差构建。
2. Barra / 因子协方差构建。
3. BL / FM / EP 需要的统计量预处理。

#### 5.4.5 `objective_builder.py`

职责：

1. 构造 `MinRisk`。
2. 构造 `Sharpe`。
3. 构造 `Utility`。
4. 构造 `MaxRet`。

---

### 5.5 `constraints`

#### 5.5.1 `constraint_templates.py`

v0.1 冻结模板：

1. 预算约束：`1.00`
2. 单票上限：`0.05`
3. 换手上限：`0.20`

适用 benchmark：

1. TopN 纯多等权。
2. Min Risk（历史版）。
3. Min Risk（Barra 版）。
4. Sharpe。
5. Utility。
6. Risk Parity。
7. HRP / HERC / NCO。

#### 5.5.2 `constraint_builder.py`

职责：

1. 将模板转成优化器可用的参数。
2. 保证同一 benchmark 家族内约束值固定。
3. 保留后续扩展接口。

---

### 5.6 `runners`

#### 5.6.1 `pipeline.py`

职责：

1. 串联输入、平滑、优化、输出。
2. 支持单日执行与批量回放。
3. 统一返回 `OutputBundle`。

---

## 6. Benchmark 实现路由

### 6.1 alpha_is_absolute_return = True

默认 benchmark：

1. `Classic + Sharpe`
2. `Classic + Utility`
3. `FM + Sharpe`
4. `BL + Sharpe`
5. `RP`
6. `HRP`

### 6.2 alpha_is_absolute_return = False

默认 benchmark：

1. `TopN 纯多等权`
2. `TopN 多空等权`
3. `Min Risk（历史版）`
4. `Min Risk（Barra 版）`
5. `RP`
6. `HRP`

可选扩展：

1. `Min Risk + alpha tilt`
2. `TE-min + alpha tilt`（后续版本）

---

## 7. 信号门控实现方案

### 7.1 逻辑

1. 先计算 TopN 平均换手率。
2. 若平均换手率超过阈值，则启用 EMA。
3. 否则直接使用原始信号。

### 7.2 推荐默认值

1. `topn_n = 50`
2. `turnover_window = 5`
3. `turnover_threshold = 0.30`
4. `ema_span = 5`
5. `mode = auto`

---

## 8. 输出实现方案

优化器输出必须统一成标准输出 bundle：

1. 目标持仓宽表。
2. 调仓表。
3. 组合摘要表。
4. 审计元数据表。

其中下游 `vectorbt_qs` 最核心的输入是：

| index | columns | values |
|------|---------|--------|
| date | asset | target_weight |

## 9. 降级与回退方案

### 9.1 优化不可行时

如果某个 benchmark 在冻结硬约束下不可行：

1. 记录不可行状态。
2. 不自动修改约束。
3. 回退到同家族的更稳健 benchmark，或返回空结果并标记失败。

### 9.2 信号平滑不可用时

如果平滑器无法判断换手或无法计算 EMA：

1. 直接使用原始信号。
2. 在审计元数据中记录 `fallback_used = True`。

### 9.3 输入缺失时

若行业、风格、基准或持仓信息缺失：

1. 只启用当前模型必需字段。
2. 其余部分保持留白。

## 11. 结论

v0.1 的实现方案应当坚持以下原则：

1. 先做协议，再做实现。
2. 先做门控，再做优化。
3. 先固定 benchmark 和硬约束，再谈扩展。
4. 先打通最小闭环，再逐步增加复杂度。

只要按照这个顺序推进，`riskfolio_qs` 就可以稳定地从上游 alpha、行业、风格与行情数据，生成可直接供下游回测使用的目标持仓数据。
