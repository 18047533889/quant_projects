# 组合优化与回测接口协议 v0.1

本文档定义 `riskfolio_qs` 的标准输入协议、标准输出协议，以及与下游 `vectorbt_qs` 的对接契约。

目标是把上游 alpha 信号、行业标签、风格暴露、行情数据统一洗成标准格式，再由组合优化器输出统一的目标持仓数据，最后交给回测框架直接消费。

---

## 1. 设计原则

1. 协议优先，适配器留白。
2. 优化内核与数据源解耦。
3. 上游输入与下游输出都采用宽表加审计元数据的方式。
4. 所有协议都必须支持样本外滚动回放。
5. 默认以日频为主，允许扩展到分钟频或周频，但同一条流水线内频率必须一致。

---

## 2. 系统分层

### 2.1 输入侧

上游数据进入 `riskfolio_qs` 后，先经过数据适配层，转换为标准输入协议。

### 2.2 优化侧

标准输入协议进入组合优化器，生成目标权重与组合级摘要。

### 2.3 输出侧

优化结果经过输出适配层，洗成 `vectorbt_qs` 可直接消费的目标持仓宽表和调仓表。

---

## 3. 标准输入协议 v0.1

### 3.1 通用约定

统一以“长表”或“宽表”表达，但所有参与优化的核心表必须满足以下约束：

1. 主键必须可唯一定位到 `date + asset`。
2. 日期必须是交易日，类型统一为 `datetime64[ns]`。
3. 资产代码必须统一命名体系，且与行情数据一致。
4. 输入表之间必须支持同日对齐。
5. 缺失值必须有明确语义，不能混用。

### 3.2 alpha 信号表

#### 3.2.1 作用

承接上游模型输出的 alpha 或打分信息。

#### 3.2.2 推荐结构

长表：

| 字段 | 类型 | 含义 |
|------|------|------|
| date | datetime64[ns] | 交易日 |
| asset | string | 资产代码 |
| alpha_raw | float64 | 原始 alpha 值 |
| alpha_rank | float64 | 横截面排序百分位，可选 |
| alpha_z | float64 | 横截面标准化值，可选 |
| alpha_side | int | 方向标签，可选，1=做多，-1=做空，0=中性 |
| alpha_version | string | 模型版本号 |

#### 3.2.3 最低要求

至少要有一个可用列：`alpha_raw`、`alpha_rank`、`alpha_z` 中的任意一个。

#### 3.2.4 语义建议

1. 若上游仅提供排序信息，优先使用 `alpha_rank`。
2. 若上游提供 zscore 后信号，优先使用 `alpha_z`。
3. 若上游提供可解释预期收益，才使用 `alpha_raw` 进入收益项。

### 3.3 行情表

#### 3.3.1 作用

提供收益率、价格、波动率和成交可行性判断的基础数据。

#### 3.3.2 推荐结构

| 字段 | 类型 | 含义 |
|------|------|------|
| date | datetime64[ns] | 交易日 |
| asset | string | 资产代码 |
| open | float64 | 开盘价 |
| high | float64 | 最高价 |
| low | float64 | 最低价 |
| close | float64 | 收盘价 |
| adj_close | float64 | 复权收盘价，可选 |
| volume | float64 | 成交量 |
| ret_1d | float64 | 日收益率，可选 |
| tradable | bool | 是否可交易，可选 |

#### 3.3.3 最低要求

至少应提供 `close` 或 `adj_close`，并能计算组合所需收益或风险输入。

### 3.4 行业标签表

#### 3.4.1 作用

用于行业中性、行业上下限、行业偏离控制。

#### 3.4.2 推荐结构

| 字段 | 类型 | 含义 |
|------|------|------|
| date | datetime64[ns] | 交易日 |
| asset | string | 资产代码 |
| industry_level_1 | string | 一级行业 |
| industry_level_2 | string | 二级行业，可选 |
| industry_code | string | 行业编码 |

#### 3.4.3 约定

1. 同一交易日内，行业标签必须能映射到 one-hot 或分组矩阵。
2. 标签变更必须有时间戳，不允许使用未来行业信息。

### 3.5 风格暴露表

#### 3.5.1 作用

用于风格中性、风格限幅、因子暴露控制。

#### 3.5.2 推荐结构

| 字段 | 类型 | 含义 |
|------|------|------|
| date | datetime64[ns] | 交易日 |
| asset | string | 资产代码 |
| size | float64 | 市值因子暴露 |
| value | float64 | 价值因子暴露 |
| momentum | float64 | 动量因子暴露 |
| volatility | float64 | 波动率因子暴露 |
| liquidity | float64 | 流动性因子暴露 |
| beta | float64 | 市场 beta 暴露 |

#### 3.5.3 约定

1. 风格暴露矩阵默认按横截面标准化。
2. 如果使用 Barra 原始暴露，必须在适配层统一标准化后再进入优化器。

### 3.6 基准持仓表

#### 3.6.1 作用

用于相对基准中性、跟踪误差约束、主动组合约束。

#### 3.6.2 推荐结构

| 字段 | 类型 | 含义 |
|------|------|------|
| date | datetime64[ns] | 交易日 |
| asset | string | 资产代码 |
| benchmark_weight | float64 | 基准权重 |

### 3.7 上期持仓表

#### 3.7.1 作用

用于换手约束、交易成本估计、再平衡优化。

#### 3.7.2 推荐结构

| 字段 | 类型 | 含义 |
|------|------|------|
| date | datetime64[ns] | 交易日 |
| asset | string | 资产代码 |
| prev_weight | float64 | 上期目标权重或真实持仓权重 |

### 3.8 可交易状态表

#### 3.8.1 作用

用于剔除不可交易标的，或限制目标权重的可达性。

#### 3.8.2 推荐结构

| 字段 | 类型 | 含义 |
|------|------|------|
| date | datetime64[ns] | 交易日 |
| asset | string | 资产代码 |
| tradable | bool | 是否可交易 |
| suspend | bool | 是否停牌，可选 |
| limit_up | bool | 是否涨停，可选 |
| limit_down | bool | 是否跌停，可选 |
| is_st | bool | 是否 ST，可选 |

## 4. 标准输出协议 v0.1

组合优化器输出不直接给回测框架，而是先生成标准输出协议，再由输出适配层转换。

### 4.1 目标持仓表

#### 4.1.1 作用

这是下游回测最核心的输入之一，必须能直接转成 `date x asset` 宽表。

#### 4.1.2 推荐结构

| 字段 | 类型 | 含义 |
|------|------|------|
| date | datetime64[ns] | 目标调仓日 |
| asset | string | 资产代码 |
| target_weight | float64 | 目标权重，允许为负 |
| target_value | float64 | 目标市值，可选 |
| side | string | long / short / flat |
| model_id | string | 模型名 |
| alpha_version | string | alpha 版本 |
| risk_model | string | 风险模型 |
| rebalance_id | string | 调仓批次 ID |

#### 4.1.3 宽表形式

下游 `vectorbt_qs` 最终消费的是宽表：

| index | columns | values |
|------|---------|--------|
| date | asset | target_weight |

### 4.2 调仓表

#### 4.2.1 作用

用于记录每次从上期持仓到目标持仓的变化。

#### 4.2.2 推荐结构

| 字段 | 类型 | 含义 |
|------|------|------|
| date | datetime64[ns] | 调仓日 |
| asset | string | 资产代码 |
| prev_weight | float64 | 上期权重 |
| target_weight | float64 | 目标权重 |
| delta_weight | float64 | 变化量 |
| trade_side | string | buy / sell / short / cover |
| trade_value | float64 | 交易金额，可选 |
| estimated_cost | float64 | 预估交易成本，可选 |

### 4.3 组合摘要表

#### 4.3.1 作用

记录每个调仓日的组合级统计，便于审计和回测日志对齐。

#### 4.3.2 推荐结构

| 字段 | 类型 | 含义 |
|------|------|------|
| date | datetime64[ns] | 调仓日 |
| gross_exposure | float64 | 总敞口 |
| net_exposure | float64 | 净敞口 |
| turnover | float64 | 换手率 |
| te_estimate | float64 | 跟踪误差估计 |
| expected_return_estimate | float64 | 预期收益估计，可选 |
| risk_estimate | float64 | 风险估计 |
| feasible_flag | bool | 是否可行 |

### 4.4 审计元数据表

#### 4.4.1 作用

保证实验可复现。

#### 4.4.2 推荐结构

| 字段 | 类型 | 含义 |
|------|------|------|
| date | datetime64[ns] | 调仓日 |
| model_id | string | 模型名 |
| alpha_version | string | alpha 版本 |
| constraint_profile | string | 约束模板名 |
| solver | string | 求解器名 |
| solve_status | string | 求解状态 |
| solve_time_ms | float64 | 求解耗时 |
| fallback_used | bool | 是否触发回退策略 |

## 5. 与 vectorbt_qs 的对接关系

`vectorbt_qs` 当前的核心回测输入是 `date x asset` 形态的目标权重宽表。

因此，`riskfolio_qs` 的输出适配层只需要做两件事：

1. 把标准输出协议中的“目标持仓表”整理成宽表。
2. 把调仓表、组合摘要表、审计元数据表作为附属输出，供回测与日志系统使用。

### 5.1 最终下游主输入

| index | columns | values |
|------|---------|--------|
| date | asset | target_weight |

### 5.2 与约束处理的关系

下游 `vectorbt_qs` 会基于目标权重宽表继续做市场侧约束，例如：

1. A 股停牌过滤
2. A 股涨跌停价约束
3. A 股手续费与整手
4. 美股 SSR 限制
5. 美股 ADR 去重

所以 `riskfolio_qs` 只需保证目标权重的语义正确，不需要替下游重复处理交易引擎层约束。

## 6. 适配层接口设计

### 6.1 输入适配器

输入适配器负责把上游原始数据洗成标准输入协议。

建议定义如下接口：

```python
class InputAdapter:
    def load_alpha(self, date_range, assets):
        raise NotImplementedError

    def load_market(self, date_range, assets):
        raise NotImplementedError

    def load_industry(self, date_range, assets):
        raise NotImplementedError

    def load_style(self, date_range, assets):
        raise NotImplementedError

    def load_benchmark(self, date_range, assets):
        raise NotImplementedError

    def load_prev_positions(self, date_range, assets):
        raise NotImplementedError

    def load_tradable_flags(self, date_range, assets):
        raise NotImplementedError
```

### 6.2 输出适配器

输出适配器负责把优化器结果洗成下游目标权重宽表与附属表。

```python
class OutputAdapter:
    def build_target_positions(self, optimized_weights):
        raise NotImplementedError

    def build_trade_table(self, prev_positions, target_positions):
        raise NotImplementedError

    def build_portfolio_summary(self, target_positions, diagnostics):
        raise NotImplementedError

        raise NotImplementedError
```

标准输入与标准输出都必须通过校验器。


## 8. 最小可运行闭环

建议第一阶段只跑通以下流程：

1. MockAdapter 生成标准输入协议。
2. 优化器接收输入，产出标准输出协议。
3. 输出适配器生成目标权重宽表。
4. 宽表喂给 `vectorbt_qs` 回测。
5. 回测结果返回到 `riskfolio_qs` 进行审计。

这样即使上游真实数据还没接通，也能先把优化-回测闭环跑起来。

## 10. 结论

`riskfolio_qs` 最适合采用“标准输入协议 + 标准输出协议 + 适配层留白”的方式推进。

你现在不需要先等上游真实数据，只要先把协议定死，再用 MockAdapter 跑通闭环，后续接任何上游都只改适配层，不动优化内核，也不动回测框架。
