# 组合优化器方案 v0.1

本文档只定义 `riskfolio_qs` 里“组合优化器”这一层的产品方案，不讨论上游数据接入细节，也不讨论下游回测实现细节。

该方案的目标是：

1. 提供一组可以一键调用或函数调用的组合优化模型。
2. 针对不同类型的 alpha 信号，定义默认 benchmark 模型清单。
3. 预留自定义优化器的扩展入口与参数体系。

---

## 1. 设计原则

1. 优先支持可解释、可复现、可回放的优化模型。
2. 默认 benchmark 必须区分 alpha 信号的“绝对收益尺度”与“仅排序/标准化尺度”。
3. 组合优化器不直接依赖具体上游数据格式，只消费标准输入协议。
4. 所有模型都必须返回统一的标准输出协议。
5. 自定义优化器必须通过显式配置开启，不能隐式覆盖默认 benchmark。

---

## 2. 组合优化器的职责边界

组合优化器只负责以下事情：

1. 接收标准输入协议。
2. 根据配置选择模型。
3. 构建约束并求解。
4. 输出目标持仓、调仓表、组合摘要与审计元数据。

不负责以下事情：

1. 原始上游数据清洗。
2. 下游回测执行。
3. 订单撮合与交易引擎层约束。

---

## 3. 一键调用的模型清单

### 3.1 经典均值-风险族

这一类模型适用于输入里有可解释预期收益率，或者至少 alpha 可以合理映射为“代理收益”的场景。

#### 3.1.1 Classic

对应 Riskfolio-Lib 的 `Portfolio.optimization(model="Classic", ...)`。

可配置目标：

1. `obj="MinRisk"`
2. `obj="MaxRet"`
3. `obj="Utility"`
4. `obj="Sharpe"`

常见风险度量：

1. `MV`
2. `CVaR`
3. `CDaR`
4. `EVaR`
5. `RLVaR`
6. `MSV`
7. `MAD`
8. `GMD`

#### 3.1.2 Black-Litterman（BL）

对应 `blacklitterman_stats(...) + optimization(model="BL", ...)`。

适用于：

1. 有主观观点。
2. 希望把观点与历史统计融合。
3. 希望以稳定的后验收益/风险输入做优化。

#### 3.1.3 Factor Model（FM）

对应 `factors_stats(...) + optimization(model="FM", ...)`。

适用于：

1. 有 Barra 或自建因子暴露。
2. 需要更稳健的协方差/风险结构。
3. 希望把行业、风格与收益预测放在同一个因子框架里。

#### 3.1.4 BLFM

对应 `blfactors_stats(...) + optimization(model="BLFM", ...)`。

适用于：

1. 既有因子结构，又有明确观点。
2. 需要融合多源信息。

#### 3.1.5 Entropy Pooling（EP）

对应 `entropy_pooling_stats(...) + optimization(model="EP", ...)`。

适用于：

1. 需要在情景分布层面融合观点。
2. 需要非参数化的后验分布修正。

---

### 3.2 风险预算/风险平价族

#### 3.2.1 Risk Parity（RP）

对应 `rp_optimization(...)`。

适用于：

1. alpha 信号只提供排序信息。
2. 不希望把 alpha 当成绝对收益值。
3. 需要稳定、可解释的仓位分配。

#### 3.2.2 Relaxed Risk Parity（RRP）

对应 `rrp_optimization(...)`。

适用于：

1. 需要比标准风险平价更强的约束表达。
2. 仍希望保持风险预算思想。

---

### 3.3 层次聚类组合族

对应 `HCPortfolio.optimization(...)`。

支持模型：

1. `HRP`
2. `HERC`
3. `HERC2`
4. `NCO`

适用于：

1. 资产数量较多。
2. 协方差矩阵噪声较大。
3. 希望做稳健的分组分配。

---

### 3.4 扩展优化族

#### 3.4.1 OWA

对应 `owa_optimization(...)`。

适用于：

1. 需要排序型风险聚合。
2. 想用自定义的情景权重序列。

#### 3.4.2 Worst Case（WC）

对应 `wc_optimization(...) + wc_stats(...)`。

适用于：

1. 需要鲁棒优化。
2. 需要对均值和协方差不确定性建模。

#### 3.4.3 Factor Risk Contribution（FRC）

对应 `frc_optimization(...)`。

适用于：

1. 需要控制因子风险贡献。
2. 组合构造必须显式约束风格或因子暴露。

---

## 4. 默认 benchmark 设计

这一部分是本方案的重点：默认 benchmark 必须按照 alpha 信号的类型来分流。

### 4.1 alpha 信号类型定义

#### 4.1.1 真实尺度预测收益率

定义：上游模型输出的值可以合理解释为未来收益率、超额收益率或某种可量化的收益代理。

配置布尔值建议：

```python
alpha_is_absolute_return = True
```

#### 4.1.2 仅排序信息或标准化信号

定义：上游模型输出只代表排序、相对强弱或 zscore，不应直接解释为收益率绝对值。

配置布尔值建议：

```python
alpha_is_absolute_return = False
```

---

### 4.2 真实尺度预测收益率场景下的默认 benchmark

当 `alpha_is_absolute_return = True` 时，默认 benchmark 应优先使用“收益-风险联合”模型。

#### 4.2.1 第一层 benchmark

1. Classic + `obj="Sharpe"`
2. Classic + `obj="Utility"`
3. Classic + `obj="MaxRet"`
4. Classic + `obj="MinRisk"`

#### 4.2.2 第二层 benchmark

1. BL + `obj="Sharpe"`
2. FM + `obj="Sharpe"`
3. BLFM + `obj="Sharpe"`
4. EP + `obj="Sharpe"`

#### 4.2.3 第三层 benchmark

1. `wc_optimization(...)`
2. `owa_optimization(...)`
3. `frc_optimization(...)`

#### 4.2.4 默认启用建议

如果只允许先落地少量 benchmark，建议先实现：

1. Classic + Sharpe
2. Classic + Utility
3. FM + Sharpe
4. BL + Sharpe
5. RP
6. HRP

其中前四个适合真实收益预测场景，后两个作为稳健对照组。

---

### 4.3 仅排序信息或标准化 alpha 场景下的默认 benchmark

当 `alpha_is_absolute_return = False` 时，默认 benchmark 不能把 alpha 当作绝对收益直接代入收益项。

#### 4.3.1 第一层 benchmark

1. TopN 纯多等权
2. TopN 多空等权
3. TopN 纯多 + 风险平价
4. TopN 纯多 + HRP

#### 4.3.2 第二层 benchmark

1. 最小方差（历史协方差版）
2. 最小方差（Barra / 因子协方差版）
3. 最小方差 + alpha 倾斜
4. 跟踪误差最小化 + alpha 倾斜

#### 4.3.3 第三层 benchmark

1. 风险平价（RP）
2. 层次风险平价（HRP）
3. 最小方差 + 行业中性 + 风格限幅

#### 4.3.4 默认启用建议

如果只允许先落地少量 benchmark，建议先实现：

1. TopN 纯多等权
2. TopN 多空等权
3. 最小方差（历史版）
4. 最小方差（Barra 版）
5. RP
6. HRP

这组 benchmark 最适合只有排序信息或 zscore 信号的场景。

---

### 4.4 布尔配置建议

建议在配置里放一个总开关：

```python
alpha_is_absolute_return: bool
```

然后由该布尔值驱动 benchmark 路由：

```python
if alpha_is_absolute_return:
    default_benchmarks = [
        "classic_sharpe",
        "classic_utility",
        "classic_maxret",
        "classic_minrisk",
        "bl_sharpe",
        "fm_sharpe",
        "blfm_sharpe",
        "ep_sharpe",
        "rp",
        "hrp",
    ]
else:
    default_benchmarks = [
        "topn_long_only_equal_weight",
        "topn_long_short_equal_weight",
        "topn_long_only_risk_parity",
        "topn_long_only_hrp",
        "minvar_hist",
        "minvar_barra",
        "minvar_alpha_tilt",
        "te_min_alpha_tilt",
        "rp",
        "hrp",
    ]
```

这类路由设计是第一版最关键的产品化决策。

### 4.5 硬约束模板（冻结值）

v0.1 只冻结三类硬约束：

1. 预算约束
2. 单票上限
3. 换手约束

以下约束暂不进入 v0.1，只作为后续版本备选：

1. TE 约束
2. 流动性约束
3. 指数锚定约束
4. 行业中性 / 风格中性约束

#### 4.5.1 冻结原则

1. 同一 benchmark 家族内，硬约束模板固定，不按模型效果临时调整。
2. 约束值属于 benchmark 定义，不属于调参对象。
3. 任何需要改变约束值的情况，都应通过版本升级而不是运行时改写。
4. 如果某个 benchmark 在固定约束下不可行，应直接标记为不可比，不自动放松约束。

#### 4.5.2 通用长多模板

适用于：

1. TopN 纯多等权
2. Min Risk（历史版）
3. Min Risk（Barra 版）
4. Sharpe
5. Utility
6. Risk Parity
7. HRP / HERC / NCO

冻结值：

| 参数 | 冻结值 | 说明 |
|------|------|------|
| `budget` | `1.00` | 组合净值全投资 |
| `max_single_name_weight` | `0.05` | 单票权重上限 5% |
| `turnover_cap` | `0.20` | 每次再平衡最大换手 20% |
| `turnover_definition` | `0.5 * sum(|w_t - w_{t-1}|)` | 标准换手定义 |

#### 4.5.3 TopN 纯多等权模板

固定规则：

| 参数 | 冻结值 | 说明 |
|------|------|------|
| `topn_n_long` | `50` | 每期固定选前 50 只 |
| `long_weight_per_name` | `0.02` | 每只股票 2% |
| `budget` | `1.00` | 全部权重和为 100% |
| `single_name_cap` | `0.05` | 与等权权重保持一致 |
| `turnover_cap` | `0.20` | 仍使用通用换手上限 |

说明：如果某期可用股票数不足 50，只要不改变 benchmark 定义，就不自动改成其他 N；该期应直接标记为不可比。

#### 4.5.4 TopN 多空等权模板

固定规则：

| 参数 | 冻结值 | 说明 |
|------|------|------|
| `topn_n_long` | `10` | 做多前 10 只 |
| `topn_n_short` | `10` | 做空后 10 只 |
| `long_weight_per_name` | `0.05` | 每只多头 5% |
| `short_weight_per_name` | `-0.05` | 每只空头 -5% |
| `gross_exposure_cap` | `1.00` | 总敞口 100% |
| `net_exposure_target` | `0.00` | 净敞口 0 |
| `turnover_cap` | `0.20` | 每次再平衡最大换手 20% |

说明：多空基线只用于排序信息或标准化信号场景，不引入收益尺度解释。

#### 4.5.5 其他 benchmark 的约束模板

1. Min Risk（历史版）和 Min Risk（Barra 版）共享同一长多模板。
2. Sharpe 和 Utility 共享同一长多模板。
3. Risk Parity 和 HRP 共享同一长多模板。
4. 上述模型之间只允许更换风险模型或目标函数，不允许更换硬约束值。

#### 4.5.6 后续版本备选约束

以下约束留作 v0.2 及以后版本再接入：

1. `allowTE` / `TE`
2. 流动性 / ADV 约束
3. 行业中性 / 风格中性
4. 指数锚定主动暴露控制
5. beta 中性

### 4.6 Benchmark 总表

以下为 v0.1 建议保留的 benchmark 清单。所有 benchmark 都共享同一套冻结约束模板，除非特别注明。

| Benchmark 名称 | alpha 类型 | 目标函数 / 构造方式 | TopN | 冻结硬约束 |
|------|------|------|------|------|
| `TopN 纯多等权` | 仅排序 / zscore | 选前 50 只等权 | 50 | `budget=1.00`，`max_single_name_weight=0.05`，`turnover_cap=0.20` |
| `TopN 多空等权` | 仅排序 / zscore | 多 10 空 10，等权 | 10 + 10 | `gross_exposure_cap=1.00`，`net_exposure_target=0.00`，`turnover_cap=0.20` |
| `Min Risk（历史版）` | 仅排序 / zscore | `Portfolio.optimization(model="Classic", obj="MinRisk")` | 不适用 | 同通用长多模板 |
| `Min Risk（Barra版）` | 仅排序 / zscore | 因子协方差 + `MinRisk` | 不适用 | 同通用长多模板 |
| `Risk Parity` | 两类都可 | `rp_optimization(...)` | 不适用 | 同通用长多模板 |
| `HRP` | 两类都可 | `HCPortfolio.optimization(model="HRP")` | 不适用 | 同通用长多模板 |
| `Sharpe` | 真实尺度收益率 | `Portfolio.optimization(obj="Sharpe")` | 不适用 | 同通用长多模板 |
| `Utility` | 真实尺度收益率 | `Portfolio.optimization(obj="Utility")` | 不适用 | 同通用长多模板 |

#### 4.6.1 真实尺度预测收益率场景

默认主 benchmark：

1. `Classic + Sharpe`
2. `Classic + Utility`
3. `FM + Sharpe`
4. `BL + Sharpe`
5. `RP`
6. `HRP`

#### 4.6.2 仅排序 / zscore 场景

默认主 benchmark：

1. `TopN 纯多等权`
2. `TopN 多空等权`
3. `Min Risk（历史版）`
4. `Min Risk（Barra版）`
5. `RP`
6. `HRP`

7. `Min Risk + alpha tilt`
8. `TE-min + alpha tilt`（后续版本备选）

## 5. 自定义优化器的支持方法与参数

如果默认 benchmark 不能满足需求，方案必须提供自定义优化入口。

### 5.1 支持的自定义方式

#### 5.1.1 自定义目标函数

允许用户在配置中选择预定义的目标函数模板。

建议形式：

1. `MinRisk`
2. `MaxRet`
3. `Utility`
4. `Sharpe`
5. `AlphaTilt`
6. `TrackingErrorTilt`

#### 5.1.2 自定义风险度量

允许用户选择风险度量类型。

建议形式：

1. `MV`
2. `CVaR`
3. `CDaR`
4. `EVaR`
5. `RLVaR`
6. `MAD`
7. `GMD`
8. `MSV`
9. `SKT`

#### 5.1.3 自定义约束模板

允许用户从约束模板中组合：

1. 行业中性
2. 行业上下限
3. 风格中性
4. 风格限幅
5. 单票上限
6. 换手约束
7. 跟踪误差约束
8. 净敞口约束
9. 总敞口约束

#### 5.1.4 自定义数据映射

允许用户自定义：

1. alpha 列映射
2. 风格因子列映射
3. 行业列映射
4. 基准权重列映射
5. 上期持仓列映射

### 5.2 建议暴露的配置参数

以下参数建议在第一版中开放：

#### 5.2.1 与 alpha 有关

| 参数 | 类型 | 含义 |
|------|------|------|

| `solver` | string | 求解器名称 |
| `use_higher_moments` | bool | 是否启用高阶矩 |

#### 5.2.3 与约束有关

| 参数 | 类型 | 含义 |
|------|------|------|
| `sht` | bool | 是否允许做空 |

| `allowTO` | bool | 是否约束换手 |
| `turnover` | float | 换手上限 |
| `allowTE` | bool | 是否约束跟踪误差 |
| `TE` | float | TE 上限 |
| `benchmark_mode` | string | `absolute` / `relative` |

#### 5.2.4 与行业/风格有关

| 参数 | 类型 | 含义 |
|------|------|------|
| `industry_neutral` | bool | 是否行业中性 |
| `style_neutral` | bool | 是否风格中性 |
| `neutral_band` | float | 中性容忍带 |
| `industry_limit` | float | 行业偏离上限 |
| `style_limit` | float | 风格偏离上限 |

## 7. 结论

组合优化器 v0.1 的定位应该是“模型路由器 + benchmark 路由器 + 约束模板容器”。

第一版的关键不是把所有模型都做完，而是先把以下三件事定义清楚：

1. 什么时候把 alpha 当真实收益。
2. 什么时候只能把 alpha 当排序或标准化信号。
3. 不同 alpha 类型下默认 benchmark 应该调用哪些模型。

只要这三件事先定下来，后续的实现、扩展和回测都能稳定推进。
