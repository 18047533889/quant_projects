# Fast 与 Accurate 回测模式说明

本文描述 `vectorbt_qs` 当前 A 股回测的两种业务口径。重点是两种模式如何理解信号、行情、成交和组合收益，以及各自适合回答什么研究问题。

## 1. 两种模式解决的问题不同

`fast` 是无摩擦的因子研究口径，目标是让大量因子、分组和参数组合在统一假设下快速横向比较。它有意消除手续费、整手和初始资金规模等因素，重点观察选股与权重本身是否有效。

`accurate` 是带状态的基础交易回测口径，目标是回答目标组合在现金、持仓、整手、费用、停牌和涨跌停等约束下能否形成，以及这些约束对最终收益有什么影响。

二者不是“低精度与高精度的同一个计算开关”，而是针对不同研究阶段设计的两套口径：

| 维度 | Fast | Accurate |
|---|---|---|
| 主要用途 | 因子分层、组合排序、参数初筛 | 候选策略复核、交易约束与费用评估 |
| 成交单位 | 分数股 | 默认 100 股一手 |
| 现金与持仓 | 按目标权重无摩擦再平衡 | 逐日维护实际现金和股数 |
| 费用与滑点 | 固定为零 | 方向性费用、最低佣金和滑点 |
| 停牌、涨跌停 | 忽略或目标层近似 | 根据实际持仓和订单方向判断 |
| 资金不足 | 允许按目标权重近似完成 | 按可用现金分配并形成实际股数 |
| 结果重点 | 相对排名和分组差异 | 可实现收益、换仓成本和约束影响 |

## 2. 输入权重的共同约定

两种模式都以目标权重表作为策略输入：

- 行索引是信号日期，必须是无时区、无日内时间的真实交易日；
- 列是 A 股证券代码；
- 正数表示目标多头权重，`0` 表示清仓；
- `NaN` 表示该证券没有新指令，继续维持当前状态；
- 不支持负权重；
- 每行已明确给出的权重之和不能超过 1，未使用部分保留为现金。

为避免 `NaN` 持仓与其他新权重叠加后产生不直观的总敞口，常规因子研究建议每个调仓日提供一行完整权重：未入选证券明确填 `0`，而不是 `NaN`。

证券池、因子计算、股票筛选和目标权重生成发生在回测之前。回测不会替策略补做历史成分股筛选，也不会自动消除幸存者偏差。输入权重使用的股票池必须由研究流程保证在当时可知。

## 3. 数据来源与处理方式

### 3.1 交易日历

交易日来自 `lqtp_data/Calendar`，对应 `data_access` 中的 A 股交易日历数据。只有 `IsTradeDay` 为真的日期进入回测。

信号延迟按交易日而不是自然日计算。例如周五收盘后的信号，在下周一正常开市时执行；若下周一休市，则顺延到下一个真实交易日。

### 3.2 股票日行情

股票行情来自 `lqtp_data/StockDailyBar`，主要使用：

- `Open`、`Close`、`Vwap`；
- `IsSuspend`；
- `HighLimit`、`LowLimit`；
- `Factor`。

Fast 研究口径使用**后复权**价格：

```text
后复权价格 = 原始价格 × Factor
```

`Factor` 从证券上市初期附近的 1 开始，随着分红、送转等公司行动逐步累积，不会在回测末日重新归一化为 1。因此直接用原始价格乘以 `Factor` 是以后复权尺度延展价格序列，而不是保持最新价格不变的前复权。

Fast 的开盘、收盘和 VWAP 使用同一后复权因子，分数股与零费用设定避免价格尺度
影响组合间比较。

Accurate 不使用复权价格成交或估值。它使用 `StockDailyBar` 的原始
`Open`/`Vwap`/`Close`、原始 High/Low 和原始涨跌停价，持仓与订单均为真实股数。
`lqtp_data/StockDividend` 的公司行为按 `TradeDate`（除权除息日）单独处理：

- `CashDividend × 除息前持仓股数` 进入组合现金；
- `StockDividend` 和 `StockTransfer` 增加真实持仓股数；
- 这些公司行为在当日估值和订单之前生效；
- `Factor` 仅用于数据完整性校验，不能因其包含现金分红而直接解释为股数变化。

因此 Accurate 中“100 股一手”、最低佣金、印花税和成交金额都处于真实交易单位。

#### 停牌与涨跌停的数据及判断标准

可交易性所需字段全部来自 `lqtp_data/StockDailyBar`：

| 判断内容 | 数据字段 | 处理方式 |
|---|---|---|
| 停牌 | `IsSuspend` | 直接使用数据源标记，不根据成交量为零或价格不变自行推断 |
| 涨停价 | `HighLimit` | Accurate 直接使用原始交易所价格 |
| 跌停价 | `LowLimit` | Accurate 直接使用原始交易所价格 |
| 比较价格 | 默认 `Open` | Accurate 可配置原始 `open` 或 `vwap`；Fast 固定使用复权开盘价 |

系统不根据前收盘价、股票板块、ST 状态或上市天数重新计算涨跌停价，而是以行情表提供的 `HighLimit` 和 `LowLimit` 为准。这样可以直接继承数据源已经处理好的不同涨跌幅制度。

方向性判断为：

```text
停牌：
    买入和卖出都不可执行

买入或增加权重：
    执行价格 >= 原始涨停价时不可执行

卖出或降低权重：
    执行价格 <= 原始跌停价时不可执行
```

价格与涨跌停价相等时视为触及限制。为避免复权乘法和浮点表示造成边界误差，两个价格在相对误差 `1e-5`、绝对误差 `1e-8` 范围内接近时，也按相等处理。

涨跌停提供两种可配置口径：

| `limit_check_mode` | 买入限制 | 卖出限制 | 适用考虑 |
|---|---|---|---|
| `execution` | 选定原始执行价格触及涨停价 | 选定原始执行价格触及跌停价 | 适合认为 VWAP 代表可完成成交的研究 |
| `strict` | 当日原始最高价触及涨停价 | 当日原始最低价触及跌停价 | 保守口径；只要日内曾触及限制，就不假设相关方向能够全额成交 |

`strict` 的“触及”不是只判断严格的数学大于或小于，而是：

```text
买入受限 = High >= HighLimit，或 High 与 HighLimit 在容差内接近
卖出受限 = Low  <= LowLimit，或 Low  与 LowLimit 在容差内接近
```

容差可以通过以下配置调整：

```yaml
backtest:
  limit_check_mode: strict
  limit_price_rtol: 0.00001
  limit_price_atol: 0.00000001
```

相对容差主要吸收价格尺度和复权乘法误差，绝对容差用于接近零时的数值保护。两项都必须是非负有限数。

Fast `ignore` 不使用上述停牌和涨跌停判断，只检查非零目标是否具有有效复权开盘价。Fast `approximate` 使用配置选择的涨跌停口径，但买卖方向取决于当前目标相对“上一次被允许的目标”的变化。Accurate 则根据当时的实际持仓股数和本次目标股数判断订单方向。

### 3.3 基准指数

指数行情来自 `lqtp_data/IndexDailyBar`，例如沪深300使用 `000300.SH`。

基准收益使用指数 `Close` 的相邻交易日涨跌计算。该数据表中的 `Return` 是基点口径，不直接作为小数收益率使用。指数日期与组合交易日历对齐，中间缺口以前值延续。

可视化中的三条 NAV 定义为：

```text
策略 NAV = 当日组合价值 / 首日组合价值
基准 NAV = 当日指数收盘价 / 首日指数收盘价
超额 NAV = 策略 NAV / 基准 NAV
```

超额 NAV 是相对财富曲线。大于 1 表示从回测起点至当日累计跑赢基准，小于 1 表示累计跑输基准。

### 3.4 缺失数据

对尚未上市且目标权重为零、实际持仓也为零的证券，缺少行情不会阻止回测。

以下情况会被视为无法可靠执行：

- 非零目标缺少执行价格；
- 已持仓证券缺少当日估值价格；
- accurate 模式下订单需要的停牌或涨跌停字段缺失；
- 配置要求的证券在整个行情数据中缺失且曾有非零目标。

## 4. 信号频率与执行时序

当前基础模式支持日频和周频，不支持月频。

CLI 和 YAML 均支持显式回测区间。`start` 默认是 `2024-01-01`，`end`
默认使用仓位数据的最后日期：

```yaml
backtest:
  start: 2024-01-01
  end: 2025-12-31
```

命令行单次回测使用 `--start` 和 `--end`。

### 日频

`freq: 1D` 保留输入中的每个信号日。默认 `execution_lag: 1`，即当天收盘产生目标，下一交易日执行。

### 周频

`freq: 1W` 在每个以周五结束的自然周中，选取输入里最后一个实际信号日。该日期不被改写成周五，随后再按交易日延迟执行。

例如某周只有周一至周四有信号，则周四是该周信号日；若采用收盘信号加一个交易日延迟，通常在周五执行。

### 防止未来信息

收盘后产生的信号不能在同一交易日执行。Fast 固定使用收盘信号和下一交易日复权开盘价。

Accurate 允许研究者声明盘前已知信号并配置当日执行，但研究者仍需自行保证信号在所选成交价格之前确实可知。回测只能检查显式的时序配置，不能判断因子数据本身是否包含未来信息。

## 5. Fast：无摩擦因子研究口径

### 5.1 固定假设

Fast 固定采用以下条件：

- 收盘产生信号；
- 延迟一个真实交易日；
- 以复权开盘价再平衡；
- 使用分数股，不做 100 股取整；
- 共享一个组合现金账户；
- 手续费、固定费用和滑点全部为零；
- 每日使用复权收盘价估值；
- 初始资金只改变金额尺度，不应改变收益率。

这些假设使不同因子组、不同持仓数量和不同股票价格水平之间更容易公平比较。

### 5.2 再平衡方式

每个执行日直接以目标权重为组合再平衡目标。需要降低的权重和需要提高的权重在同一个现金账户内协调。

非调仓日没有新目标，组合继续持有，并随每日复权收盘价变化。由于允许分数股，Fast 不会产生整手取整误差；由于费用为零，小额调仓不会因最低佣金受到额外惩罚。

### 5.3 可交易性口径

Fast 提供两种明确选择。

#### `fast_tradeability: ignore`

这是默认的纯因子研究口径：

- 忽略停牌和涨跌停；
- 只要求非零目标在执行日具有有效复权开盘价；
- 假设目标组合可以在该价格完成。

该口径最适合回答“因子选出的股票后来表现是否更好”，但不能用于判断真实可成交收益。

#### `fast_tradeability: approximate`

这是可交易性敏感性检查：

- 停牌时维持此前被接受的目标；
- 权重增加且开盘价处于涨停时，阻止增加；
- 权重减少且开盘价处于跌停时，阻止减少。

方向判断基于“当前目标相对上一次被接受目标”的变化，而不是实际股数和真实成交结果。因此它仍然不是订单级模拟，无法准确反映部分成交、整手、现金不足和连续受限交易造成的路径差异。

该口径可与 `limit_check_mode: strict` 组合，使用当日最高价和最低价进行更保守的触限检查。`fast_tradeability: ignore` 会按定义忽略 `limit_check_mode`。

### 5.4 Fast 结果如何解读

Fast 适合比较：

- 因子分层的收益单调性；
- Top 组与 Bottom 组的差异；
- 不同因子、持仓数量和调仓频率的相对表现；
- 大量参数组合的初步排序；
- `ignore` 与 `approximate` 之间的可交易性敏感度。

Fast 不适合直接估计：

- 扣费后的可实现收益；
- 资金容量和冲击成本；
- 小资金下的整手偏差；
- 涨跌停或停牌期间的真实持仓路径；
- 实盘订单数量和成交明细。

## 6. Accurate：带现金与持仓状态的基础交易口径

### 6.1 组合状态

Accurate 在每个执行日根据实际现金、实际持仓股数和执行价格计算组合权益，再把目标权重换算为目标股数。

默认按 100 股一手取整：

```text
目标股数 = 向下取整(
    组合权益 × 目标权重 ÷ 执行价格 ÷ 每手股数
) × 每手股数
```

未投入部分保留为现金。由于股价、整手和费用不同，即使目标权重相同，实际持仓权重也可能略有偏离。

规则上，完整清仓会卖出全部剩余股数，即使其中包含不足一手的零股；部分减仓仍按整手处理。当前组合从零持仓开始且买入按整手执行，因此通常不会自行产生零股，这条规则主要保证全退出语义完整。

### 6.2 卖出优先

同一调仓日先处理卖出，再使用卖出释放的现金处理买入。这符合共享现金账户下的基本资金约束。

卖出成功后才会增加可用现金。若卖出因停牌或跌停被阻止，原持仓继续保留，相应现金也不会被用于当天买入。

### 6.3 停牌和涨跌停

订单根据实际增减仓方向判断：

- 停牌：买卖均阻止；
- 买入或加仓：执行价处于涨停价时阻止；
- 卖出或减仓：执行价处于跌停价时阻止。

被阻止的订单不会改变现金和持仓。后续调仓日会再次根据当时的实际持仓和新目标计算需要交易的数量。

当成交价采用 VWAP 或收盘价时，建议使用 `limit_check_mode: strict`。否则只要 VWAP 或收盘价本身没有处于涨跌停价，即使日内最高价或最低价曾触及限制，原有 `execution` 口径仍可能假设目标订单能够全额成交。

### 6.4 资金不足

可买现金不足以完成全部目标时，不按证券排列顺序依次把现金用完，而是先对所有可买订单进行同比例缩减，再按整手向下取整。

随后会考虑最低佣金对小额订单的影响，必要时继续减少整手；若仍有剩余现金，则优先补给目标市值缺口较大的证券，每只证券最多补一手。

这种处理减少了证券代码排列顺序对结果的影响，但实际成交权重仍会受整手和费用约束。

### 6.5 成交容量

`max_participation_rate` 可限制单股订单占执行日 `Volume` 的比例。冻结的
`standard_accurate_v2` 使用 `0.10`，即单次最多成交当日市场成交量的 10%，并按
100 股整手向下取整。容量不足时订单日志标记为 `partial_volume`/`volume`，未成交
部分不会虚构为持仓，而会在后续调仓日根据新的目标权重和真实持仓重新计算。

### 6.6 费用与滑点

默认费用口径为：

| 项目 | 买入 | 卖出 |
|---|---:|---:|
| 佣金 | 0.025% | 0.025% |
| 印花税 | 0 | 0.05% |
| 过户费 | 0.001% | 0.001% |
| 最低佣金 | 每笔 5 元 | 每笔 5 元 |

最低佣金只补足佣金部分；印花税和过户费仍按成交金额另计。

若滑点为 `s`：

```text
买入成交价 = 选定价格 × (1 + s)
卖出成交价 = 选定价格 × (1 - s)
```

费用和滑点会真实减少可用现金，并影响后续调仓可买股数，因此其影响具有路径依赖。

### 6.7 成交价格

Accurate 使用原始成交价。通用接口可选择 `open`、`close` 或 `vwap`，冻结的
`standard_accurate_v2` 只遍历下一交易日原始 `open` 和原始 `vwap`。

选择成交价格时必须与信号可得时间一致。例如收盘后信号配合下一交易日开盘价是清晰的无未来信息口径；不能用当天收盘后才能得到的信号回到当天成交。

### 6.8 Accurate 的边界

Accurate 比 Fast 更接近可交易组合，但仍是日频基础回测，不等同于交易所撮合或实盘账户：

- 不使用盘口、逐笔成交或日内价格路径；
- 冻结口径限制为当日成交量的 10%，但不使用分时成交量曲线，也不额外估计非线性
  市场冲击；
- 严格涨跌停口径使用当日 High/Low 是否触限，并继续检查滑点后的最终成交价；
- 一天只有一个组合级再平衡事件；
- 没有独立建模委托排队、撤单和部分撮合；
- 现金分红、送股和转增按 `StockDividend` 拆分，但现金分红按数据字段全额入账，
  未模拟与持有期限相关的个人红利税；
- 持仓证券缺少原始收盘估值时会失败退出，不会静默沿用旧价格，也不假设一个未经
  数据支持的退市清算价格；
- 不面向融券、做空、融资或多币种账户；
- 没有独立的日内 T+1 可卖股数模型。默认收盘信号次日执行的日频流程不会产生同日回转，但不能替代更细粒度的证券可卖库存管理。

因此 Accurate 适合策略级可实现性复核，但若要回答大资金冲击、涨停排队、退市
清算或实盘成交偏差，仍需更细的成交和事件数据。

## 7. 推荐研究流程

建议按以下顺序使用两种模式：

1. 使用 Fast `ignore` 对因子分层、持仓数量和参数组合做统一初筛；
2. 使用 Fast `approximate` 检查结论是否对停牌和涨跌停敏感；
3. 对少量候选组合使用 Accurate，加入整手、方向性费用、最低佣金和滑点；
4. 比较 Fast 与 Accurate 的差异，识别收益是否主要来自高换手、小额订单或难成交证券；
5. 对计划投入实盘的策略，另行开展容量、冲击成本、公司行动和成交延迟压力测试。

不建议把 Fast 与 Accurate 的绝对收益直接并列后，仅将差值解释为“交易成本”。两者还同时存在分数股、现金分配、可交易性和实际持仓路径等口径差异。

## 8. 配置示例

### Fast 因子研究

```yaml
backtest:
```
