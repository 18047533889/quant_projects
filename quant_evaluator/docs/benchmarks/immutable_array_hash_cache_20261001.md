# 不可变数组配置哈希缓存（2026-10-01）

提交 `37f8eda8c` 将缓存逻辑拆到 `contracts/_array_hash_cache.py`。配置哈希函数在处理完整数组 JSON 后保存 SHA 状态；重复请求命中时跳过该数组的 base64 编码和哈希扫描，随后继续处理剩余字段。它保留 `EvaluationConfig.v2` 原有字节口径，不更改后端选择规则。

缓存只接受至少 8 MiB、C 连续、由不可变 `bytes` 持有的普通数值 ndarray。只读标志不足以证明底层不可变；可变底层、memmap、非连续数组等继续走原编码。缓存键包括进入数组前的哈希、数组身份、dtype、shape、strides 和字节数。最多 32 项；弱引用不保留数组数据，fork 子进程清空条目并更换锁。

## 64 MiB 微测

我们在 server-c 用 `.venv/bin/python`，对 bytes 持有的 `np.arange(8*1024*1024, dtype=np.float64)` 连续哈希四次。请求 tag 为 `qe.cache.micro.v1`，字段为 `factor_values`、`factor_ids=("f",)`、`metrics=("coverage",)`；只选择 factor_values 流式编码。

旧实现四次耗时：0.127418、0.126604、0.123283、0.123006 秒。新实现：0.122720、0.0000495、0.0000249、0.0000200 秒。两次进程峰值 RSS 约 288 MiB。所有输出均为 `b7b3a96ef2a1960453c60acf06cd54a5eb48e01cec1de816dbcfe940877fc94d`。这些数字只衡量配置哈希；不能换算为全量评估的加速倍数。首次编码和新数组身份仍需要扫描，真实批量收益需要单独 A/B。

## 验证范围

主干改前 QE 全套为 4,491 通过、26 跳过；改后为 4,501 通过、26 跳过。缓存/流式哈希聚焦测试 22 项通过，覆盖原始编码字节一致性、跳过编码、前后字段变化、元数据变化、可变底层绕过、弱引用/LRU、并发和 fork。完整回归后我们补强元数据测试，让小数组使用低阈值缓存，再跑聚焦测试 22 项通过。fork 测试会触发 Python 多线程 fork 警告。

重复使用同一个 FactorBatch 才能复用数组身份。重新读取 COS、构造新批次或改变配置前缀会造成缓存未命中；调用者仍需计算数据加载、指标计算和输出构建的端到端成本。
