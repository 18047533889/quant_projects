# Public evaluate() 多指标批次 CPU/CUDA A/B（2026-09-26）

本次直接调用公开的 evaluate()，每次请求包含多个指标。测试在 server-c 的 NVIDIA L20 上运行；两轮 CPU/CUDA 次序反转，每种后端在独立子进程中连续运行一次冷启动和两次热调用。GPU 显存比例上限 40%，主机结果上限 64 MiB，每个子进程 120 秒。机器可读记录：public_batch_routes_20260926.json。

## 数据与口径

- 通过已有 DataAccess 注册入口读取 ashare_stock_daily_adj：2023-09-01 至 2026-08-27，723 个行情分区、3,714,828 行、5,314 只股票。
- 使用截至决策日 t-1 的调整 VWAP 构造 5 日和 20 日滞后动量测试信号，标签为 t 到下一实际交易日的调整 VWAP 收益；最终为 701 日 × 5,314 股 × 2 因子。信号由真实行情派生，并非生产因子绩效认证。
- 组合指标使用相同信号的等权有符号收益作为诊断用 ProbePortfolioArtifact，并非已认证的可交易组合。
- 读取后的行情仅保存在运行进程内存中，没有复制整库或持久化行情面板。

## 完整输出一致性

8 个批次对照（4 种组合 × 2 轮）全部通过容差对拍：形状、有限值位置、计数、有效掩码、样本数 provenance、输入因子字节哈希相同；数值在 rtol=1e-8、atol=1e-10 内。标量 MetricValue 的指标 ID、版本、有效性、样本量、警告、样本单位逐字段相同，其值按同一容差一致。全部指标最大绝对差不超过约 1.32e-15。

首次对拍将 MetricValue.value 用 Python 浮点数精确相等比较，所以部分 evidence_equal=false；例如 rank IC 仅差 1e-17。随后单独重新计算全部批次并按上述规则逐字段复核。JSON 中 metric_evidence_semantic_equal 和 all_parity_numeric_tolerance_pass 记录该结果，原始严格相等字段仍保留供审计。

## 自动后端建议

对已支持的多指标批次，上述规模及 L20 的证据支持整批选择 CUDA。CUDA 执行器复用排序、排名、日度 IC 和分位中间结果；混合请求中即使某个单指标独立测试由 CPU 更快，拆成逐指标不同后端也可能比整批 CUDA 更慢，并增加证据与来源标识的复杂度。

自动路由应以公开入口整批耗时、显存预算和完整结果对拍决定；指标组合、面板维度、硬件、依赖版本改变后应重新测量。小面板、无 GPU、未支持指标或附加输入类型不同的请求须单独处理。本报告仅覆盖四组组合和 L20，不能证明 164 个指标及所有组合都最快、都正确。
