# 分层日收益：CPU 数值稳定性修复（2026-10-03）

## 计算口径与已确认问题

每个日期、因子、分层，仅取分层 ID 有效且标签有限的股票集合 $S$。
样本量 $c=|S|$；若 $c < \mathrm{min\_assets}$，收益为 NaN，否则：

$$r_{t,q,f}=\frac{1}{c}\sum_{i\in S} y_{t,i}.$$

有限标签不能保证中间 Float64 求和有限。独立 `Decimal.from_float`
（2000 位精度）测试发现 NumPy 路径把 `[1e308,1e308]` 的均值算成
Inf，而正确结果为 `1e308`；`[1e308,1,-1e308,3]` 算成 0.75 而非 1。
CPU 后端之间相互一致不足以证明正确性。

## 模块及行为

`metrics/quantile_numeric.py` 为 NumPy 直接/预分层/optimized 路径和
Numba 公共包装器共享的修复模块。分层归属、计数、有效性与 min_assets
口径不变。Numba 仍使用其原始分层结果，不重新分层。

普通标签保留原有快速求和。按标签行一次计算保守顺序求和误差界，
$\gamma_N=N\epsilon/(1-N\epsilon)$，使用
$2\gamma_N\sum_i|y_i|$；只有均值误差界超过 `1e-12` 或结果不有限的
充分样本桶才重算。绝对值和缩放计算，避免界本身溢出；极端或全
subnormal 行保守进入修复。风险桶使用精确有理数求和及除法，最后
一次性转 Float64，避免中间溢出和二次舍入。
这不是每个普通输入均值都逐位正确舍入的声明。
独立审查还发现 `fsum` 后除以数量可能二次舍入；`[1,2**-53,0]`
反例保留为精确断言，因此风险桶不采用 `fsum` 后再除法的方案。

## 验证范围与未闭合事项

新增高精度 oracle 覆盖大数、消去、subnormal、mask、counts 和阈值。
普通分层及请求缓存回归必须继续保持一致；真实宽面板的新旧 A/B
尚需单独执行，不能从小测试推断性能无损。

## 宽面板实测与后续修复

初次默认 32 线程 A/B 为 T128/N5461/F48，标签标准差 0.02，Q5/Q20，
各三轮 ABBA，逐次核验 counts 及收益、输入/源码/运行时身份。
`benchmarks/quantile_numeric_guard_initial_20261003.json` 保存完整历史回执。
Q20 保护开启时 NumPy 中位数 15.20 秒（绕过保护 3.01 秒），Numba
15.35 秒（绕过保护 2.06 秒）。Q5 分别为 2.664/2.539 和 1.822/1.815 秒。
入场时存在其他 FE 测试负载，不能把这些数字解释成全局最快资格。

发现整行误差界对较小分层桶过于保守。对参与本次聚合的标签均满足
$|y_i|\leq1$ 的有限普通收益率集合（NaN/Inf 不参与判定），以同一保守
公式重新计算桶内界，N 改为
桶内有限观测数量；若桶内界仍超阈值则精确修复。混合大尺度标签、
非有限均值保持原精确路径，独立二次舍入断言不放宽。NumPy 同一批次
只构建一次标签行界，各因子共享；独立预分层聚合仍自行计算界。
第二轮历史回执为 `quantile_numeric_guard_refined_20261003.json`；最终
回执为 `quantile_numeric_guard_final_20261003.json`，后者包含忽略无效标签
的最终源码。相同 shape/seed/runtime 下最终 Q20 NumPy 为 3.8299 秒、
Numba 为 3.0648 秒；绕过保护为 2.9283/2.0007 秒，仍有约 0.90/1.06 秒
数值保护开销，不能宣称性能无损。Q5 开销为 0.017/0.039 秒。
每组每后端 9 次配对核验，counts 精确一致，收益使用声明容差；输入、
三份指标源码及真实 32 线程运行时在前后保持一致。这是合成 CPU 分层
保护开销实测，不是全 QE、COS、GPU 或默认 auto 的全局最快证明。
相关 CPU 小回归 62 项、扩展回归 130 项通过；真实 Numba JIT 的三组
溢出/消去样例另行对照高精度 oracle。

工作树中的 GPU `batched_quantile_returns` 已接入独立设备内风险检查及
精确均值修复；GPU 模块尚未包含在本次 CPU 数值修复提交中，需另行
验证、发布，不能从本提交推断远端 GPU 已修复。
每分块在所有 Q 均值算完后调用一次。标签先在 GPU 转 binary64 后求和，
极端风险使用整数精确累加、除法及一次 IEEE 舍入，不把标签复制回 CPU。
工作空间不足 fail-closed，不在 `cuda_strict` 偷偷回退 CPU。公开路径与
模块合计 20 项 CUDA 测试通过；多 GPU 当前设备不匹配测试因单卡跳过。
跨时间收益汇总仍需独立数值审查，不能据此宣称所有指标正确或最快。
源码变化使旧源码 hash 的性能证据成为历史证据，默认 auto 的最快后端
主张必须经当前源码、运行时和真实批量数据重新资格验证。
