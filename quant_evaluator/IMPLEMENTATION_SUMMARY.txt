## Technical Implementation Notes

### Data Flow
1. Input: numpy arrays (T, N, F)
2. Convert to long format with time_idx, asset_idx, factor_idx
3. Build polars LazyFrame (deferred execution)
4. Filter NaN values
5. Groupby (time, factor) with aggregation
6. Collect with streaming=True
7. Convert back to (T, F) dense format

### Lazy Evaluation
- Uses LazyFrame throughout for query optimization
- Streaming execution reduces peak memory
- Polars optimizer can reorder/fuse operations

### Correlation Implementation
- **Pearson**: Direct pl.corr() in groupby
- **Spearman**: Two-pass (rank first, then correlate ranks)

### Quantile Implementation
- Rank within (time, factor) groups using pl.rank()
- Map rank to quantile: floor((rank - 1) * n_quantiles / n_valid)
- Clip to [0, n_quantiles - 1]

## Known Limitations

1. **Small batch overhead**: Setup cost makes polars slower for small datasets
2. **Spearman inefficiency**: Requires collect() after ranking, then re-lazy
3. **Long format conversion**: Initial reshape creates temporary memory spike
4. **No GPU**: Polars is CPU-only (use cupy for GPU)

## Future Improvements

1. **Chunked conversion**: Process data in chunks to reduce peak memory
2. **Arrow interop**: Use PyArrow for zero-copy when possible
3. **Parallel factor groups**: Split high-F batches across workers
4. **Single-pass Spearman**: Explore native rank correlation
5. **Adaptive thresholds**: Calibrate based on hardware profile
6. **LazyFrame input**: Accept LazyFrame directly to skip conversion
