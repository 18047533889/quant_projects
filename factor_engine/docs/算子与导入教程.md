## 1. 五分钟上手

### 1.1 目录与 PYTHONPATH

所有命令在 **`factor_engine` 根目录**执行（下文路径均相对该根目录，如 `api/`、`examples/`、`tests/`）：

```bash
cd ~/quant_projects/factor_engine   # 或你的 factor_engine 根目录
export PYTHONPATH=.:${PYTHONPATH}

# 自检：api 必须来自本包的 api/
python -c "import api; print(api.__file__)"
# 期望输出路径以 .../factor_engine/api/__init__.py 结尾
```

**常见错误**：PYTHONPATH 里若把 **monorepo 里旧的 `quantsociety/api/`** 排在 **`factor_engine` 根目录** 前面，会 import 到过期副本。

### 1.2 三种用法（选一种即可）

#### 用法 A：只写字符串（投递 manifest，最常见）

```json
{
  "formula": "rank(ts_mean(close, 20))",
  "expression_type": "dsl",
  "market": "us_stock"
}
```

框架导出器写进 `candidate_pool/.../manifest.json` 即可；**不必**在挖掘代码里 `import api`。

#### 用法 B：Python 里拼公式

```python
from api.columns import col
from api.factor import Factor
from api import rank, ts_mean

factor = Factor(
    name="mom20_rank",
    expr=rank(ts_mean(col("close"), 20)),
    freq="1d",
    universe="US_MASSIVE_ALL",
)
```

#### 用法 C：字符串 → 解析成 Factor（本地校验）

```python
from api.dsl_parser import parse_factor, DSLParseError

try:
    factor = parse_factor(
        'rank(ts_mean(close, 20))',
        name="check_me",
    )
    print("公式合法")
except DSLParseError as e:
    print("公式不合法:", e)
```

### 1.3 怎么 import 任意算子

**规则**：合法算子名都可以 `from api import <算子名>`。**`api` 里没有算子实现**，每次 import 只是查 `cleaned_operators` 注册表并返回一个「造表达式树」的工厂函数。

```python
# 常用 — api/__init__.py 显式导出（底层仍是 cleaned 工厂）
from api import rank, ts_mean, ts_std, zscore, delay

# 其余 ~500 个 — __getattr__ 动态解析（查 OperatorRegistry 后缓存工厂）
from api import winsorize, group_rank, if_else, ts_rsi, ts_macd
from api import SMA, MACD, BollingerBands   # 别名名也可以 import

# 列引用 / 因子容器 / DSL 解析
from api.columns import col
from api.factor import Factor
from api.dsl_parser import parse_expr, parse_factor, DSLParseError

# 白名单（= col + cleaned 已实现算子及别名，约 512 名）
from api.operator_registry import build_dsl_allowlist
print(len(build_dsl_allowlist()))
```

**`from api import rank` 背后发生了什么（不算数，只造树）：**

```text
from api import rank
  → make_cleaned_call_factory("rank")     # api/cleaned_ops.py
  → 返回 callable，调用后得到 CleanedCall  # expr/cleaned_call.py
  → FactorEngine.run 时才走 cleaned_bridge → OperatorRegistry.calculate()
```

**已经废弃，不要写**：

```python
from api.operators import rank      # ❌ api/operators/ 整包已删（第 31 版）
import cleaned_operators              # ❌ 挖掘/投递侧不需要；维护者调试 wide panel 时可选
from expr.ts import TsMean            # ❌ 强类型 expr 算子节点已删
```

**旧架构对照（帮你确认没有「两套算子」）：**

| 第 30 版及以前（已删除） | 第 31 版（当前唯一路径） |
|--------------------------|--------------------------|
| `api/operators/ts.py` 等工厂 + 强类型 `expr/TsMean` | `api/cleaned_ops.py` → 统一 `CleanedCall` |
| `PandasBackend` 里逐算子 `_kernels` | `PandasBackend` → `cleaned_bridge` → `cleaned_operators` |
| `STUB_IR_OPS` 占位仍可 parse | 白名单 **仅** 有 pandas runtime 的 cleaned 算子 |
| 实现分散在三处，易重复 | **实现只在** `cleaned_operators/` |

磁盘上 **`api/operators/` 目录不存在**；若文档/catalog 仍写 `api/operators/*`，那是迁移前历史标注。

### 1.4 投递前校验（公式必须是 factor_engine DSL）

在 **`factor_engine` 根目录**执行：

```bash
# 只校验公式字符串
PYTHONPATH=. python scripts/validate_delivery_formula.py "rank(ts_mean(close, 20))"

# 校验整份 manifest.json（推荐）
PYTHONPATH=. python scripts/validate_delivery_formula.py --manifest path/to/manifest.json

# 字段 / domain / 算子名是否误当列名（任意目录均可，用绝对路径）
python3 ~/quant_projects/factor-pool-standard/scripts/check_manifest_fields.py path/to/manifest.json
```

两条 CLI 分工：`validate_delivery_formula.py` 查 **DSL 语法与白名单**；`check_manifest_fields.py` 查 **列名是否在 canonical 注册、是否跨 domain**。详见 [`miner_delivery_spec.md`](miner_delivery_spec.md) §5.4。

也可在 Python 里调用 [`api/mining_integration.py`](../api/mining_integration.py)：

```python
from api.mining_integration import validate_us_dsl, validate_manifest_for_execution

ok, msg = validate_us_dsl("rank(ts_mean(close, 20))")
ok, msg = validate_manifest_for_execution(
    market="us_stock", expression_type="dsl", formula="rank(ts_mean(close, 20))"
)
```

## 2. `api/` 与 `cleaned_operators/`：分工（必读）

**一句话：** `cleaned_operators` = 算子引擎（唯一数值实现）；`api` = 公式入口（import、DSL 字符串解析、白名单校验）。**不是两套算子库，也不重复维护两套 rolling/rank 代码。**

### 2.1 数据流（从公式到因子值）

```text
manifest.formula 字符串          Python: from api import rank; Factor(...)
         │                                    │
         └──────────────┬─────────────────────┘
                        ▼
              api/dsl_parser.parse_expr
              或 api/cleaned_ops 工厂
                        │
                        ▼
              expr/CleanedCall（表达式树，还不算数）
                        │
                        ▼
              ir → planner → backend/cleaned_bridge
                        │
                        ▼
              cleaned_operators/OperatorRegistry.calculate()
              （wide panel 上 rolling / rank / MACD …）
                        │
                        ▼
              MultiIndex Series (timestamp, instrument)
```

### 2.2 各目录干什么

| 目录 | 职责 | 有没有算子实现 | 你要不要改 |
|------|------|----------------|------------|
| **`api/`** | `col`、`Factor`、`parse_expr`、`from api import rank` | ❌ 只有工厂 + 白名单 | 投递/试算 **用**；新增算子 **一般不改** |
| **`cleaned_operators/`** | `OperatorRegistry`、各模块 `@register_operator` | ✅ **唯一 runtime** | **新增/改语义只改这里** |
| **`expr/` `ir/` `planner/`** | 编译链 | ❌ | 不用 |
| **`backend/cleaned_bridge.py`** | MultiIndex ↔ panel，调用 cleaned | ❌ 桥接 | 一般不用 |

### 2.3 `api/` 每个文件（当前仅 8 个 py，无 `operators/` 子包）

| 文件 | 作用 |
|------|------|
| [`cleaned_ops.py`](../api/cleaned_ops.py) | `make_cleaned_call_factory(name)` → 构造 `CleanedCall` |
| [`operator_registry.py`](../api/operator_registry.py) | `build_dsl_allowlist()` = `col` + `build_cleaned_dsl_allowlist()` |
| [`dsl_parser.py`](../api/dsl_parser.py) | 字符串公式 → `Expr`；函数名必须在白名单 |
| [`columns.py`](../api/columns.py) | `col("close")` |
| [`factor.py`](../api/factor.py) | `Factor` 数据类 |
| [`mining_integration.py`](../api/mining_integration.py) | 投递校验、`default_*_data_source_config` |
| [`__init__.py`](../api/__init__.py) | 常用算子显式导出 + `__getattr__` 动态解析其余名 |

`build_dsl_allowlist()` **不维护第二份名单**：它调用 [`backend/cleaned_bridge.py`](../backend/cleaned_bridge.py) 的 `build_cleaned_dsl_allowlist()`，遍历 `OperatorRegistry` 里 **已有 pandas runtime** 的 canonical 名与 `_aliases.py` 别名，为每个名字挂一个 `make_cleaned_call_factory`。

### 2.4 `cleaned_operators/` 每个模块

| 模块 | 典型算子 |

### 2.5 白名单规模与重复检查（2026-06 审计结论）

| 指标 | 数量 | 说明 |
|------|------|------|
| 已实现 canonical | ~392 | `OperatorRegistry._operators` |
| DSL 可写名字（含别名） | ~512 | `build_dsl_allowlist()` |
| 白名单名无 runtime | **0** | 不会出现「能 parse 不能算」的旧 stub 路径 |
| `api/operators/` 目录 | **不存在** | 旧包已删 |

**已知冗余（不影响投递，维护者可择机合并）：** `statistics_regression.py` 里 `Beta`/`beta`、`Slope`/`slope` 等大小写各注册了一个类，语义相同，均在白名单。更干净的做法是保留一个 canonical、另一个放进 `_aliases.py`。

**catalog 里 `sources: api/operators/*`：** 迁移前历史路径，**不是**仍在使用的代码。

### 2.6 我该改哪一层？

| 目标 | 改哪里 |

## 3. 公式怎么写（只认 factor_engine）

**算子从哪来：** 仅 [`build_dsl_allowlist()`](../api/operator_registry.py) 与 [`cleaned_operators/`](../cleaned_operators/)。文档里若出现第二套命名（框架内置表、LQTP 注册表、华泰 catalog 等），**以本仓库代码为准**；不在白名单里的名字 **不能写**。

### 3.1 字段规则

**标准：公式里凡是要读数据的列，都写成裸字段名**（与 `close` 相同规则）：

| 类型                 | 规则                              | 合法示例                                                                                     |
| -------------------- | --------------------------------- | -------------------------------------------------------------------------------------------- |
| **字段名**     | 小写蛇形：`[a-z_][a-z0-9_]*`    | `open` `high` `low` `close` `volume` `ret_price` `adj_factor` `transactions` |
| **算子**       | 蛇形函数名 +`(`                 | `rank(` `ts_mean(` `delay(` `ts_atr(`                                                |
| **窗口**       | 第二个起多为**整数 bar 数** | `ts_mean(close, 20)` → 20 根 K 线                                                         |
| **常数**       | 数字字面量                        | `1e-9` `0.01` `14`                                                                     |
| **字符串参数** | `name="value"`                  | `ts_macd(close, line="hist")`                                                              |

**字段从哪来：** 必须是你这场 campaign 数据里 **真实存在的列**（见 [`miner_delivery_spec.md`](miner_delivery_spec.md) §4.1 主表字段 + `mining_scope.primary_tables`）。没有该列，Assetization 会报错。

**字段 vs 算子：** 单独出现的标识符 → 字段；后面跟括号且在白名单里 → 算子。

```text
rank(ts_mean(close, 20))
     ^^^^^^ ^^^^^ ^^
     算子   算子  字段 + 窗口常数
```

`col("close")` 仍合法，与 `close` 等价；**新公式统一裸写字段名**。

**Python 手写 Expr** 时仍用 `col("close")`，或整段字符串 `parse_factor("rank(ts_mean(close, 20))")`。

### 3.2 四则运算

```text
close - open
(high - low) / (close + 1e-9)
-close
volume * 2
```

### 3.3 比较与逻辑

```text
close > open
if_else(close > open, close, open)
if_else(and_(close > open, volume > 0), rank(close - open), 0)
```

| 想写 | 正确     | 错误    |
| ---- | -------- | ------- |
| 与   | `and_` | `and` |
| 或   | `or_`  | `or`  |
| 非   | `not_` | `not` |

不支持链式比较：`a < b < c` ❌

### 3.4 因子示例（manifest 里 `formula` 就长这样）

**动量 / 反转**

```text
rank(ts_mean(close, 20))
rank(close / delay(close, 1) - 1)
rank(ts_mean(close, 5) - ts_mean(close, 60))
zscore(close / delay(close, 20) - 1)
```

**量价比 / 流动性**

```text
rank(volume / (ts_mean(volume, 20) + 1e-9))
rank(ts_delta(volume, 1))
rank(((high - low) / (close + 1e-9)) * volume)
```

**缺口 / 振幅**

```text
rank((open - delay(close, 1)) / (delay(close, 1) + 1e-9))
rank((close - low) / ((high - low) + 1e-9))
```

**波动 / 技术指标**（`ts_atr` 等需要 `high` `low` `close` 都在数据里）

```text
rank(ts_std(close / delay(close, 1) - 1, 20))
rank(ts_rsi(close, 14))
rank(ts_macd(close, line="hist"))
rank(ts_atr(high, low, close, 14))
```

**截面处理**

```text
zscore(ret_price)
winsorize(close / delay(close, 1) - 1, lower=0.01, upper=0.99)
nan_to_num(close / delay(close, 1))
```

**manifest 示例：**

```json
{
  "formula": "rank(ts_mean(close, 20))",
  "expression_type": "dsl",
  "market": "us_stock",
  "frequency_bucket": "daily"
}
```

### 3.5 别名（仅限 factor_engine 内登记）

下列别名 **已在** `cleaned_operators/_aliases.py` 注册，与 canonical 等价。**不要**自造别名，不要从外部文档抄名字。

| DSL 中可写       | canonical         | 含义          |
| ---------------- | ----------------- | ------------- |
| `delay(x, d)`  | `ts_delay`      | 滞后 d 根 bar |
| `mean(x, d)`   | `ts_mean`       | 滚动均值      |
| `std(x, d)`    | `ts_std`        | 滚动标准差    |
| `shift(x, d)`  | `ts_delay`      | 同 delay      |
| `SMA(x, d)`    | `SMA`           | 简单移动平均  |
| `EMA(x, d)`    | `ema` / `EMA` | 指数均线      |
| `MACD(x)`      | `ts_macd`       | MACD          |
| `where(c,a,b)` | `if_else`       | 条件选择      |

完整表：[`cleaned_operators/_aliases.py`](../cleaned_operators/_aliases.py)。**没有** `ts_sma` / `ts_ema` — 外部文档若这么写，是错的。

### 3.6 非法写法（一律须改成 factor_engine DSL）

| ❌ 错误（来自框架/旧文档）                         | ✅ 正确（factor_engine）         |
| -------------------------------------------------- | -------------------------------- |
| `RANK(TS_MEAN($close, 20))` QuantaAlpha          | `rank(ts_mean(close, 20))`     |
| `$open` `$close` `#close`                    | `open` `close`               |
| `StockDailyBar.Close` LQTP 表前缀                | `close`                        |
| `CS_Rank` `TS_Mean` 华泰 PascalCase            | `rank` `ts_mean`（蛇形小写） |
| `df['close'].rolling(20).mean()` CogAlpha python | `ts_mean(close, 20)`           |
| `and` / `or` / `not`                         | `and_` / `or_` / `not_`    |
| `ts_sma` `ts_ema` `pasteurize` `hump`      | 见 §4.5；用白名单内名           |
| `*_stub` `vec_avg` `vec_sum`                 | 禁止；改组合或等维护者实现       |
| `delay(close, -1)`                               | 正整数窗口 only                  |
| 换行 / 分号                                        | `formula` 单行                 |

**导出 adapter 职责**：框架 LLM 或内部 AST **不得**原样写入 manifest；必须输出上表右列这种 **可通过 `parse_expr` 的 factor_engine 字符串**。

## 4. 怎么查「有哪些算子、能不能用」

### 4.1 程序里查白名单（最权威）

见 [`dsl_operators_reference.md`](dsl_operators_reference.md) 与 [`dsl_allowlist.json`](dsl_allowlist.json)。

```python
from api.operator_registry import build_dsl_allowlist

allow = build_dsl_allowlist()
names = sorted(allow.keys())

print(len(names))           # ~512
print("rank" in allow)      # True
print("ts_mean" in allow)   # True
print("vec_avg" in allow)   # False — stub，不在白名单

# 模糊搜
hits = [n for n in names if "macd" in n.lower()]
print(hits)
```

Gateway 的算子白名单应与 **`build_dsl_allowlist()`** 一致。

### 4.2 文档里查语义（参数、要哪些列）

| 文档                                                                                 | 看什么                                                               |
| ------------------------------------------------------------------------------------ | -------------------------------------------------------------------- |
| [`cleaned_operators/operators_catalog.md`](../cleaned_operators/operators_catalog.md) | **全量目录**：canonical、别名、`implemented` / `stub` 状态 |
| [`operators_semantics.md`](operators_semantics.md)                                    | **参数含义**、HLC 列依赖、DSL 限制 |
| [`dsl_operators_reference.md`](dsl_operators_reference.md)                            | 不可 parse 名与替代写法 |

**查某个算子要不要 extra 列**（例：ATR 要 high/low/close）→ 看 `operators_semantics.md` 技术指标章节。

### 4.3 绝对不能写的名字

以下 **不在** `build_dsl_allowlist()`，`parse_expr` 直接报错 — **不是「另一种方言」，就是写错了**：

- 框架内置名：`TS_MEAN`、`RANK`、`$close`、`#close` 等
- 表前缀字段：`StockDailyBar.Close` 等
- 华泰 / 外部 PascalCase：`CS_Rank`、`TS_Mean` 等（须改成蛇形，**不要**再查外部 catalog 当合法名）
- 旧文档 / catalog 有但未进白名单：`pasteurize`、`ts_sma`、`ts_ema`、`hump` 等（§4.5）
- 全部 `*_stub`、`vec_avg`、`vec_sum`

**怎么确认能不能写：** 只问 `name in build_dsl_allowlist()` 或 `parse_expr` 是否通过 — 不问框架文档、不问 LQTP 表。

### 4.4 算子分类速查（可投递代表）

完整枚举见 [`dsl_operators_reference.md`](dsl_operators_reference.md) §3 与 [`dsl_allowlist.json`](dsl_allowlist.json)。下表便于 LLM / 研究员快速选题：

| 类       | 代表算子                                                              | 备注                                             |
| -------- | --------------------------------------------------------------------- | ------------------------------------------------ |
| 截面     | `rank` `zscore` `winsorize` `neutralize` `quantile`         | 每个 timestamp 横截面                            |
| 时序     | `ts_mean` `ts_std` `delay` `ts_delta` `ts_corr` `ts_rank` | 窗口`d` = bar 数                               |
| 分组     | `group_rank` `group_neutralize` `group_zscore`                  | 需数据里有**行业/板块列**（如 `sector`） |
| 逻辑     | `if_else` `where` `and_` `or_` `not_`                       | 勿用 Python 关键字                               |
| 清洗     | `protected_div` `nan_to_num` `fillna` `coalesce`              | 防除零、填 NaN                                   |
| 技术指标 | `ts_rsi` `ts_macd` `ts_atr` `SMA` `EMA`                     | HLC 类须`high`/`low`/`close` 都在          |
| 条件交易 | `trade_when`                                                        | 见[`adr_trade_when.md`](adr_trade_when.md)        |

**均线命名陷阱**：白名单里是 **`SMA(x,d)` / `EMA(x,d)`** 或 `ts_mean`；**没有** `ts_sma` / `ts_ema` 别名（见 §4.5）。

### 4.5 旧文档常见名 → factor_engine 正确写法

catalog / 外部教程里出现、但 **当前不在白名单** 的名字 — **不能沿用**，须改成右列（右列也须再跑 `parse_expr` 确认）：

| ❌ 错误写法           | ✅ factor_engine 内替代                              |
| --------------------- | ---------------------------------------------------- |
| `ts_sma(close, 20)` | `SMA(close, 20)` 或 `ts_mean(close, 20)`         |
| `ts_ema(close, 20)` | `EMA(close, 20)`                                   |
| `pasteurize(x)`     | `nan_to_num(x)`                                    |
| `hump(x, …)`       | `hump_decay(x, threshold=…)`（若在白名单）        |
| `ret` 列名          | `close / delay(close, 1) - 1` 或字段 `ret_price` |
| `pre_close`         | `delay(close, 1)`                                  |
| `amount`            | `close * volume`                                   |

## 7. 常见问题

### Q1：`from api.operators import rank` 报错？

`api/operators/` 已在第 31 版删除。改为：

```python
from api import rank
```

### Q2：`import api` 打出来的路径不对？

PYTHONPATH 里 **`factor_engine` 根目录（`.`）须优先于 monorepo 里旧的 `quantsociety/api/`**。见 §1.1。

### Q3：公式里一定要写 `col("close")` 吗？

**字符串 / manifest：不用。** 写 `close` 即可（挖掘侧标准）。

**Python 手写 Expr**：要用 `col("close")`，或整段用 `parse_factor("rank(ts_mean(close, 20))")`。

### Q4：`api` 和 `cleaned_operators` 是不是重复了两套算子？

**不是。** 第 31 版起 **只有一套 runtime**：`cleaned_operators/`。`api/` 不提供第二套 rolling/rank 实现，只做：

- `from api import rank` → 造 `CleanedCall` 表达式树；
- `parse_expr("rank(...)")` → 同上 + 白名单校验；
- `build_dsl_allowlist()` → 转发 cleaned 注册表。

执行时 **`PandasBackend` 100% 经 `cleaned_bridge`** 调 `OperatorRegistry.calculate()`。详见 §2。

### Q5：能不能 `import cleaned_operators` 直接调？

可以，但**仅限维护者调试**。挖掘侧应走 `api` + `FactorEngine`，否则绕过 DSL 白名单与编译链。

### Q6：框架文档里的算子表能信吗？

**不能。** 唯一权威是 `build_dsl_allowlist()` 与 `parse_expr`。QuantaAlpha / LQTP / 华泰 / 旧版 factor_engine 文档里的名字，**不在白名单就是错的**，必须改成 factor_engine 写法（§3.6）。

### Q7：怎么知道公式会不会被拒？

```python
from api.dsl_parser import parse_expr, DSLParseError

def validate(formula: str) -> tuple[bool, str]:
    try:
        parse_expr(formula)
        return True, "OK"
    except DSLParseError as e:
        return False, str(e)
```

Gateway 还会查复杂度、未来函数、去重等 — 见 [`miner_delivery_spec.md`](miner_delivery_spec.md) §5（投递前校验清单）。

### Q8：`Unsupported function: xxx` 怎么修？

| 报错片段                          | 常见原因                   | 处理                                        |
| --------------------------------- | -------------------------- | ------------------------------------------- |
| `Unsupported function: ts_sma`  | 不在白名单                 | 改`SMA(...)` 或 `ts_mean(...)`（§4.5） |
| `Unsupported function: and`     | 用了 Python 关键字         | 改`and_`                                  |
| `Unsupported name: close`       | 极少见；多为语法树解析异常 | 检查是否误写成赋值、是否有非法字符          |
| `Unsupported function: TS_MEAN` | 框架语法未改               | 改`ts_mean`（蛇形小写）                   |
| `Invalid expression syntax`     | 括号不匹配、非法 token     | 保证单行、检查引号                          |

用 `validate_delivery_formula.py` 或 `parse_expr` 可复现 Gateway 侧的语法拒因。

### Q9：`group_rank` 报错缺列？

分组算子需要 **分组键列**（如 `sector`、`industry`）出现在数据源 / `mining_scope` 主表中。PV 日频若只有 OHLCV，**不要**写 `group_neutralize(x, sector)`，除非 campaign 数据已 merge 行业表。

### Q10：给 LLM 写因子时引用哪份提示词？

只用 [`factor_engine_llm_prompt.md`](factor_engine_llm_prompt.md) + [`dsl_operators_reference.md`](dsl_operators_reference.md) + 本文。**禁止**把 QuantaAlpha / 华泰 / LQTP 算子表塞进 prompt 当合法集合。生成后必须 `parse_expr` / §1.4 CLI 通过。
