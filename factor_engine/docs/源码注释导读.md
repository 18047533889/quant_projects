# 源码注释导读

阅读 `factor_engine` 源码时的 **注释约定** 与 **按目录导读**。各目录还有独立 `README.md`，本页做总索引。

---

## 1. 注释怎么写（维护者约定）

| 层级 | 要求 |
|------|------|
| **模块** | 文件顶部的 `"""..."""`：本文件职责、上下游、非职责 |
| **类** | 一句话用途 + 关键字段说明 |
| **公开函数/方法** | 参数、返回值、典型调用场景；复杂逻辑写「为什么」 |
| **私有函数 `_xxx`** | 至少一行说明输入输出；算法非显然时写步骤 |
| **行内注释** | 只解释非显然的业务/性能取舍，避免复述代码 |

语言：**中文为主**，与现有 `runtime/`、`backend/` docstring 风格一致。

---

## 2. 数据流（先建立全局图）

```
api（DSL、Factor）
  → expr（ColumnRef / Literal / CleanedCall）
  → ir.Analyzer（Expr → IRNode，推导 lookback、引用列）
  → planner（IR → PlanNode，CSE、优化）
  → backend.execute（PlanNode → MultiIndex Series）
  → storage/materializer（可选落盘）

读数据：storage.DataAccessSource → data_access.get_store()
算子：cleaned_operators.OperatorRegistry.calculate()
编排：runtime.FactorEngine
```

## 4. 关键入口函数（建议先读）

| 函数 | 文件 | 作用 |
|------|------|------|
| `FactorEngine.run` | `runtime/engine.py` | 单因子编译+执行 |
| `FactorEngine.run_many` | `runtime/engine.py` | 多因子 + CSE |
| `build_data_source` | `storage/factory.py` | 构造 DataSource |
| `build_backend` | `backend/factory.py` | 选择 Pandas/Polars/SQL |
| `Analyzer.lower` | `ir/analyzer.py` | Expr → IR |
| `Lowerer.lower` | `planner/lowerer.py` | IR → PlanNode |
| `PandasBackend.execute` | `backend/pandas_backend.py` | 递归求值 PlanNode |
| `compile_registry_op` | `backend/polars_registry_bridge.py` | Registry 算子 long 表编译 |
| `OperatorRegistry.get` | `cleaned_operators/registry.py` | 按 backend 取算子实现 |

## 5. 注释覆盖进度

| 模块 | 状态 |
|------|------|
| `expr/`、`ir/`、`cache/`、`util/` | 模块 + 主要函数已补中文 docstring |
| `backend/base.py`、`factory.py`、`context.py` | 已补 |
| `backend/polars_registry_bridge.py` | 每函数已补详细说明 |
| `runtime/engine.py`、`planner/`、`cleaned_operators/` 大文件 | 原有模块 docstring；函数级持续增量 |
| `tests/` | 测试意图在 docstring；不逐行注释 |

大文件（如 `polars_expr_emitter.py`、`elementwise_math.py`）按 **公开 API 优先** 逐步补注释；算子语义以 [`operators_semantics.md`](operators_semantics.md) 为准。
