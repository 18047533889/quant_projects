# 默认 auto 批量落值（R5）

推荐入口保持只有因子集合，不需要选择 DAG、内存比例、worker 数或后端：

```python
from factor_engine import get_engine

# all_factors 是已有 Factor 的有限集合或迭代器；可一次提交整个集合。
# 管理员先配置已有、已批准的 FACTOR_ENGINE_V2_PROFILE。
with get_engine() as engine:
    receipt = engine.run_many(all_factors)

print(receipt["status"], receipt["counts"])
print(receipt["result_index"])
print(receipt.get("run_dag"))
```

数据日期、股票范围、数据快照和授权输出位置仍由批准的业务配置确定。
入口不猜数据集或写入目标，不自动发布生产因子。返回的是持久化回执和结果索引，
不是把所有因子面板装进一个返回字典。原始 FactorEngine 构造器的旧接口保持兼容；
它不等价于这里的持久化默认入口。

## 默认生效的执行选项

- 明确启用 CSE、面板执行、原生融合、adaptive 调度、auto 后端，worker 数自动决定。
  旧版关闭这些优化的 PerfConfig 环境变量不会覆盖此入口传入的选项。
- 资源池按有效剩余内存的 80% 目标治理，仍受宿主机、cgroup、其他作业和出口预留约束；
  它不是总物理内存的 80%，也不是无条件填满内存。
- CSE 实际缓存容量来自同一 broker 的实时预算，包含父进程代理路径。
  零预算保持为零；缩容不得提前释放仍被消费者持有的值。
- 数据读取、计算任务、落值出口仍经过原有预算准入、有限重试和逐因子终态。
- 多后端选择只比较当前可用且通过语义/能力准入的执行路径。融合与转换不得改变结果。
  “auto”是受约束的成本模型选择，不是已经测得所有硬件、所有算子的绝对最优。
  未验证的快速数值核不会因追求速度而被强制启用；GPU 也不是所有算子的通用后端。

## 整任务 DAG 的边界

默认入口先流式估算整任务定义、图索引和进程传输的元数据开销，
向统一 broker 申请元数据租约。通过准入后，以同一批 DAG 调度全部根；
主计算进程使用完整的动态 CPU/IO 权限，不再只得到双槽的一半配额。
面板值仍由已有 scheduler/CSE/出口预算治理，不会一次返回全部面板。

如果图元数据或落值回执传输预算不允许，则自动保持有界分批。
回执的 `run_dag.execution_scope`、`reason`、估算字节数说明实际选用的模式。
元数据估算是保守启发式，不是 Python 内存占用的数学上界。
后续实时内存压力仍可能导致等待、有限失败或资源拒绝，不能保证永不 OOM。

重要：目前分批之间没有持久化的受治理共享值缓存。
同一 DAG 内的公共表达式可以复用；跨批次仍可能重算。
尤其 10 万根的回执可能超过 IPC 预算，因此不能把“一次提交 10 万因子”
表述为“已经证明 10 万根所有公共值全程只计算一次”。

独立的 run_dag_catalog 已完成 10 万轻量定义的流式元数据测试，
但暂不挂到默认链路：当前执行器尚不消费其预编译结果，额外登记只会增加开销。
该测试不是 10 万真实市场因子的落值或吞吐验收。
