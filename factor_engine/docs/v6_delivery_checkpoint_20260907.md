## 默认调用

管理员先通过 `FACTOR_ENGINE_V2_PROFILE` 指定已批准的业务配置。它必须包含日期范围、证券池、日线后复权数据集和已存在的隔离输出目录；不能由 Agent 猜测这些权限或范围。

```python
from factor_engine import get_engine

if __name__ == "__main__":
    with get_engine() as engine:
        receipt = engine.run_many(all_factors)
```

无需调用者选择后端、并发度、批大小或内存比例。脚本的 main guard 是 spawn 的必要入口保护，不是性能参数。原有 FactorEngine 字典结果接口与这个 v2 artifact 回执接口分开。示例代码位于 `factor_engine/examples/run_many_v2_example.py`。

当前默认配置只接受 `ashare_stock_daily_adj`、`1d` 面板与权威 OHLC 字段映射；不接受用 `hfq` 标签搭配原始价格字段。这个构造检查不等于真实数据、PIT 或执行认证通过。

## 已落地的主要代码

- 零余量与未知测量不再回退到硬内存总量；默认 80% 政策进入 broker。
- 父进程统一持有资源租约，工作进程通过 IPC 申请；回收须核实 PID 和启动身份已退出。
- 数据缓存没有预算时不保留缓存，但仍可返回结果；缓存租约跟踪底层数组、索引及保留的视图。
- 编译与数值输出错误按因子记录；输入中途失败保留部分结果。状态分页，不把十万条详情全部放进默认回执。
- 默认执行通过 spawn 工厂创建可复用核心；正常关闭数据源，卡住时有限终止。旧的非工厂兼容路线仍有 fork 警告。
- 读波新增规划与执行双重预算门：单项超过预算直接拒绝；运行时未取得共享租约不得读取。不同时间范围暂不合并，避免窗口语义改变。
- 默认写入和外部回执验证受进程监管。数值、dtype、索引、掩码、覆盖与哈希读回验证，提交文件目录逐级同步；不登记生产目录或推进生产水位。
- TSZScore 参数语义、区域成本及共享节点、Polars/Pandas 桥接轴与参数顺序等已修；旧的未实现 Polars 声明隔离而非冒充已支持后端。

## 性能与转换账本

写入 manifest 逐 chunk 保存实际转换方向、Arrow 逻辑字节、转换时间、写入和读回时间。
真实复制字节未测量时保持 `null`，不将逻辑字节伪装成分配峰值。
`evidence/v6_fixture_artifact_ledger_20260907.json` 仅为六行合成样本的观测摘要；不是吞吐基准，更不是十万因子或最快后端证明。

另有可复现的 8 因子 × 100,000 行串行合成写入测量。首次历史峰值与较晚 baseline 起点不一致，不能直接归因 writer scratch；新增 2ms 区间采样（281 次）观察到 RSS 从 124,882,944 字节至 239,939,584 字节，耗时 1.0267 秒。详见 `evidence/v6_interval_writer_measurement_20260907.json`。它包含输入、初始化和 allocator 常驻，并非生产 spawn 路径；短峰可能漏采。32 MiB scratch 账目不能当成进程族总内存上限，尚无 OOM 防护验收证明。

随后已将读回校验的 cell hash 改为最多 8,192 行一段，去掉两份整块 bytes 副本，并提前释放写阶段 frame；精确数值/索引/dtype 校验保留，43 项写入与状态测试通过。这个修复只限制 hash 临时行数，不等于整个 writer 内存有界，也不限制单行字符串字节数。
