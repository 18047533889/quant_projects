**三句话记住：**

1. 代码里只写**数据集名**（如 `ashare_stock_daily`）；需要换盘时用 `read_root` / `write_dir`，不要自己 `pd.read_parquet`  
2. **COS 和已发布数据只读**，你的结果写到 `factor_lake_staging`（或自选 `write_dir`）  
3. 入口永远是：`from data_access import get_store` → `store = get_store()`

## 1. 功能一览：支持什么、不支持什么

### 1.1 支持的功能

| 类别 | 功能 | 怎么用（一句话） |
|------|------|-----------------|
| **读** | 读 A 股 / 美股 / 因子 Parquet | `store.read_frame("数据集名", columns=..., time_range=...)` |
| **读** | **全市场 / 全部股票** | **省略** `instrument_filter`（默认读该时间段内所有标的） |
| **读** | 只读指定股票 | `instrument_filter=["000001.SZ", ...]` |
| **读** | 读参数化数据（因子湖） | 加 `factor_id="xxx"` |
| **读** | 大表流式、Polars lazy | `read_arrow_stream()` / `scan_polars()` |
| **读** | 从腾讯云 COS 远程读 clean_data | 设 `DATA_ACCESS_COS_READ_MODE=remote` |
| **读** | 自选读路径（覆盖数据集根） | `read_root=` 或 `DATA_ACCESS_READ_ROOT_*` |
| **读** | HTTP 远程读（不装全仓库） | `DataAccessClient("http://服务器:8765")` |
| **算** | SQL 聚合 / JOIN / 窗口函数 | `store.sql("SELECT ... FROM {{数据集}}", ...)` |
| **算** | 读→算→写一条链路 | `store.compute_and_write(...)` |
| **写** | 写因子草稿 | `store.write_arrow("factor_lake_staging", ...)` |
| **写** | 自选落盘路径 | `write_root=` / `write_dir=` 或 `DATA_ACCESS_WRITE_ROOT_*` |
| **写** | 增量合并去重 | `store.upsert(..., upsert_on=[...])` |
| **写** | 写个人回测结果 | `store.write_arrow("single_asset_backtest_runs", ...)` |
| **发布** | 草稿晋升全员可见 | `store.publish_from_staging(...)` |
| **追溯** | 本次读用了哪些文件 | `read_result()` 返回 `snapshot_id` |
| **因子** | DSL 批量算因子 | factor_engine + `data_source.type: data_access` |

### 1.2 不支持 / 禁止

| 不做的事 | 原因 |
|---------|------|
| 业务代码里 `pd.read_parquet` / `duckdb.connect` | 绕过白名单、审计、性能优化 |
| 直接写 `factor_lake`（已发布因子） | 必须走 staging → publish |
| 修改 COS 里的文件 | COS 是全员只读真源 |
| 绕过 store 直接 `pd.read_parquet("/home/...")` | 换机器就挂；用数据集名，必要时用 `read_root`/`write_dir` |

### 1.3 数据流（你的代码在整个链路中的位置）

```
┌─────────────────────────────────────────────────────────┐
│  COS clean_data（A股/美股清洗数据）  ← 只读，你不改这里   │
│  factor_lake（已发布因子）            ← 只读               │
└───────────────────────┬─────────────────────────────────┘
                        │  store.read_frame / sql / factor_engine
                        ▼
                 ┌──────────────┐
                 │  你的运算     │  SQL / Python / DSL
                 └──────┬───────┘
                        │  write_arrow / compute_and_write
                        ▼
┌─────────────────────────────────────────────────────────┐
│  factor_lake_staging（你的草稿）  ← 你写这里             │
│  namespaced（个人实验）           ← 你写这里             │
└───────────────────────┬─────────────────────────────────┘
                        │  publish_from_staging（可选）
                        ▼
                 factor_lake（全员可读）
```

## 2. 安装与环境（第一次必做）

需要：Python 3.10+。本包目录即 `data_access/`（内含本手册）。

### 2.1 方式一：拿到 `data_access` 目录后本地安装（能读能写能算）

```bash
# 假设你收到的包解压后路径是 ./data_access
cd data_access
pip install -e ".[all]"          # 或 pip install -e .
# 依赖：duckdb / pyarrow / pandas 等（见 pyproject.toml）

# 把包所在父目录加入 PYTHONPATH（若不是 editable 安装）
export PYTHONPATH="$(pwd)/..:${PYTHONPATH}"
```

若你们仓库里还有顶层 `env.sh`，可继续 `source env.sh`；**单独只拿本包时**，至少设：

```bash
export QUANT_RUN_NAMESPACE=你的名字          # 写数据必设
export DATA_ACCESS_COS_READ_MODE=remote      # 其他服务器读 COS 时
export DATA_ACCESS_COS_REMOTE_BACKEND=cli
export DATA_ACCESS_EXTRA_ALLOWED_ROOTS=/data/my_ws   # 自选读/写路径时
```

### 2.2 方式二：只装客户端（HTTP 远程读）

```bash
pip install -e "./data_access[client]"
# 或从 git：
# pip install "data-access[client] @ git+https://github.com/18047533889/quant_projects.git#subdirectory=data_access"
```

### 2.3 每次开终端要做的事

```bash
# 写数据必设
export QUANT_RUN_NAMESPACE=你的名字

# 其他服务器读 COS（按需）
export DATA_ACCESS_COS_READ_MODE=remote
export DATA_ACCESS_COS_REMOTE_BACKEND=cli
```

### 2.4 验证安装成功

```python
from data_access import get_store
store = get_store()
print("已登记数据集数量:", len(store.registry.names()))
print("示例:", store.registry.names()[:5])
```

能打印出一串数据集名 = 安装 OK。

### 场景 A：只读行情或因子（最常见）

**适合**：风控看数、研究画图、截面因子、拉一批日线做分析。

**选股范围怎么定**（`instrument_filter`）：

| 你要的范围 | 写法 | 说明 |
|-----------|------|------|
| **全市场 / 全部股票** | **不传** `instrument_filter` | 默认行为：该 `time_range` 内所有标的都会读进来 |
| 指定几只 | `instrument_filter=["000001.SZ", "600000.SH"]` | 白名单过滤，A 股用 `Symbol`，美股用 `Ticker` |
| 先拿名单再过滤 | 先读 `ashare_stock_list` / `ashare_universe_daily`，再传 `instrument_filter=名单` | 指数成分、自定义股票池常用 |

**你要做的**：

```bash
# 只读可以不设 namespace；写了也没问题
# 若有仓库顶层 env.sh 可 source；单独装本包时按第 2 章设环境变量即可
```

```python
from data_access import get_store
store = get_store()

# A 股日线全部可选字段（见 6.2）
ASHARE_DAILY_COLS = [
    "TradeDate", "Symbol",
    "Open", "High", "Low", "Close", "PreClose",
    "Volume", "Amount", "Return", "Vwap",
]

# --- ① 全市场单日（截面算因子最常用）---
df_all_one_day = store.read_frame(
    "ashare_stock_daily",
    columns=ASHARE_DAILY_COLS,
    time_range=("2024-06-28", "2024-06-28"),
    # 不传 instrument_filter = 该日全部 A 股
)
print("标的数:", df_all_one_day["Symbol"].nunique())

# --- ② 全市场一段区间 ---
df_all_range = store.read_frame(
    "ashare_stock_daily",
    columns=ASHARE_DAILY_COLS,
    time_range=("2024-01-01", "2024-01-31"),
)

# --- ③ 指定若干只股票 ---
df_pick = store.read_frame(
    "ashare_stock_daily",
    columns=ASHARE_DAILY_COLS,
    time_range=("2024-01-01", "2024-12-31"),
    instrument_filter=["000001.SZ", "600000.SH", "000002.SZ"],
)

# 美股日线全部字段（见 6.2）
US_DAILY_COLS = [
    "TradeDate", "Ticker",
    "Open", "High", "Low", "Close", "PreClose",
    "Volume", "Amount", "AdjFactor", "VWAP",
    "Ret", "Ret_Intra", "Ret_Overnight",
]

# --- ④ 美股：全市场单日 ---
df_us_all = store.read_frame(
    "us_stock_daily",
    columns=US_DAILY_COLS,
    time_range=("2024-01-02", "2024-01-02"),
)

# --- ⑤ 美股：指定几只 ---
df_us_pick = store.read_frame(
    "us_stock_daily",
    columns=US_DAILY_COLS,
    time_range=("2024-01-01", "2024-01-31"),
    instrument_filter=["AAPL", "MSFT", "NVDA"],
)

# 因子全部字段（见 6.2）
FACTOR_COLS = [
    "datetime", "asset", "value",
    "calc_time", "factor_version", "data_snapshot_id",
    "is_valid", "invalid_reason",
]

# --- ⑥ 已发布因子：全市场 ---
df_factor_all = store.read_frame(
    "factor_lake",
    factor_id="某个因子ID",
    columns=FACTOR_COLS,
    time_range=("2024-01-01", "2024-06-30"),
)

# --- ⑦ 已发布因子：部分标的 ---
df_factor_pick = store.read_frame(
    "factor_lake",
    factor_id="某个因子ID",
    columns=FACTOR_COLS,
    time_range=("2024-01-01", None),
    instrument_filter=["000001.SZ", "600519.SH"],
)

print(df_all_one_day.head())
```

**常用数据集名**：

| 要什么 | 数据集名 | 时间列 | 标的列 |
|--------|---------|--------|--------|
| A 股日线 | `ashare_stock_daily` | TradeDate | Symbol |
| A 股分钟 | `ashare_stock_minute` | QuoteTime | Symbol |
| 美股日线 | `us_stock_daily` | TradeDate | Ticker |
| A 股股票池（按日） | `ashare_universe_daily` | TradeDate | Symbol |
| 已发布因子 | `factor_lake` | datetime | asset |

完整清单见第 5 章；**每个数据集有哪些列、怎么读**，见 **第 6 章「字段参考 + 案例大全」**。

### 场景 B：在别的服务器，从 COS 读 clean_data

**适合**：风控服务器、云主机——**没有我们学校磁盘**，但要读 A 股/美股清洗数据。

**特点**：不依赖本机目录结构；COS 源文件不会被改。

**第一步：配置环境（复制粘贴，改名字）**

```bash
source env.sh

export DATA_ACCESS_COS_READ_MODE=remote
export DATA_ACCESS_COS_REMOTE_BACKEND=cli
export QUANT_RUN_NAMESPACE=你的名字

# 独立缓存目录（可选，建议设）
export DATA_ACCESS_COS_CACHE_ROOT=/data/.cos_remote_cache
```

**前置**：本机已装 `clean-cos-ro`，且 `~/.cos.yaml` 有 COS 读权限（向我们申请）。

**第二步：读数据（代码和场景 A 完全一样）**

```python
from data_access import get_store
store = get_store()

df = store.read_frame(
    "ashare_stock_daily",
    columns=["TradeDate", "Symbol", "Close"],
    time_range=("2024-01-04", "2024-01-04"),   # 务必传 time_range，只拉需要的日期
)
print(df.head())
```

**第三步：验收（可选）**

```bash
export DATA_ACCESS_COS_READ_MODE=remote
export DATA_ACCESS_COS_REMOTE_BACKEND=cli
export QUANT_RUN_NAMESPACE=test_smoke
python3 scripts/smoke_cos_compute_write.py
```

成功 = 从 COS 读了 A 股 + 美股 + clean 衍生层，并写了 staging。

**COS 上能读什么**：A 股 lqtp 20 表 + 美股 massive 18 表 + 美股 clean 5 表 = **43 个数据集**（见第 5 章）。

### 场景 C：读数据 → 运算 → 结果写到别处

**适合**：在 COS 上读行情，SQL 算特征，结果落到本机 staging，**不碰源数据**。

```bash
source env.sh
export DATA_ACCESS_COS_READ_MODE=remote
export DATA_ACCESS_COS_REMOTE_BACKEND=cli
export QUANT_RUN_NAMESPACE=你的名字
```

```python
from data_access import get_store
store = get_store()

result = store.compute_and_write(
    # ① SQL 运算（表名用 {{数据集名}}）
    """
    SELECT
      CAST(TradeDate AS TIMESTAMP) AS datetime,
      Symbol AS asset,
      Close AS value,
      CAST(strftime(TradeDate, '%Y') AS INTEGER) AS year
    FROM {{ashare_stock_daily}}
    WHERE Symbol = '000001.SZ'
    """,
    # ② 从哪读
    read_datasets=["ashare_stock_daily"],
    read_time_ranges={"ashare_stock_daily": ("2024-01-01", "2024-01-31")},
    # ③ 写到哪（只能是 staging 或 namespaced，不能写 factor_lake）
    write_dataset="factor_lake_staging",
    factor_id="my_feature_v1",
    mode="overwrite",
    partition_by=["year"],
)

print("算出行数:", result["rows_computed"])
print("写入路径:", result.get("path"))

# ④ 读回验证
check = store.read_frame("factor_lake_staging", factor_id="my_feature_v1",
                         columns=["datetime", "asset", "value"])
print(check.head())
```

**算完后若要全员可见**（需有权限）：

```python
store.publish_from_staging("factor_lake_staging", "factor_lake", factor_id="my_feature_v1")
```

```bash
source env.sh

```

**客户端**：

```bash
pip install "data-access[client] @ git+https://github.com/18047533889/quant_projects.git#subdirectory=data_access"
```

```python
from data_access.service.client import DataAccessClient

client = DataAccessClient("http://服务器IP:8765", api_key="密钥")

# 健康检查
print(client.health())

# 读 A 股
df = client.read_frame(
    "ashare_stock_daily",
    columns=["TradeDate", "Symbol", "Close"],
    time_range=("2024-01-01", "2024-01-31"),
)
print(df.head())
```

| HTTP 接口 | 方法 | 说明 |
|-----------|------|------|
| `/health` | GET | 健康检查，无需密钥 |
| `/v1/datasets` | GET | 列出全部数据集 |
| `/v1/datasets/{name}` | GET | 单个数据集信息 |
| `/v1/read` | POST | 读数，返回 parquet |

POST `/v1/read` 请求体：

```json
{
  "dataset": "ashare_stock_daily",
  "columns": ["TradeDate", "Symbol", "Close"],
  "time_range": ["2024-01-01", "2024-01-31"],
  "format": "parquet"
}
```

请求头加：`X-API-Key: 你的密钥`

### 场景 E：批量算因子（factor_engine）

**适合**：DSL 公式、复杂算子、上百个因子一起跑。

**流程**：

```
配好 COS remote（场景 B 的环境变量）
    ↓
写因子 YAML（指定 data_source.dataset = ashare_stock_daily 等）
    ↓
factor_engine 跑 pipeline
    ↓
自动写入 factor_lake_staging
    ↓
publish_from_staging → factor_lake
```

**YAML 示例**：

```yaml
data_source:
  type: data_access
  dataset: ashare_stock_daily
  fields:
    close: Close
    volume: Volume
    open: Open
    high: High
    low: Low
  start_date: "2024-01-01"
  end_date: "2024-12-31"

formula: "rank(ts_mean(close, 20))"

output:
  dataset: factor_lake_staging
  factor_id: my_momentum_v1
```

**环境**：

```bash
export DATA_ACCESS_COS_READ_MODE=remote
export DATA_ACCESS_COS_REMOTE_BACKEND=cli
export QUANT_RUN_NAMESPACE=你的名字
source env.sh
```

## 4. 核心概念

### 4.1 数据集 vs 文件路径

```python
# ✅ 正确：用登记好的名字
store.read_frame("ashare_stock_daily", ...)

# ❌ 错误：写路径
pd.read_parquet("/some/path/StockDailyBar/2024-01-01.parquet")
```

### 4.2 三种权限

| access_mode | 读 | 写 | 举例 |
|-------------|----|----|------|
| published | 全员 | **禁止** | `ashare_stock_daily`, `factor_lake` |
| staging | 本 namespace | 本 namespace | `factor_lake_staging` |
| namespaced | 本 namespace | 本 namespace | `single_asset_backtest_runs` |

### 4.3 参数化数据集

部分数据集路径里带参数，调用时必须传：

| 数据集 | 必传参数 | 示例 |
|--------|---------|------|
| `factor_lake` | `factor_id` | `factor_id="mom_3d_v1"` |
| `factor_lake_staging` | `factor_id` | `factor_id="my_new_v1"` |
| `ashare_universe_daily` | `universe_id` | `universe_id="hs300"` |
| `single_asset_backtest_runs` | `strategy_id`, `version` | `strategy_id="mom", version="v1"` |

### 4.4 读参数

| 参数 | 作用 | 示例 |
|------|------|------|
| `columns` | 只读这些列（**强烈建议传**） | `["Close", "Volume"]` |
| `time_range` | 时间范围，闭区间 | `("2024-01-01", "2024-12-31")` |
| `instrument_filter` | 按标的白名单过滤；**不传 = 全市场该时段全部股票** | 省略，或 `["000001.SZ", "AAPL"]` |

## 5. 支持哪些数据（数据集清单）

### 5.0 最常用的 6 个（90% 场景够用）

### 5.1 A 股 lqtp（20 表，COS 可读）

COS：`cos://qs-cold/clean_data/ashare/lqtp_data`

| 数据集名 | 说明 | 时间列 | 标的列 |
|----------|------|--------|--------|
| `ashare_stock_daily` | 日线 | TradeDate | Symbol |

### 6.6 性能与常见坑

| 建议 | 原因 |
|------|------|
| `columns` 只选需要的列 | 生产模式强制；少列少 IO |
| 收窄 `time_range` | 全市场 × 长区间 ≈ 交易日 × 股票数 |

| 不确定列名 → `store.get_dataset(name).schema` | 与登记一致 |
| A 股全市场日线一月约 10 万行；分钟单日可达千万行 | 先估数据量 |

## 7. 从 COS 读数据（其他服务器）

### 7.1 三种模式

| `DATA_ACCESS_COS_READ_MODE` | 行为 |
|-----------------------------|------|
| `mirror`（默认） | 先同步到本地永久目录，再读 |
| `remote` | 按需从 COS 读，不写永久目录 |
| `auto` | 本地有缓存用本地，没有则 remote |

### 7.2 远程后端

| `DATA_ACCESS_COS_REMOTE_BACKEND` | 行为 |
|----------------------------------|------|
| `cli`（**推荐**） | `clean-cos-ro` 按需下载到 cache |
| `httpfs` | DuckDB 直读 s3://（需扩展+密钥） |
| `auto`（默认） | 有 httpfs 用 httpfs，否则 cli |

### 7.3 推荐配置

```bash
export DATA_ACCESS_COS_READ_MODE=remote
export DATA_ACCESS_COS_REMOTE_BACKEND=cli
export DATA_ACCESS_COS_CACHE_ROOT=/data/.cos_remote_cache
export ASHARE_LQTP_COS_PREFIX=cos://qs-cold/clean_data/ashare/lqtp_data
export US_MASSIVE_COS_PREFIX=cos://qs-cold/clean_data/us_stock/massive_data
export US_CLEAN_COS_PREFIX=cos://qs-cold/clean_data
```

需 `clean-cos-ro` + `~/.cos.yaml` 凭证。

**重要**：COS remote（尤其 `cli` 后端）读日频/hive 表时，`read_frame` / `read_arrow` / `sql` 都必须带 `time_range`（或 `read_time_ranges`），避免整表拉取。

## 8. 运算、SQL、compute_and_write

### 8.1 sql 规则

- 只允许 `SELECT`
- 表名写 `{{ashare_stock_daily}}` 这种占位符
- COS 远程读必须传 `read_time_ranges`
- 生产/严格读模式需传 `view_columns`（显式列投影）
- 禁止 `read_parquet`、`INSERT` 等

```python
tbl = store.sql(
    "SELECT Symbol, AVG(Close) AS avg_c FROM {{ashare_stock_daily}} GROUP BY Symbol",
    read_datasets=["ashare_stock_daily"],
    read_time_ranges={"ashare_stock_daily": ("2024-01-01", "2024-01-31")},
    view_columns={"ashare_stock_daily": ["TradeDate", "Symbol", "Close"]},
)
```

### 8.2 compute_and_write

读 → SQL 算 → 写 staging，一条搞定：

```python
store.compute_and_write(
    "SELECT ... FROM {{ashare_stock_daily}} WHERE ...",
    read_datasets=["ashare_stock_daily"],
    read_time_ranges={"ashare_stock_daily": ("2024-01-01", "2024-01-31")},
    write_dataset="factor_lake_staging",
    factor_id="my_v1",
    partition_by=["year"],
    # 可选：结果落到自选目录
    # write_dir="/data/my_out/my_v1",
)
```

### 8.3 自选读路径 / 写路径（可选）

默认路径来自 `datasets.yaml`。其他服务器目录结构和我们不一样时，可以覆盖：

| 参数 / 环境变量 | 作用 |
|----------------|------|
| `read_root=` 或 `DATA_ACCESS_READ_ROOT_<数据集>` | 覆盖**读**根目录 |
| `write_root=` 或 `DATA_ACCESS_WRITE_ROOT_<数据集>` | 覆盖**写**根（参数化数据集仍拼 `factor_id` 等后缀） |
| `write_dir=` | 指定**最终**写入目录（完全覆盖模板） |
| `DATA_ACCESS_EXTRA_ALLOWED_ROOTS` | 自定义路径的白名单（逗号分隔）；不配会被拒 |

```bash
# 先把自选根加进白名单
export DATA_ACCESS_EXTRA_ALLOWED_ROOTS=/data/my_ws,/data/my_cache

# 可选：按数据集用环境变量固定
export DATA_ACCESS_READ_ROOT_ASHARE_STOCK_DAILY=/data/my_ws/a_share/lqtp_data/StockDailyBar
export DATA_ACCESS_WRITE_ROOT_FACTOR_LAKE_STAGING=/data/my_ws/staging/factors
```

```python
# 从自选目录读
df = store.read_frame(
    "ashare_stock_daily",
    columns=["TradeDate", "Symbol", "Close"],
    time_range=("2024-01-01", "2024-01-31"),
    read_root="/data/my_ws/a_share/lqtp_data/StockDailyBar",
)

# 算完写到自选最终目录
store.compute_and_write(
    "SELECT ... FROM {{ashare_stock_daily}}",
    read_datasets=["ashare_stock_daily"],
    read_time_ranges={"ashare_stock_daily": ("2024-01-01", "2024-01-31")},
    write_dataset="factor_lake_staging",
    factor_id="my_v1",
    write_dir="/data/my_ws/out/my_v1",   # 结果就落这里
)

# 或只换写根，仍按 factor_id 分子目录：
store.write_arrow(
    "factor_lake_staging", tbl,
    factor_id="my_v1",
    write_root="/data/my_ws/staging/factors",  # → .../factors/my_v1/
)
```

说明：
- `read_root` 在 `QUANT_PRODUCTION_MODE=1` / `DATA_ACCESS_STRICT_READ=1` 下会被禁止（防生产误切路径）；`write_root` / `write_dir` 不受此限（staging 本身就可写）。
- 设置了 `read_root` / `DATA_ACCESS_READ_ROOT_*` 时，该数据集**跳过 COS remote**，直接读本地覆盖路径。
- `write_dir` 仍要求参数化数据集的必填参数（如 `factor_id`），只是不再用它拼路径。

## 9. 写数据与发布

| 操作 | API | 写到哪 |
|------|-----|--------|
| 整目录重写 | `write_arrow(mode="overwrite")` | staging / namespaced（可用 write_dir/write_root） |
| 追加文件 | `write_arrow(mode="append")` | 同上 |
| 按键合并 | `upsert(upsert_on=[...])` | 同上 |
| 发布 | `publish_from_staging()` | staging → factor_lake |

```python
# 写草稿（默认路径）
store.write_arrow("factor_lake_staging", tbl, factor_id="x", partition_by=["year"])

# 写草稿（自选落盘）
store.write_arrow(
    "factor_lake_staging", tbl, factor_id="x",
    write_dir="/data/my_ws/out/x",
)

# 发布
store.publish_from_staging("factor_lake_staging", "factor_lake", factor_id="x")
```

**published 和 COS 永远不能直写。**

## 10. HTTP 远程读数

见场景 D（第 3 章）。服务端 `data-access-server`，客户端 `DataAccessClient`。

- `POST /v1/read` 支持 `format`: `parquet`（默认）| `arrow_ipc` | `json`
- 服务端强制要求显式 `columns`（比本地更严，防宽表打满带宽）
- 生产模式（`QUANT_PRODUCTION_MODE=1`）必须设置 `DATA_ACCESS_API_KEY`；本地调试无密钥时需显式 `DATA_ACCESS_API_ALLOW_OPEN=1`

## 12. 环境变量

| 变量 | 什么时候设 | 示例 |
|------|-----------|------|
| `QUANT_RUN_NAMESPACE` | **写数据时必设** | `export QUANT_RUN_NAMESPACE=shw` |
| `DATA_ACCESS_COS_READ_MODE` | 其他服务器读 COS | `remote` |
| `DATA_ACCESS_COS_REMOTE_BACKEND` | 其他服务器读 COS | `cli` |
| `DATA_ACCESS_COS_CACHE_ROOT` | 独立 cache 目录 | `/data/.cos_remote_cache` |
| `DATA_ACCESS_EXTRA_ALLOWED_ROOTS` | 自选读/写路径白名单 | `/data/my_ws,/data/my_cache` |
| `DATA_ACCESS_READ_ROOT_<数据集>` | 覆盖某数据集读根 | `/data/my_ws/.../StockDailyBar` |
| `DATA_ACCESS_WRITE_ROOT_<数据集>` | 覆盖某数据集写根 | `/data/my_ws/staging/factors` |
| `DATA_ACCESS_STRICT_READ` | 严格读（强制 columns 等） | `1` |
| `DATA_ACCESS_API_KEY` | HTTP 服务鉴权 | 团队密钥 |
| `DATA_ACCESS_API_ALLOW_OPEN` | 生产下允许无密钥（仅调试） | `1` |
| `DATA_ACCESS_API_MAX_ROWS` | HTTP 结果行上限 | `500000` |
| `DATA_ACCESS_API_MAX_BYTES` | HTTP 结果字节上限 | `512000000` |
| `DATA_ACCESS_API_HOST` / `PORT` | 服务监听 | `0.0.0.0` / `8765` |
| `DUCKDB_MEMORY_LIMIT` | 内存不够时 | `16GB` |
| `CLICKHOUSE_HOST` 等 | 读 CH 宽表时 | 按实际填写 |

每次开终端：`source env.sh`（已含大部分默认值）。

## 13. 规则与排障

### 13.1 必须遵守

1. 读写走 `get_store()`，禁止裸 `pd.read_parquet`
2. 不写 published / 不改 COS
3. 写数据设 `QUANT_RUN_NAMESPACE`
4. 不用别人重复的 namespace
5. 代码里不写绝对路径

### 13.2 常见报错

| 报错 | 处理 |
|------|------|
| 数据集未注册 | 检查数据集名拼写（第 5 章） |
| 缺参数 factor_id | 加上 `factor_id="..."` |
| 读出 0 行 | 放宽 time_range / instrument_filter |
| published 不允许直写 | 改写到 `factor_lake_staging` |
| COS 未拉到文件 | 检查 clean-cos-ro、凭证、time_range |
