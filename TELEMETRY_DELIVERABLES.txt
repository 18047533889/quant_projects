USAGE QUICK START
================================================================================

1. Enable Telemetry (opt-in):

   from telemetry import (
       configure_metrics,
       configure_tracing,
       configure_health_checks,
   )
   
   configure_metrics(enabled=True)
   configure_tracing(enabled=True)
   configure_health_checks(enabled=True)

2. Use Metrics:

   from telemetry import get_metrics_registry
   
   registry = get_metrics_registry()
   counter = registry.counter("requests", label_names=["method"])
   counter.inc(labels={"method": "GET"})

3. Use Tracing:

   from telemetry import get_tracer, trace
   
   tracer = get_tracer(__name__)
   
   with tracer.trace("operation") as span:
       span.set_attribute("key", "value")
       # ... work ...
   
   @trace(name="compute")
   def compute():
       pass

4. Use Health Checks:

   from telemetry import get_health_checker, ComponentHealth, HealthStatus
   
   checker = get_health_checker()
   
   def check_db():
       return ComponentHealth("database", HealthStatus.HEALTHY)
   
   checker.register("database", check_db, interval=60.0)
   status = checker.check_all()

5. Run Example:

   cd /home/shw/quant_projects/factor_engine
   PYTHONPATH=. python3 telemetry/example_usage.py

ARCHITECTURE NOTES
================================================================================

Design Patterns:
  - Singleton pattern for global registries
  - Factory pattern for metric creation
  - Observer pattern for exporters
  - Decorator pattern for instrumentation
  - Context manager pattern for spans

Thread Safety:
  - All metrics use threading.Lock for concurrent updates
  - Registry operations are atomic
  - Health checks run in background threads with proper locking

Extensibility:
  - MetricsExporter interface for custom backends
  - SpanProcessor pipeline for custom trace processing
  - SpanExporter interface for custom trace backends
  - HealthCheck callable interface for custom checks
