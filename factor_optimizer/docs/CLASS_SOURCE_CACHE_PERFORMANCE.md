# 类源码读取缓存与自动优化冷启动

## 改动位置与边界

在 FactorEngine 的 _freeze_value_unbounded 类源码分支复用
inspect.getsource 返回的原始文本；不是缓存整个语义指纹。
默认参数、闭包、数值策略、实现身份、生产准入等计算未被绕过。
此前试验的“后端分类缓存”已撤销，本次是另一个已定位的调用位置。

缓存仅在当前进程内存在，最多 512 条，不写磁盘、不复制代码树。
键包含类对象、模块名、限定名、源码路径、设备/文件标识、大小、
纳秒修改/变更时间及读取函数。类重命名、来源变化或文件版本变化会重新读取。
读取异常不缓存；自定义元类、非文件来源沿用原始读取路径。
这复用的是 inspect 的源码视图，不是 Python 热重载机制，也不是文件防篡改系统。

## 为何需要修改 FE

优化库的基础预处理通过 FP 适配器调用 FE 权威算子。
首次调用会初始化 FE 注册表；类源码指纹生成重复解析相同源文件，
使只有几百日数据的优化任务也承担明显冷启动成本。
因此本次没有复制一套 FP 数学实现、减少候选或跳过评估来冒充提速。

## 验证方式

1. 先复现同一类重复解析源码，再添加有界复用。
2. 测试源码修改、限定名变化、临时读取失败后重试。
3. 四个新进程 old/new/new/old 对照，旧路径直接调用 inspect.getsource，
   新路径调用缓存辅助函数，其余工作树、数据与搜索设置一致。
4. 逐个记录 4,191 个实现的首注册身份及物理 spec 的 execution_kind、
   implementation_source_hash、parameter_domain_hash、semantic_contract_hash、
   implementation_closure_hash，并比较整个快照摘要。
5. DataAccess 读取绑定 COS 真实因子，500 日×256 股票，103 个候选、
   99 次自助抽样；比较完整输出数组、候选记录、选择身份与验证下界摘要。
   TEST 没有评分。数据读取耗时不计入优化函数耗时，冷启动包含在内。

## 共享工作树与发布边界

注册表已有其他 AI 的 134 行未提交新增，本次只修改独立的两行调用位置。
仅提交本轮辅助模块、测试、文档和调用改动，不提交其他 AI 的代码。
对照使用同一共享工作树，因此绝对耗时包含其现有未提交实现；
这些测量不等于所有机器或干净发布环境的性能保证。

## 本轮结果

完整原始记录见 class_source_cache_real_ab_20260922.json。

  这里是包含冷启动的优化函数耗时，不是热运行或数据读取提速。

  不构成显著性检验、全局最优或所有环境加速保证。
