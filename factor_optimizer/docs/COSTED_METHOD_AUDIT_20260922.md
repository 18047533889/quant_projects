# 逐方法成本后验证与时间区间修复

## 本轮改动

1. TRAIN 诊断不再仅相信 horizon=1。相邻收益区间必须满足
   `label_end_time[t] <= label_start_time[t+1]`，否则保留 IC/分层分析，
   但不输出日频夏普和复利回撤，明确记录重叠原因。
   已以“名义单期、实际两期重叠”的数据先复现，再修复。
2. 每个数值可执行方法除了前缀不变性、资产排列和行对齐检查，
   还计算成本后的 TRAIN 联合指标。复用 [joint.v1](JOINT_SELECTION.md)
   公式、10bps 全名义交易成本、RAW 相对退化底线。
   记录 RankIC、RankICIR、Sharpe、最大回撤、最差三分块 Sharpe 和换手率，
   以及效用差；执行成功和指标可用分开标注。
3. DataAccess 支持有界 JSON 元数据读取及显式递归元数据枚举，
   见 [读取与绑定约束](../../data_access/docs/RESEARCH_METADATA.md)。
   还没有把未经绑定、含条件分支的 DSL 擅自转为已知处理谱系。

## 暴露数据的实际限制

通过 DataAccess 对现有镜像中 2024-08-02 的行业/估值文件各投影读取 3 行：
行业 `UpdateTime` 为 2026-06-02，估值为 2026-06-13。
这只能证明镜像更新时间晚于交易日，不能证明这些历史暴露当时不可获得，
也不能证明当时可获得。因此不能把 TradeDate 伪造为 available_time，
直接给历史中性化盖上 PIT 认证。
行业表同一股票有多个 IndustrySource，自动接入还必须固定一个分类来源。

仍待完善：真实配方/因子值摘要绑定、具备时点可得性证据的暴露加载、
分层衰减定向搜索、更广泛成本敏感性与性能等价测试，最后才打开真实 TEST。
当前不能宣称自动优化链已全部闭合、绝对无 bug 或保证收益改善。
